> 的联调边界和验收顺序说清楚，避免把移动端桥接源码或编译产物继续塞回 helix 仓。

## 2. 联调分层

推荐按 4 层递进，不要一上来就真机全链路。

### L0：helix Rust / FFI 本仓验收

在 helix 仓运行：

```bash
cd /System/Volumes/Data/workspace/rust/helix
```

### L1：移动端集成项目 C++ 直调

在移动端集成项目中完成，不在 helix 仓完成。

输入产物来自 helix：

- `crates/helix-driver-ffi/helix.h`
- `crates/helix-driver-ffi/helix.hpp`
- `target/release/libhelix_driver_ffi.*`

C++ 必测：

1. `helix_create_with_network` 创建 handle。
2. `helix_query("helix_version", "{}")` 返回 `{"abi":1}`。
3. `helix_query("helix_capabilities", "{}")` 返回：
   - `commands` 包含 `im_send`
   - `queries` 包含 `helix_capabilities`、`helix_version`、`im_query_dialog_list`、`im_query_messages_by_channel`
   - `events` 不包含 `im:post:send-failed`
4. `helix_command("im_send", {"channelId","temporaryId","text","type"})` 能收到 `im:post:sending` 批事件。
5. `helix_query("im_query_dialog_list", "{}")` / `helix_query("im_query_messages_by_channel", payload)` 能返回 JSON，并由 `helix_query_free(ptr,len)` 释放。
6. 空 handle、未知 query、非法 JSON、destroy 后调用都有稳定错误码，不崩溃。

事件回调铁律：

- `on_domain_events_batch(ptr,len)` 中的 `ptr` 只在回调期间有效。
- C++ 必须在回调内立即 memcpy 到自己的 buffer，再交给 QuickJS / Flutter。
- 不允许把回调借用指针跨线程保存。

### L2：QuickJS / JS wrapper smoke

在移动端集成项目中完成。

L2 分两层验收：

1. **CoreBridge 低层 smoke**：证明 QuickJS 能调用 C++ bridge 暴露的 `call/query/capabilities/onEvents/dispose`。
2. **业务糖衣 smoke**：证明移动端最终可以调用 `im.send(...)` / `xxx.send(...)` 这类 API，而不关心 `helix_command`、命令名、字段归一和事件对账细节。

CoreBridge 低层建议暴露：

```js
const core = new CoreBridge();

core.version();
core.capabilities();

await core.call("im_send", {
  channelId: "01hq0000000000000000000000",
  temporaryId: "tmp-mobile-1",
  text: "hello",
  type: "TEXT"
});

const dialogs = await core.query("im_query_dialog_list", { limit: 50 });
const messages = await core.query("im_query_messages_by_channel", {
  channelId: "01hq0000000000000000000000",
  limit: 50
});
```

业务糖衣建议第一批只做最小 facade，不在 JS 里重写业务规则：

```js
const core = new CoreBridge();
const im = createImApi(core);

const receipt = await im.send({
  channelId: "01hq0000000000000000000000",
  text: "hello",
  type: "TEXT"
});

// receipt 只表示 Rust 已接收并产生 optimistic 事件，不表示 Go 已完成。
console.log(receipt.temporaryId);
```

`im.send(...)` 的职责边界：

- 可以生成 `temporaryId`，也可以接收 Flutter 传入的 `temporaryId`。
- 只把 `{channelId, temporaryId, text, type}` 交给 `core.call("im_send", payload)`。
- 等待或订阅 `im:post:sending`，把 optimistic receipt 返回给 Flutter。
- 不在 JS 里拼 Go `/posts/create` 请求体。
- 不在 JS 里判断发送成功；成功仍等 Rust 经 WS echo 对账后发 `im:post:received`。
- 不在 JS catch 中合成 `im:post:send-failed`。

JS 必测：

- `capabilities()` 启动检查失败时，拒绝继续初始化 UI。
- `call()` 只表示 Rust 已接收命令，不表示 Go Server 已完成。
- `im.send(...)` 能隐藏底层命令名和字段归一细节，移动端调用方无需知道 `im_send` / `im_send_message`。
- 发送结果必须等事件：`im:post:sending` 乐观行，WS echo 后 `im:post:received`。
- 不把 JS catch 或错误字符串合成 `im:post:send-failed`。
- `dispose()` 后再调用返回稳定错误。

本机若暂时缺 Android / iOS / Flutter e2e 环境，先把 L2 作为“最后一公里前置验收”：

- 用桌面或命令行 QuickJS runtime 跑 JS smoke。
- 链接真实 `helix-driver-ffi`，不能用 `rust_core_mock.cpp` 代替。
- 断言 `im.send(...)` 触发 `im:post:sending` 事件批。
- 断言 `core.capabilities()` 覆盖 `commands` / `queries` / `events` 启动检查。
- 真机 Flutter e2e 标记为环境依赖 TODO，等 Android/iOS 工具链和移动端项目路径就绪后再补。

## 3. 发送消息全链路验收

完整链路：

```text
Flutter 点击发送
  -> QuickJS JS wrapper
    -> C++ CoreBridge.call("im_send", payload)
      -> helix_command
        -> helix-im im_send_message
          -> im:post:sending 乐观事件
          -> HTTP /posts/create 到 cses-im-server
          -> Go WS post echo
          -> temporaryId 对账
          -> im:post:received
          -> C++ callback memcpy
          -> JS / Flutter 渲染已发送
```

验收点：

- `im_send` 入参可用 camelCase，Rust 归一为内部 snake_case。
- `im:post:sending` 必须先出现，UI 可立即插入乐观行。
- `im:post:received` 必须通过 WS echo 对账产生，不由 JS 伪造。
- 超时未 echo 时沿用 PC/Tauri 发送规则：持久化 `send_status='unsend'`，不新增移动端专属 `im:post:send-failed`。

## 4. 出问题时的定位顺序

1. `helix_query("helix_capabilities")` 失败：先查 C ABI 调用、out buffer、`helix_query_free` 配对。
2. `im_send` 无 `im:post:sending`：先查 command name / JSON / callback vtable。
3. 有 `im:post:sending` 无 HTTP：查 `helix-driver-ffi` 网络配置、headers、Go URL。
4. HTTP 成功无 `im:post:received`：查 `cses-im-server` WS echo、connectionId、cookieId/userId。
5. Rust 有投影但 Flutter 不变：查 C++ 回调 memcpy、QuickJS event dispatch、Flutter 状态绑定。
6. loopforge 绿但移动端红：通常是 C++/QuickJS/平台线程或内存边界问题，不应先改 helix 内核。
