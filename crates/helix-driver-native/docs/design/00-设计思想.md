# helix-driver-native 设计思想

> 本文是 `helix-driver-native` 这个 crate 的角色宣言与关键决策备忘，  
> 供后来开发者快速定位「这里做什么 / 不做什么 / 为什么这么薄」。  
> 真源：`src/`；设计图索引：[`README.md`](README.md)；完整泵核语义见 `helix-driver-host`。

---

## 1. 这个 crate 的本质：PC 端薄壳

`helix-driver-native` 是 Helix 三层架构里**平台驱动层**的 PC/Tauri 实现。  
它的职责只有两件事：

1. **组装 native 特化 ports**（NativeStorage、SharedWsClient、SharedHttpClient、NativeEventSink、NativeClock）
2. **调用 host 泛型泵核** `run_engine_loop`，把组装好的 ports 传进去

**它不持有任何 I/O 逻辑。** WS 管理、HTTP 管理、存储实现、BoundedSpawner、  
timer registry 全在 `helix-driver-host`。native 只是「把对的东西拼在一起」。

---

## 2. ADR-007 前后对比：从 1119 行到 ~168 行

**ADR-007 之前**，`engine_loop.rs` 是 native crate 的核心，1119 行，包含：

- BoundedSpawner 原语
- Persist/Http/HttpFire 三池构造
- Effect 分发 match
- timer registry
- 存储 op 执行
- HTTP 信封编解码

这些全是「任何端都需要的泵逻辑」，但只在 native 里。FFI 端若要复用，要么整块搬，  
要么语义漂移——两个选项都糟糕。

**ADR-007 之后**，这些全下沉到 `helix-driver-host`。native 的 `engine_loop.rs` 变成：

```
组装 ports → 调 run_engine_loop
```

约 168 行。`engine_loop.rs` 从「I/O 实现者」变成「组装者」，单职责。

---

## 3. NativeEventSink：broadcast 即时推

native 端的 EventSink 是 `NativeEventSink`，内部是 `tokio::sync::broadcast`（cap=1024）。

- `emit(ev)` = `sender.send(bytes).ok()`（非阻塞，无接收者静默丢弃）。
- `flush()` = no-op（`BatchSink` supertrait 默认实现）。

为什么 flush 是 no-op？broadcast 即时推送，每条 DomainEvent 都立刻可被订阅者消费，  
不需要攒批。相比之下，FFI 端的 `FfiEventSink::flush` 会把整步的 DomainEvent 批打包  
成单一 buffer 过 vtable 回调（HX-C007）。host 层的 `BatchSink` 设计让两种策略  
都能接在同一个泵核上，无侵入。

## 4. NativeStorage：HostStorage 薄壳适配层

`NativeStorage` 不持有独立状态，只是 `Arc<HostStorage>` 的 newtype 包装 + `Storage` trait impl 委托。  

```rust
pub struct NativeStorage(Arc<HostStorage>);
impl Storage for NativeStorage { ... /* 全部委托 HostStorage */ }
```

- 等价性由结构保证（parity by construction），不靠「对比测试」。
- 额外暴露 `execute_raw`（DDL 用途，测试建表），非 `Storage` trait 公开方法。
- 压测语义（batch_upsert / monotonic_upsert 吞吐）已迁移到 `helix-driver-host/tests/stress_storage_core.rs`（单一真源）。
- native 保留 parity 烟测（`tests/stress_storage.rs`）：通过 NativeStorage 跑一次 5000 行 + MAX guard，  
  证明委托层透明转发无语义分叉。

---

## 5. 唯一合法的 ambient API 落点

GOAL §1.2 要求 core 不调 `Instant::now` / `SystemTime`。但驱动层**必须**访问真实时间（如 NativeClock、  
stress test 的 `Instant::now`）。全局 clippy 在 core crate 里 deny ambient time API，  
native/ffi driver 是**唯一合法 allow 点**。

本 crate 的 `engine_loop.rs` 是 `allow(clippy::disallowed_methods)` 注解的合法所在。

## 7. 总结一句话

`helix-driver-native` = 「组装 native ports + 调 host 泛型泵核」，不持有 I/O 实现，  
thin shell by design，确保 PC 与 Flutter 端泵语义 parity by construction。
