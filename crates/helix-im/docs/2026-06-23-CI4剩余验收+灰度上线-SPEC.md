## 2. #13 上线 — **all-in 直接全量切换**（2026-06-23 用户拍板：不灰度）

> **决策（用户 2026-06-23）：不灰度，直接 all-in 上线**——`IM_ENGINE=helix` 一次性对全量用户生效，
> **取消** dogfood/10% 渐进阶段。**但 CI-4 全绿仍是硬前置**（all-in 只去掉「渐进」，不去掉「先验证」——
> 不能切到没验过的引擎）。一键回滚保留为安全网（all-in 风险更高，回滚必须随时可用）。
>
> **不是自驱 agent workflow**——上线是生产 ops 动作（改 cses-client `boot.rs` 注册 + 前端 flag + 发版），
> 本节是**人工执行清单**。

### 2.1 切换机制（真源 04 §2，照此操作）
- **后端开关**：env / `tauri.conf` `IM_ENGINE=helix|legacy`；`boot.rs` 启动按开关**二选一注册**
  helix 薄壳命令集 **或** legacy 命令集（同名 `#[tauri::command]` 不可并存）。
- **前端开关（成对）**：前端 service 层 `legacy` feature flag 双写分支，由同一 env（`tauri.conf` 暴露
  给前端 `IM_ENGINE`）切。**必须前后端成对切**——表 B service 已改语义 invoke，纯后端切 legacy 会让
  语义命令名在 legacy 集 command not found。
- **写权防线**：灰度期**禁止 helix 与 legacy 同时对同一 PK 写**（env 二选一注册保证同刻只一套引擎写）。
  数据兼容：两端同写 `message`(PK=temporaryId)/`channel`/`channel_member`/`channel_event_cursor`，
  schema 对齐（ADR-013 移除 segment_id 死列，与 legacy `IF NOT EXISTS` 共存不冲突）→ 回滚不丢数据。

### 2.2 all-in 上线步骤（一次性全量，**红则全量回滚**）

| 步 | 动作 | 可证伪 gate / 验收 |
|---|---|---|
| **P0 前置** | CI-4 全绿（§1 V5-V8 + 矩阵 §3 gate 自检全过） | CI-4 任一 FAIL → **不上线**，先修 helix / 报 Go 复验 |
| **P1 切换** | cses-client `boot.rs` 把默认注册改 `IM_ENGINE=helix`（全量）+ 前端 service 默认走 helix 分支（成对）+ 发版 | 同名命令二选一注册校验：legacy 命令集不再注册（防双写 PK 冲突，§2.1）|
| **P2 上线后冒烟**（首日盯） | 真实用户：冷启动 increment 落库 / 发消息 echo / 已读未读 / 离线 sync / WS 重连无风暴（SyncScheduler K=8）| 四指标（送达率 / 未读准确率 / sync cursor 不回退 / 崩溃率）≥ legacy 基线 |
| **P3 收尾** | legacy 命令集**保留 ≥2 周**可回滚后才下线 | 2 周内零 P0/P1 才删 legacy 分支 |

> **all-in 风险提示**：无渐进缓冲 = 问题一次暴露给全量用户，**P2 首日必须有人盯四指标 + 回滚开关待命**。
> CI-4 全绿是把这个风险压住的唯一前置——所以 §1 的 workflow 必须先真跑过、全绿，再做 P1。

### 2.3 一键回滚（每阶都必须可逆）
- **动作**：`IM_ENGINE=legacy` 切回 legacy 注册 **+ 前端 service legacy 分支**（成对，§2.1）。
- **触发**：任一阶观察期出现 P0/P1（消息丢失 / 未读错乱 / sync cursor 回退 / 崩溃率超基线）→ 立即回滚
  + 落终态行到 `worktrees/im-takeover/SESSION.md §0`（`⚠️ PARTIAL 灰度回滚 @ts | 卡在 <阶> | 根因 <…>`）。
- **回滚验收（falsifiable）**：回滚后白名单用户读到的 `message/channel` 表数据完整（schema 共享 → 不丢）；
  语义命令名在 legacy 集可达（不 command not found）。
