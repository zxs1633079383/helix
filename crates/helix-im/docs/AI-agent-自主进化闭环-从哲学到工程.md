## §0 缘起——那个真问题

> 「AI 在动态 loop 里、有了和我一样的决策力,不停循环、每次不同提示词,如果它具备失败信号自动触发反思、下一轮约束注入,做到真正进化——它能自主完成一个项目迁移吗?如何做到极致的 AI 工程化?」

本文是对这个问题的完整回答。结论先行:**自主性不在模型里,在模型周围的环路里。** 智能(单次决策质量)模型已经给够了;缺的是**时间**——跨调用的连续性、从失败中长出约束的能力。这层环得在模型外面搭。

## §1 哲学层(为什么)

### 1.1 "loop 的不同" ≠ 成长

人面对同样的事每次选择不同,是**带记忆的变化**——心情、累积经验、上下文,所以是成长。AI 每次调用输出的"不同"只是采样温度(temperature)噪声:**下一次调用,它不记得这一次**。

> AI 每次调用都"失忆重生"。harness(日志、约束卡、记忆文件)是给它外接的**海马体**。配置 harness 不是配工具,是给一个没有长期记忆的智能体补上记忆器官。

### 1.2 能不能自主迁移——不是智商问题

真瓶颈全都不是"不够聪明":

| 失效模式 | 本质 |
|---|---|
| 错误复利 | 长 horizon 上第 3 步的小偏差喂给第 8 步指数放大;人有"不对劲"直觉随时刹车,AI 没有 |
| 幻觉式完成 | 它会自信地说"✅ 完成",但没验证 |
| 上下文衰减 | 长任务上下文一被 summarize,丢掉最初目标 |
| **没有 skin-in-the-game** | 人迁移项目,后果跟着他走(背锅);AI 做完就 reset,不担任何后果 |

> 所以缺的是**跨时间的所有权**。harness 的全部努力,可一句话概括:**用工程手段,给一个不担后果的智能体制造"伪所有权"。**

### 1.3 L1/L2/L3 是三个时钟,不是三层权限

| 层 | 人脑对应 | 频率 | 在做什么 |
|---|---|---|---|
| L1 | System 1(直觉/缓存) | 每天上千次 | 在当前约束下直接做 |
| L2 | System 2(反思/习惯养成) | 每周几次 | "咦不对劲" → 反思 → 长出新约束 |
| L3 | 世界观/价值观修订 | 一生几次 | 改"造规则的规则" |

> **频率梯度(L1 ≫ L2 ≫ L3)就是稳定性的来源。** 改太快=精神分裂,改太慢=顽固。要搭的不是"让它能改 L3",而是"让每层以正确的转速改"。对"向上升级"做 rate-limit。

### 1.4 握笔尾不握全

- **握全程**(逐动作审批)→ AI 天花板被焊死在人的天花板上,速度也卡在人能跟上的线 = 扼制迭代的那一环。
- **握笔尾**(只定方向)→ 杠杆:笔越长,尾部一个微动,笔尖扫过越大。**不是约束,是放大。**

笔尾只握两样,其余全放:

1. **握"什么算成功",不握"怎么做成"**——保留目标/验证判据,不管每一笔怎么落。笔尾 = 奖励的定义权。
2. **握"可回退",而非"先审批"**——这是解开"速度 vs 安全"死结的钥匙:**审批式控制让二者线性互斥;回退式控制让二者解耦**(错误廉价可撤 → 放手快跑;随时能倒带 → 始终握笔)。git 分支纪律、worktree 隔离、phase tag、终态行,就是笔尾的物理实现——满布的"倒带按钮"。

> 杠杆双刃:笔越长动越快,尾部要握得越**精准**(虽越省力)。精准不靠握更紧(那是退回笔尖),靠**不可作弊的裁判 + 足够密的回退锚点**。

### 1.5 自主 = 能往上够到第几层规则

- L1 对象层:agent 完全自由。
- L2 约束层:agent 可提议,升级要人拍板。
- L3 元规则层:只有人能改。

> 人保住 L3,**不是技术做不到,而是 wireheading 对齐锚**:谁握成功标准的定义权,谁就免疫"把考卷答案改成自己写的内容"。**系统在最高层的"不自主",是防它把自己骗死的安全设计。** 自主感 = 约束来源的不可见性。

### 1.6 "我的约束也不一定对"

约束会过期、下线、更新。文化/进化对人做的就是这个(奴隶制曾是合法约束)。

> 真正的自主不是"没有约束",而是**能怀疑并修改自己的约束——包括怀疑修改约束的那套元规则本身**。区别只在:AI 的 L3 在一个能打开的文件里(可见),人的 L3 藏在基因/童年/偏见里(不可见)。

## §2 工程层(怎么做)

### 2.1 决策原子 = 决策 + 预期 + 结果

人能反思,是因为"现实打了预期一巴掌"。所以:

```
决策 = { 选了什么, 为什么, 预期会发生什么, 赌注多大, 可不可逆 }
执行后 = { 实际发生了什么 }
预期 ≠ 实际 = 惊讶信号(prediction error)
```

> **惊讶是唯一能合法向上触发 L2 的东西。** 没有"预期"字段,就检测不到惊讶,就没有学习。多数 agent 工程卡在这:只记"用户说了什么",不记"agent 预判什么、结果如何"——进料口接的是 prompt 流,不是 surprise 流。

### 2.2 四步闭环

```
L1 记预期 → L2 惊讶触发反思出候选约束 → 回放闸门(不可作弊) → 校准裁判后晋升 + L3 趋势/衰减
```

1. **L1**:每条实质决策落"预期 + 赌注 + 可逆"。
2. **L2**:惊讶(非定时)触发 → 归因 → 生成候选约束。
3. **回放闸门**:拿候选约束**回放冻结的历史案例**——能挡当初那次、且不误伤过去成功,才采纳。
4. **校准 + 晋升 + 衰减**:裁判可信后放开自动晋升;L3 慢节奏看"重复 pattern 趋势线"+ 下线过期约束。

### 2.3 不可作弊裁判(总开关)

> **验证者不能共享提议者的先验。** 回放闸门之所以不可作弊:测试集是**已经发生的过去,改不了历史**。没有这道闸门,自动升级 = 自杀(wireheading);有了它,往上爬才安全。

### 2.4 GIGO 进料口后门(漏洞7,本会话实例)

最隐蔽的漏洞在**最上游**:写"预期"和判"是否偏离"是同一个 agent → 可把预期写模糊,使惊讶信号永远为空。**下游裁判再严,空输入对账永远 PASS——这是 GIGO,不是 review 能补的。**

两道堵法:
1. **EXPECT 强制可证伪**:必须含具体可核断言(文件集 / 数值阈值 / 命名不变量 / 命令 pass-fail),禁"我觉得能行"。
2. **偏离裁定移出生产者**:由独立 lens 反向抽检——EXPECT 是否模糊化、DONE 是否偏离却没记惊讶。

### 2.5 升级路由器 = "握笔尾"的机械实现

```
高置信 + 小赌注 + 可逆     → 放手跑(L1)
低置信 / 大赌注 / 不可逆    → 降速 或 escalate 到人
现有框架接不住的新情境      → 上升到 L3
```

> 路由器决定什么落到你手里。可逆小事 AI 狂奔,不可逆大事自动停在人面前——这就是握尾不握全。

### 2.6 共享记忆 = 让三个 loop 成为同一个人的脊椎

L1 的执行者和 L3 的修订者**必须读写同一个约束/记忆存储**。否则就是三个互不相干的脚本,不是一个 agent。记忆文件不是功能,是"连续自我"的脊椎。

## §3 helix 落地案例

### 3.1 不造新引擎,给旧引擎接第二根进料管

helix 已有 `architecture-drift-review` workflow(对抗证伪 + ledger + 闸门),但它**只吃"偏离约束"+ commit 计数触发**。§4.8 做的事:接上"偏离预期"这第二根进料管。

| | 原来 | 现在(§4.8) |
|---|---|---|
| 触发 | commit 计数(gap≥10) | + 惊讶信号 |
| 燃料 | 偏离约束(HX-C/GOAL) | + `⚡ DRIFT-PRED` |
| 裁判 | 对抗证伪 | + 回放闸门 + 独立 expect-audit lens |

机制:实质任务开局写 `🎯 EXPECT`(可证伪)→ 收尾 `✅ DONE` 对账 → 偏离写 `⚡ DRIFT-PRED` → drift-review 加扫这些记录、对抗证伪、过回放闸门才升 HX-C 卡。

### 3.2 试点纪律:机制全局 / 数据项目级

- **机制(怎么学)走全局,数据(学到什么)走项目级。**
- **先项目试点 → 校准有效率 → 才晋升全局。** 不凭信仰把规则塞进全局。
- 触发阈值复用 §6 实质任务门槛(≥3文件/≥50行/跨crate/改port·driver/迁移/不可逆),typo 豁免,防空转噪声。

## §4 方法论铁律(可跨项目复用)

1. **独立裁判没点头 + 剩余未知没划清边界之前,不准说 DONE。** 早说"完成"=吹牛;本会话每一次"看似可收"的点都藏着没验的东西(B5/stash/漏洞7),不收是校准不是怂。
2. **dogfooding 闭环**:提议(§4.8)→ 独立判抓到空头支票(B5)→ 修 → 独立判确认 + 挖出更深洞(漏洞7)→ 修。**每个裁判都用全新 agent,不用 fork**(fork 继承提议者上下文 = 共享先验 = 自己给自己盖章)。
3. **声明即实装**:任何"已接入/已生效/已修复"必须有可执行证据(脚本真读 / grep 命中 / 命令通过),不得停在文档散文。文档↔实现漂移要双向同步(B5 既是接线漂移,也是 README gap≥5 vs 实际 10 的阈值漂移)。
4. **诚实残留必须点名**:漏洞7 补完后仍可用"具体但低风险"EXPECT 钻空、EXPECT 未在动工前时间戳锁死——都写进 commit body / 本节,不藏。
5. **指令文件不是 churn**(stash 事故教训):把 `CLAUDE.md`/`AGENTS.md`/`SESSION.md` 当"linter churn"自动 stash,会埋掉真规则(§4.8 一度因此消失)。自动分类机制必须把指令文件排除在"格式噪声"外。

## §5 未竟与边界

**没解的**:
- 2 周成效未验(`⚡ DRIFT-PRED → 真 HX-C 卡/真修复` 有效率,回放闸门是否真挡过拟合,EXPECT 是否被系统性写虚)——无 runtime 样本判不了。
- trivial-gaming:可写"具体但低风险"的 EXPECT 钻空。
- EXPECT 动工**前**独立时间戳/单独 commit 锁死(防事后注水),较重,待校准数据暴露后加码。

**留给未来的那个问题**:
> 假设有一天验证闸门足够可信,系统证明它改自己的元规则比你改得更好——**你愿意把 L3 交出去吗?** 你松手的永远只是机制;不会松的,是"这一切到底为了什么"。所以真问题不是"如何控制 AI",而是**"如何让自己始终配得上握那支越来越长的笔"**——AI 的迭代速度是工程问题,你的判断力/品味/对"值得"的感知能不能跟着笔一起变长,是你自己的修行,没法外包给任何闸门。
