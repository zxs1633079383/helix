## 为什么每个 UC 仍要写远端表

Consul 只能回答“服务当前连到哪一个数据库”，不能回答“某个 UC 应该改哪张表”。因此两层信息都必须存在：

1. 本文件冻结环境级真源：pre 当前连接 `mattermost-imv2`。
2. `UC全链路发布矩阵-v1.md` 每一行声明该 UC 涉及的具体远端表，例如 G-01 是 `post/channel/channel_member/channel_event`。
3. 真正运行时再用 evidence bundle 证明本次操作确实命中了声明的库表，不能只凭配置推断已落库。

## N/A 规则

- 只有整个合同都不可能出网的纯本地查询才可把远端库标记为 `N/A`，并且必须用 trace/HTTP 计数证明没有出网。G-10 已是条件 local-first：Complete 分支仍要证明零 HTTP，但 Partial/Miss/Unsupported 会读取 imv2，故整行必须声明远端库表，不能再标 `N/A`。
- 投票、平均分等第二网关若未核验其数据库，必须标记 `external-unverified` 和 blocked，不能冒充写入 imv2。
- Redis/Pulsar/ES 属于附加基础设施证据，不得塞进“远端 DB 表”单元格混淆语义。
