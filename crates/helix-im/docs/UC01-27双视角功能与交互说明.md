# UC01-27 双视角功能与交互说明

## 1. 文档定位

本文以 Helix Strict Matrix epoch 5 为功能合同，将 UC01-27 按“产品目标、发送者/发起者视角、接收者/观察者视角、双视角收敛、对应功能面”展开。

- 本文只描述功能和交互效果，不描述 HTTP、WS、数据库、代码实现或测试结果。
- “发送者”表示发起操作的人；查询、管理、组织类 UC 中也称“发起者”。
- “接收者”表示收到消息、被操作或观察结果的人；私有能力的接收者视角应保持不变。
- 双视角不要求两边界面完全一样，而要求同一业务对象在身份、内容、顺序和权限上不矛盾。
- Helix 中处于 blocked 的 G-03、G-22、G-23、G-24，本文仍描述目标产品交互，但不表示已经实现或验收通过。

合同基线：

- Helix HEAD：`9879572cb659de666c7fe075de167d9e06b3eefd`
- Strict Matrix：`helix-im-strict-matrix/v1`，epoch 5
- Macro UC：27 个
- 产品 Gate：42 个；产品 Command Operation：54 个
- 横切同步 Gate：4 个；同步 Command Operation：4 个
- Strict Matrix 合计：46 个 Gate、58 个 Command Operation

## 3. 消息发送与消息动作

### UC01 文本发送

**合同绑定**：G-01；`im_send_message`；`message.row.v1`

**功能目标**：发送者在当前会话输入文本，接收者无需额外操作即可看到同一条新消息。

**对应功能面**：消息编辑器、消息时间线、会话列表、消息操作菜单。

**发送者视角**：

1. 输入为空时发送不可用；输入正文后发送动作可用。
2. 点击发送后，正文立即以“发送中”消息行保留在时间线中，编辑器清空但不丢失失败恢复能力。
3. 发送成功后，同一消息行转为已发送，可继续回复、表情回应、撤回或转发。
4. 会话列表的最后消息预览同步更新为刚发送的正文。
5. 发送失败时只在发送者侧显示失败原因和重试入口，正文保持可见。

**接收者视角**：

1. 当前正在查看该会话时，新消息自动插入时间线正确位置，不需要点击“同步”。
2. 未打开该会话时，会话列表更新最后消息预览、时间和未读数。
3. 打开消息后可按权限进行回复、表情回应等操作。
4. 不应看到发送者的“发送中”或本地失败状态，只看到最终可接收的消息。

**双视角收敛**：两边最终指向同一条消息，作者、正文、所属频道和顺序一致；发送者的本地过程态不泄漏给接收者。

### UC02 文档消息

**合同绑定**：G-02；`im_send_message`；`message.row.v1`

**功能目标**：发送者发送具有明确文档类型和文档信息的消息，接收者以文档卡片查看和打开。

**对应功能面**：消息编辑器的文档入口、消息时间线、会话列表、文档卡片。

**发送者视角**：

1. 从编辑器选择文档后，先看到文档名称、类型和可识别摘要，确认后发送。
2. 发送中保留完整文档卡片，不降级成普通文本或空附件。
3. 成功后可从卡片打开文档，也可对整条消息执行回复、撤回或转发。
4. 文档无效、缺少必要信息或发送失败时，卡片保留并给出更换、取消或重试入口。

**接收者视角**：

1. 自动收到同一文档卡片，卡片标题和文档身份与发送者一致。
2. 点击卡片进入文档查看；不可访问时显示明确的不可用原因，而不是空白页。
3. 会话列表显示可理解的“文档消息”预览，不暴露内部字段。

**双视角收敛**：两边看到同一文档身份和消息身份；打开权限可因角色不同而不同，但不能把不同文档混成同一条消息。

### UC03 媒体附件

**合同绑定**：G-03；`im_send_message`；`message.row.v1`；当前为目标交互

**功能目标**：发送图片、文件、音视频等媒体，并让接收者看到与媒体类型匹配的消息卡片。

**对应功能面**：附件选择器、消息编辑器、媒体预览、消息时间线、会话列表。

**发送者视角**：

1. 选择媒体后先显示缩略图、文件名、大小或媒体类型，可移除或重新选择。
2. 提交期间卡片显示清晰进度；正文和附件关系不因失败而丢失。
3. 成功后图片可预览，文件可打开或保存，音视频提供对应播放入口。
4. 失败时只在发送者侧出现失败状态，可对原附件重试，不生成第二条重复消息。

**接收者视角**：

1. 只在附件可用后看到最终媒体卡片，不看到发送者未完成的本地占位。
2. 根据自身权限预览、播放或打开；无权限或资源失效时显示明确不可用态。
3. 会话预览使用“图片”“文件”“视频”等可理解摘要。

**双视角收敛**：消息身份、附件身份和媒体类型一致；发送失败不会在接收者侧留下空壳消息。

### UC04 失败重试

**合同绑定**：G-03a；`im_retry_send`；`message.row.v1`

**功能目标**：发送失败后在原消息位置重试，并保证接收者最终只收到一条成功消息。

**对应功能面**：消息时间线、失败消息行、重试按钮、会话列表。

**发送者视角**：

1. 失败消息显示失败图标、原因和重试入口，正文或附件仍保留。
2. 点击重试后，原消息行从失败转为发送中，重试期间按钮不可重复触发。
3. 成功后原消息行转为已发送，不另起一条视觉重复消息。
4. 再次失败时恢复可重试状态，并允许编辑或取消。

**接收者视角**：

1. 发送失败阶段完全不出现该消息，也不增加未读数。
2. 重试成功后只出现一次最终消息。
3. 不应看到发送者的失败次数、重试按钮或本地错误信息。

**双视角收敛**：发送者原失败行与接收者最终消息收敛为同一消息结果；重复点击或重连不能制造重复消息。

### UC05 撤回消息

**合同绑定**：G-04 在线撤回、G-04a 离线撤回重放；`im_revoke`、`im_sync_channels`；`message.row.v1`

**功能目标**：有权限的发送者撤回已发消息，在线和晚进入的接收者都看到一致的撤回结果。

**对应功能面**：消息操作菜单、危险确认弹窗、消息时间线、会话列表。

**发送者视角**：

1. 在自己的可撤回消息菜单中选择“撤回”，先看到对象明确的确认提示。
2. 确认后原消息内容从时间线移除，原位置改为“你撤回了一条消息”的系统事件。
3. 若产品允许重新编辑，入口只在发送者侧出现，并回填可编辑正文。
4. 超过撤回范围、无权限或已撤回时，动作隐藏或显示明确禁止原因。

**接收者视角**：

1. 在线时原消息自动替换成“某某撤回了一条消息”的系统事件。
2. 不显示“重新编辑”，也不能恢复已撤回正文。
3. 离线后重新进入或刷新时，仍只看到撤回系统事件，不重新闪现原文。
4. 会话预览不能继续泄漏已撤回的正文。

**双视角收敛**：双方在同一原消息位置看到同一撤回事实；文案因角色不同显示“你”或发送者姓名，但撤回对象和发生顺序一致。

### UC06 转发消息

**合同绑定**：G-05；`im_relay_messages`；`message.row.v1`

**功能目标**：发送者将一条或多条消息转发到一个或多个目标会话，目标接收者获得可理解的转发内容。

**对应功能面**：消息操作菜单、多选工具条、目标会话选择器、消息时间线、会话列表。

**发送者视角**：

1. 从单条消息菜单或多选模式进入转发，选择逐条转发或合并转发。
2. 目标选择器显示可访问会话，已选目标可检查、取消和重新选择。
3. 提交后逐目标显示成功、失败或部分成功，失败目标可单独重试。
4. 成功后可直接进入目标会话查看转发结果。

**接收者视角**：

1. 在目标会话自动看到转发消息；逐条转发保持每条消息结构，合并转发显示可展开摘要。
2. 可见来源信息应帮助理解上下文，但不能泄漏接收者无权访问的原会话内容。
3. 可对转发后的消息执行回复或表情回应。

**双视角收敛**：每个目标会话的发送结果独立，双方对转发内容、目标频道和消息顺序一致；部分失败不能被显示成全部成功。

### UC07 快捷回复与表情回应

**合同绑定**：G-06；`im_quick_reply`；`message.row.v1`

**功能目标**：用户对指定消息快速添加或取消表情回应，所有可见参与者看到一致计数。

**对应功能面**：消息悬停工具条、表情选择器、消息下方回应区。

**发送者/发起者视角**：

1. 悬停消息后打开表情入口，选择表情即可提交。
2. 提交中保持消息位置稳定，避免重复点击产生重复计数。
3. 成功后对应表情显示已选状态，计数更新；再次点击可取消自己的回应。
4. 无权限或消息已不可互动时，入口隐藏或禁用并说明原因。

**接收者/观察者视角**：

1. 同一消息下的表情种类和总数自动更新。
2. 观察者自己的“是否已选”状态独立，不继承发起者的高亮。
3. 若观察者也回应，双方计数再次收敛，但各自选中态按本人操作展示。

**双视角收敛**：回应绑定同一消息和同一表情；总计数一致，个人选中态允许不同。

### UC08 加急与确认

**合同绑定**：G-07；`im_urgent_post`、`im_urgent_confirm`；`message.row.v1`、`read.receipt.v1`

**功能目标**：发送者将指定消息加急给选定成员，接收者确认后，发送者看到确认进展。

**对应功能面**：消息操作菜单、成员选择器、加急标记、会话列表角标、确认按钮、回执弹层。

**发送者视角**：

1. 从消息菜单选择“加急”，成员选择器仅显示可见且可加急的成员，不包含自己。
2. 选定接收者后提交，消息显示加急状态和待确认人数。
3. 接收者逐个确认后，待确认数减少、已确认数增加；点击统计可查看人员分组。
4. 加急提交失败时保留已选成员并允许重试，不伪造成功人数。

**接收者视角**：

1. 被选中的接收者看到醒目的加急消息、会话角标或待处理提示。
2. 打开消息后可执行一次“确认收到”；确认期间按钮显示处理中。
3. 成功后按钮转为已确认和确认时间，不能重复确认。
4. 未被选中的成员不应看到确认入口，也不应进入加急人员名单。

**双视角收敛**：发送者的已确认名单与接收者本人的确认状态一致；人员快照、已确认和未确认人数互相可对账。

### UC09 定时发送与取消

**合同绑定**：G-08 创建、G-09 取消；`im_create_schedule`、`im_cancel_schedule`；`channel.row.v1`

**功能目标**：发送者设置未来时间发送消息，并可在触发前取消；接收者不会提前看到正文。

**对应功能面**：消息编辑器、时间选择器、待发送提示、会话列表、定时管理入口。

**发送者视角**：

1. 在编辑器设置合法的未来时间，确认正文和发送时间后创建定时消息。
2. 创建成功后，当前会话显示“有定时消息”提示，待发送项可查看时间和内容摘要。
3. 到时前可取消；取消确认后提示和待发送项消失，编辑器可重新使用原内容。
4. 时间无效、频道关闭或创建失败时保留输入，并给出明确修正入口。

**接收者视角**：

1. 触发时间前不显示正文、不更新最后消息预览，也不增加未读数。
2. 到达发送时间并真正发出后，按普通新消息进入时间线和会话列表。
3. 发送者提前取消时，接收者侧不出现消息或“取消定时”的内部提示。

**双视角收敛**：定时阶段允许只有发送者可见；真正发出后双方收敛为普通消息，取消后双方都不存在接收结果。

## 4. 会话、历史、定位与回执

### UC10 会话首屏与更早历史

**合同绑定**：G-10 首屏、G-10a 更早历史；`im_query_messages_by_channel`、`im_load_older_context`；`message.row.v1`

**功能目标**：用户进入会话后看到正确首屏，并在顶部加载更早消息而不丢失阅读位置。

**对应功能面**：会话列表、消息时间线、顶部历史加载区、日期分隔线。

**发起者视角**：

1. 点击会话后，选中态立即明确，时间线显示稳定加载占位而不是旧会话内容。
2. 首屏完成后消息按时间顺序出现，并自动定位到合理的未读或最近位置。
3. 向上滚动到顶部时出现“加载更早消息”，加载期间不改变当前已读内容位置。
4. 更早消息插入后保持滚动锚点；无更多历史时显示明确结束态，失败时原内容仍可阅读并可重试。

**观察者视角**：

1. 发起者浏览历史不会强制改变观察者当前页面或滚动位置。
2. 观察者进入同一会话时，在自身权限范围内看到相同消息身份和相同顺序。
3. 个人未读位置、滚动位置和已读状态可以不同。

**双视角收敛**：共同可见的消息集合与顺序一致；个人导航状态和阅读进度保持私有。

### UC11 定位原消息

**合同绑定**：G-11；`im_get_posts`；`message.row.v1`

**功能目标**：从引用、回复、搜索结果或消息链接跳转到指定原消息。

**对应功能面**：引用卡片、搜索结果、回复抽屉、消息时间线。

**发起者视角**：

1. 点击引用或结果后，时间线加载目标所在上下文并滚动到目标消息。
2. 目标行短时高亮，用户可继续阅读前后消息。
3. 未找到、已撤回或无权限时显示原因和返回入口，不跳到错误消息。

**观察者视角**：

1. 发起者定位不会强制改变观察者的页面。
2. 观察者执行同一定位时，若有权限应落到同一消息；无权限时只能看到不可访问态。

**双视角收敛**：定位依据同一消息身份；是否能打开由各自权限决定，不能通过引用泄漏不可见正文。

### UC12 回复列表与回复分支

**合同绑定**：G-12；`im_get_replies`、`im_get_reply_branch`；`reply.tree.v1`

**功能目标**：围绕一条原消息查看和参与回复，时间线摘要与右侧回复抽屉保持一致。

**对应功能面**：消息回复入口、原消息回复摘要、右侧回复抽屉、抽屉编辑器、引用卡片。

**发送者/发起者视角**：

1. 点击“回复”后打开右侧抽屉，顶部固定原消息，下面按顺序显示回复列表。
2. 抽屉加载中保持原消息可见；空回复显示首条回复引导，失败时提供重试。
3. 在抽屉发送回复后，新回复先保留处理中位置，成功后进入正确分支。
4. 时间线原消息同步更新回复数量和最近回复摘要；点击摘要重新打开同一分支。
5. 点击某条引用可定位回原消息或分支内目标。

**接收者/观察者视角**：

1. 新回复到达后，原消息下的回复数量和摘要自动更新。
2. 已打开回复抽屉时，新回复自动插入正确位置，不需要关闭重开。
3. 可按权限继续回复；无权访问的分支不显示正文或参与入口。
4. 观察者不会看到发送者尚未成功的本地回复草稿。

**双视角收敛**：原消息、回复集合、回复顺序和回复总数一致；抽屉与左侧时间线不能出现两个互相矛盾的回复树。

### UC13 会话已读与单条已读

**合同绑定**：G-13 会话已读、G-14 单条已读；`im_channels_view`、`im_post_read`；`channel.row.v1`、`read.receipt.v1`

**功能目标**：接收者阅读会话或具体消息后清除自己的未读，并让原发送者看到准确回执。

**对应功能面**：会话列表未读角标、消息状态、已读/未读人员弹层、成员头像列表。

**接收者视角**：

1. 打开会话并达到阅读条件后，只清除自己的会话未读数。
2. 阅读指定消息后，该消息在本人侧进入已读状态；其他成员的状态不被代替修改。
3. 接收者可以看到自己是否已读，但不能伪造其他人的回执。
4. 回执提交失败时不应先把全员状态显示为已读。

**原发送者视角**：

1. 消息下方的已读人数、未读人数随真实成员阅读变化。
2. 点击回执可查看已读和未读人员分组，姓名、头像和成员身份对应发送时的成员范围。
3. 多人陆续阅读时，计数与名单连续更新，不能出现总数与人员列表不一致。

**双视角收敛**：接收者本人的已读状态必须出现在发送者的已读名单中；会话未读、单条回执和成员范围各自表达不同含义，不能相互替代。

### UC14 模板确认收到

**合同绑定**：G-14a；`im_template_received`；`message.row.v1`

**功能目标**：接收者对需要确认的模板消息明确表示“已收到”，发送者查看确认进度。

**对应功能面**：模板消息卡、确认按钮、确认状态、人员统计弹层。

**发送者视角**：

1. 模板消息发送后显示待确认人数和已确认人数。
2. 接收者确认后，统计自动更新，可查看确认人、未确认人和确认时间。
3. 不可把普通已读直接当成模板确认，未点击确认的人仍留在未确认组。

**接收者视角**：

1. 模板卡显示明确的“确认收到”主操作及其说明。
2. 点击后进入处理中，成功后变为不可重复操作的“已确认”状态并显示时间。
3. 已过期、已确认或无权限时按钮禁用，并显示对应原因。

**双视角收敛**：接收者的确认动作与发送者确认名单一一对应；已读和已确认保持为两个独立产品状态。

## 5. 群聊、话题与成员治理

### UC15 创建群聊与创建话题

**合同绑定**：G-15a 创建群聊、G-15 创建话题；`im_create_channel`、`im_make_topic`；`channel.row.v1`、`member.row.v1`、`reply.tree.v1`

**功能目标**：发起者选择成员创建群聊，或从一条消息创建独立话题；相关成员获得可进入的新会话。

**对应功能面**：新建会话入口、成员选择器、群名输入、消息操作菜单、会话列表、话题时间线。

**发送者/发起者视角**：

1. 创建群聊时输入名称并选择成员，选择器展示已选人数、成员身份和移除入口。
2. 提交期间防止重复创建；成功后新群出现在会话列表并自动进入，可立即发送消息。
3. 从原消息菜单选择“创建话题”时，确认话题名称、成员和根消息。
4. 话题创建成功后进入新话题，顶部保留来源信息，时间线含原消息或明确引用。
5. 名称无效、成员不足、无权限或创建失败时保留用户输入并允许修正。

**接收者/被邀请者视角**：

1. 被加入群聊后，会话列表自动出现新群，显示群名、成员摘要和创建系统事件。
2. 被加入话题后，可从新会话进入并看到相同根消息。
3. 未被选择的成员不应看到新群或话题内容。

**双视角收敛**：双方指向同一新频道、同一成员集合和同一话题根消息；创建成功不能只停留在发送者的成功提示。

### UC16 群关闭、成员退出与群资料修改

**合同绑定**：G-16 关闭/退出、G-16b 退出广播、G-16c 群属性修改；`im_channel_close`、`im_channel_leave`、`im_channel_change_display_name`、`im_channel_change_notice`、`im_channel_change_info`；`channel.row.v1`、`member.row.v1`

**功能目标**：群主按权限关闭群，成员退出群，管理者修改群资料，并让受影响成员看到正确终态。

**对应功能面**：会话头部更多菜单、群设置、危险确认、成员面板、消息时间线、会话列表。

**发送者/管理者视角**：

1. 关闭群聊前显示影响范围和不可逆提示；确认后群进入关闭或只读状态，编辑器禁用。
2. 修改群名、公告或资料时，保存按钮只在内容变化且合法时可用，保存期间避免重复提交。
3. 保存成功后头部、会话列表和群设置中的信息同步更新。
4. 没有管理权限时只能查看，不显示可提交的管理动作。

**接收者/普通成员视角**：

1. 群被关闭后自动看到群状态和系统事件，不能继续发送，但仍可按产品规则查看历史。
2. 其他成员退出后，成员列表自动移除该成员，时间线显示成员退出系统事件。
3. 自己退出时先确认；成功后会话从可用列表移除或进入已退出态，不能继续读取新增内容。
4. 群资料变更后自动看到新名称、公告或资料，但普通成员没有保存入口。

**双视角收敛**：关闭、退出和资料修改分别对应独立结果；管理者与普通成员动作不同，但群状态、成员集合和资料版本一致。

### UC17 频道置顶

**合同绑定**：G-17；`im_channel_change_top`；`channel.row.v1`

**功能目标**：用户将重要会话置顶或取消置顶，调整自己的会话列表顺序。

**对应功能面**：会话右键菜单、会话列表置顶区、置顶标识。

**发起者视角**：

1. 在会话菜单选择置顶，成功后该会话移动到本人置顶区域并显示置顶标识。
2. 取消置顶后按正常会话排序规则回到列表，不发生无意义跳动。
3. 提交失败时保持原排序并允许重试。

**接收者/观察者视角**：

1. 频道置顶是个人状态，其他成员的会话排序不应改变。
2. 其他成员不应看到谁把频道置顶，也不产生频道系统消息。

**双视角收敛**：双方仍指向同一频道，但个人置顶状态允许不同；频道内容和成员信息不受影响。

### UC18 消息置顶、公告与在线状态

**合同绑定**：G-18 消息置顶、G-18a 公告读写、G-18b 在线状态；`im_set_message_top`、`im_set_message_untop`、`im_announcement_list`、`im_announcement_save`、`im_announcement_read`、`im_channel_online_status`。本 Macro UC 名称过宽，本文按 Gate 分开描述。

**对应功能面**：消息操作菜单、置顶消息入口、公告面板、会话头部、成员面板。

**G-18 消息置顶**：

- 发起者从消息菜单置顶或取消置顶；成功后消息行显示置顶标识，置顶入口或摘要同步更新。
- 接收者自动看到同一消息的置顶或取消结果，可通过置顶入口定位原消息。
- 无管理权限的成员只能查看，不能看到可提交的置顶动作。
- 双方对置顶消息身份和当前置顶集合一致。

**G-18a 公告读写**：

- 有权限的发送者从公告面板选择消息或编辑公告，发布后看到公告卡和阅读进度。
- 接收者在会话头部或公告面板看到新公告，可打开详情并标记已读。
- 接收者阅读后，本人未读标记消失；发布者的阅读统计更新。
- 公告正文、公告身份和已读状态在各自权限内一致；无写权限者不显示编辑入口。

**G-18b 在线状态**：

- 发起者打开成员面板后看到成员在线、离线等状态和在线人数。
- 观察者打开同一成员面板时看到当前可公开的同一在线事实，但不会因为发起者查询而被强制打开面板。
- 在线状态仅影响成员展示，不产生时间线消息或更改成员权限。

**双视角收敛**：消息置顶和公告内容属于频道共享事实；公告阅读状态按成员区分，在线状态按可见权限展示，查询动作本身保持个人私有。

### UC19 按条件查找频道

**合同绑定**：G-19；`im_channel_query`；`search.result.v1`

**功能目标**：用户按名称、类型或成员等条件找到有权访问的频道并进入。

**对应功能面**：会话搜索、筛选器、频道结果列表、会话列表。

**发起者视角**：

1. 输入条件后显示加载状态和可清除条件，结果按相关性或产品排序展示。
2. 结果行显示频道名称、类型和成员摘要，点击后进入目标频道。
3. 无结果时给出修改条件的空态；失败时保留搜索条件并可重试。
4. 无权访问的频道不出现在结果中。

**接收者/观察者视角**：

1. 查询是个人操作，不改变其他成员界面。
2. 观察者使用相同条件时，只看到自己有权访问的结果，两人的结果集可以因权限不同而不同。

**双视角收敛**：共同有权访问的频道身份一致；搜索条件、历史和结果面板保持个人私有。

### UC20 成员加入、角色与群昵称

**合同绑定**：G-20 拉/踢人、G-20a 设/撤管理员、G-20b 改群昵称；`im_channel_member_change`、`im_channel_member_role`、`im_update_member_nickname`；`member.row.v1`。本 Macro UC 名称偏窄，本文按 Gate 分开描述。

**对应功能面**：成员面板、成员选择器、成员操作菜单、角色标识、昵称编辑、系统事件。

**G-20 添加与移除成员**：

- 管理者从成员面板选择添加成员，确认后新成员出现在成员列表，并显示加入系统事件。
- 被添加者自动获得新会话入口，进入后看到群资料和自己有权查看的历史。
- 管理者移除成员前看到危险确认；成功后成员列表和人数更新。
- 被移除者失去继续参与能力，不能再收到新内容；其他成员看到一致的成员变化。

**G-20a 设置或撤销管理员**：

- 管理者在成员行修改角色，提交期间角色控件锁定。
- 目标成员的角色标识和可用管理动作自动变化。
- 其他成员看到角色标签变化，但不能执行超出自身权限的动作。
- 不能移除最后必要管理者或越权修改更高角色，禁止原因明确可见。

**G-20b 修改群昵称**：

- 用户编辑自己在当前群的昵称，成功后成员面板和后续消息作者名同步更新。
- 其他成员看到该用户的新群昵称，不影响用户在其他频道或组织中的名称。
- 修改失败时保留输入并恢复旧昵称，不出现半更新状态。

**双视角收敛**：成员身份不因名称变化而改变；成员集合、角色和群昵称分别更新，不能用一个字段覆盖其他信息。

### UC21 成员快照与成员目录

**接收者/观察者视角**：

3. 管理动作因角色不同而不同，普通成员不获得管理按钮。

**双视角收敛**：成员列表以稳定成员身份对齐；姓名、头像、角色、在线态是同一成员的展示属性，不能制造重复人。

**G-26a 系统通知**：

- 接收者看到面向自己的通知卡和未读提示，打开后进入详情并更新本人阅读状态。
- 通知来源方不看到接收者的私人浏览路径，除非产品明确提供公开回执。
- 失效通知保留可理解摘要和失效原因。

**G-26b 模块列表**：

- 用户看到本人可访问模块及未读或状态提示，点击进入目标模块。
- 其他用户的模块列表不受影响；双方结果可因权限不同而不同。

**G-26c 维护公司大群**：

- 管理者创建或更新公司大群后，会话列表和群资料显示最新状态。
- 被纳入范围的接收者自动获得公司群入口；不在范围内的用户不可见。
- 双方对同一公司群身份、名称和成员范围一致。

**G-26d 退出公司**：

- 成员从组织设置执行退出，确认页明确说明将失去的公司群和组织能力。
- 成功后本人公司群进入移除或不可用状态，相关组织入口同步收敛。
- 管理者或仍在组织内的观察者看到成员关系变化，但不暴露退出者的私人确认过程。

**双视角收敛**：待办、通知和模块状态属于个人视角；公司群身份、成员关系与退出结果属于共享事实，退出者失去访问和组织侧移除成员必须收敛为同一终态。

### UC27 他人新消息自动接收

**合同绑定**：G-27；`im_send_message`；`message.row.v1`

**功能目标**：重点验证接收方体验，即另一用户发送消息后，观察者在当前会话、后台会话和重新进入场景下都能自然获得消息。

**对应功能面**：消息时间线、会话列表、未读角标、最后消息预览、新消息提示。

**发送者视角**：

1. 在双方共同会话发送消息，发送中和成功效果与 UC01 一致。
2. 成功后时间线和会话预览显示最终消息，不需要关注接收者是否正停留在该页面。
3. 发送失败时只在发送者侧处理，不能让接收者看到半成品。

**接收者视角**：

1. 正在查看该会话时，新消息自动进入时间线并保持正确顺序。
2. 停留在其他会话时，目标会话的最后消息、时间和未读数自动更新。
3. 稍后进入会话时可以看到完整消息；恢复连接后不重复、不丢失。
4. 可从消息继续回复或表情回应，形成后续双向互动。

**双视角收敛**：发送者已发送与接收者已接收指向同一消息；当前页、后台页、晚进入和恢复后的结果一致，接收方不需要手动同步。

## 7. Helix 横切同步体验

以下四项不计入 UC01-27，但决定双视角交互能否自然成立：

| Gate | 用户体验作用 | 发送者/接收者效果 |
|---|---|---|
| G-S1 初始会话加载 | 应用进入后恢复会话列表 | 双方各自看到有权访问的会话、选中会话和未读状态 |
| G-S2 增量同步 | 新消息或频道变化到达时更新会话 | 接收者自动获得会话预览、未读和消息变化，不需要同步按钮 |
| G-S3 gap 补偿 | 短暂断线或事件缺口后恢复 | 恢复后不重复、不乱序，缺失期间的结果补齐 |
| G-S4 陌生频道兜底 | 收到尚未加载频道的消息时补齐频道 | 接收者先获得可理解的会话行，再进入消息，不出现无归属消息 |

## 8. Product 与 Design 共识

1. 每个跨用户写操作都必须同时设计发起方过程态和观察方自动结果，不能只设计“操作成功”提示。
2. 私有能力保持 self-only：频道个人置顶、搜索、书签、待办、模块查询不应强行广播给另一方。
3. 权限类功能以不同动作收敛到同一事实：管理者可编辑，普通成员只读，但群状态、成员和消息身份一致。
4. 消息时间线、会话列表、右侧抽屉和统计弹层属于同一产品结果的不同功能面，任何一面都不能长期显示旧状态。
5. UC18、UC20、UC26 本轮沿用现有 Macro 编号，但实施和验收时必须按其 Gate/Operation 分项处理。
