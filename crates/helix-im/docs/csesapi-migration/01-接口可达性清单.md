## 2. 横切基础设施契约（迁移必须 1:1 复刻）

### 2.1 路由根前缀

```
model.APIURLSuffixCSES = "/api/cses"
```

所有端点挂在 `srv.Router.PathPrefix("/api/cses").Subrouter()` 派出的子路由器下。未匹配兜底：`/api/cses/{anything:.*}` → `Handle404`。

子路由器全集（`Routes` 结构体）：APIRoot · Health · Posts · Agents · Post · PostApproval · Search · Channels · Channel · ChannelMembers · ChannelMember · PostBookmark · Notification · Users · Groups · Teams · Modules · BotManage · BotAgent · Sync。**PostSegment 族已于 2026-05-27 Step 8b.4 下线，不迁移。**

### 2.2 HTTP 响应信封 — dto.CommonRes（不可变契约）

JSON 结构（`server/channels/entity/dto/common_res.go`）：

```json
{ "status": "SUCCESS", "message": "...", "data": <any> }
```

| 字段 | 类型 | tag | 备注 |
|---|---|---|---|
| status | string | `json:"status"` | 必填 |
| message | string | `json:"message,omitempty"` | 零值省略 |
| data | any | `json:"data,omitempty"` | 零值省略 |

status 枚举（唯三合法值）：

| 常量 | 字符串 | 语义 |
|---|---|---|
| SUCCESS | `"SUCCESS"` | 成功 |
| FALSE | `"failed"` | 业务失败 |
| FINISH | `"FINISH"` | 完成 |

构造链：`dto.NewCommonRes().SetSuccess().SetData(x)` / `.SetFailure().SetMessage(s)` / `.SetMessageByErr(err)` / `.SetFinish()`。

写回唯一入口 `WriteJSON`：**HTTP 状态码永远 200**，业务成败靠 `status` 字段，不靠 HTTP code。唯一例外是 `rejectPersonalUser` 写 403。少量工具端点用裸 `WriteJSON(map)` 或 `wrapControllerFunc`（失败写 500），不走信封——属非主流，迁移时建议统一。

### 2.3 APIHandler 包装

- `web.Handler` 固定：`RequireSession=false`（csesapi 自行鉴权）、`TrustRequester=false`、`RequireMfa=false`。
- 入站 `Cses-Track-Id` header → `SanitizeCsesTrackId`（≤64 字符截断）→ **handler 执行前** Set 到响应头；空串不写。
- `/api/cses/health` 跳过 duration 日志。
- `ServiceSettings.WebserverMode=="gzip"` 时外套 `gzhttp.GzipHandler`。

### 2.4 鉴权入站约定（不可变）

token 解析顺序（`ParseAuthTokenFromRequest`）：

```
1. X-Bot-Token header                          → Bot Token
2. Authorization: Bearer mp_<token>            → Bot Token
3. Cookie MMAUTHTOKEN                           → Cookie
4. Cookieid header                             → Cookie（cookieId 即 userId 主路径）
```

userId / companyId 注入（`web/handlers.go`）：

```
userId    = userId header   优先，否则回落 cookieId header
companyId = companyId header 优先，否则回落 teamId header
```

Session 关键字段：`UserId`（JSON tag 是 `"id"`）、`CookieId`、`Token`、`CompanyId`。等式 `CookieId == Token == UserId`（约束 C-CIDUID-001/002）。Handler 内取 userId：`c.AppContext.Session().UserId`。

### 2.5 个人用户守卫（personal_guard.go）

```go
const PersonalUserForbiddenMessage = "PERSONAL_USER_FORBIDDEN"
// IsPersonalUser = session != nil && session.CompanyId == ""
// 命中 → w.WriteHeader(403) + {"status":"failed","message":"PERSONAL_USER_FORBIDDEN"}
```

调用方式：handler 开头 `if rejectPersonalUser(c, w) { return }`。team.go 三条路由全部走此守卫。

### 2.6 Cses-Track-Id 透传

- HTTP header 名：`Cses-Track-Id`（`model.CsesTrackIdHTTPHeader`，禁改名）
- WS envelope key：`csesTrackId`（驼峰，`model.EnvelopeCsesTrackIdKey`）
- ≤64 字符截断；服务端不解析/不持久化；handler 执行前 Set 响应头。

## 6. 迁移高风险点速查（按需优先攻关）

1. **Pulsar 异步落库链**：createPost/createPosts/createSchedule + 各系统消息走 SenderTopic/ScheduleSenderTopic/MockTopic，post_consumer 异步落库。createSchedule 依赖 Delayed Delivery，不可换普通 MQ。
2. **channel_event co-tx 离线同步 v2**：urgent/revoke/quickReply/makeTopic/templateReceived/updatePostProps 全在 ent.Tx 内 AppendEvent；event_seq 注入 post.props 随 WS 帧给客户端 pts gate。须携带 appendEntPostUpdateEventCoTx / appendEntPostDeleteEventCoTx / setEntPostEventSeqProp 共享 helper + PG `alloc_channel_event_seq` 函数 + channel_event 分区表。
3. **gRPC 外部依赖（paas-grpc）**：ReadMembersMinimalByUserIdsRaw / readIdNameListByUserIdsWithOutContext / ReadIdNamesByUserIdsRaw 用于回填用户名（channel.go 加/减管理员、loadChannelPostPinned、channelMemberChange、bot_agent 成员查询）。
4. **Elasticsearch 在线状态**：channelOnlineStatus 依赖 ES websocket 索引聚合，须迁 ES 或替换为 Redis/Hub 方案。
5. **Redis-first 路径**：getUpdatedPosts 走 ZSET+HMGET（不走 DB）；createSchedule/getSchedule 走 Redis SET/GET；makeTopic 用 Redis SetNX 幂等锁。
6. **原生 mattermost 深耦合**：createUser（4 分支 + 审计 + 邮件 + Plugin Hook + NewUser/UserUpdated 全局广播）、getUserStatusesByIds（PlatformService statusCache）。
7. **已知 bug 须随迁修复**：notification.loadSend offset（×Page 应 ×Size）；team.upsert body 双 decode；team.quit 成功无响应体；search.user/channel 桩 + nil panic；posts.getPostsAfterIndex json tag 命名；modules message 笔误；channelMemberLeave 内 panic 调用。
8. **WS 框架**：botCallback/agentCallback 直接 a.Publish；其余 channel_event 驱动；Hub/web_conn/Publish 体系须完整保留。
9. **裸响应不走信封**：webhook_dispatcher 三条（map）、health（ReturnStatusOK）、createUser（201 + *model.User）；迁移后建议统一为 dto.CommonRes。
