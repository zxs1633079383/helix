# helix-im · EventBus 文档

> IM 模块 EventBus 的设计文档集。core 层通用契约见仓库根 [`docs/过会方案/helix-eventbus-下游能力契约.md`](../../../../docs/过会方案/helix-eventbus-下游能力契约.md)；本目录是 IM 侧落地。

| 文档 | 一句话 |
|---|---|
| [`场景全集.md`](./场景全集.md) | **MVP1 交付**：现网 cses-client 全部 EventBus 场景（~130 个），按 **PUB/REP/本地三层粒度** + 业务域双轴分离 |
| [`下游域卡.md`](./下游域卡.md) | IM **消费者**域卡（通知/@我/未读/生命周期；运维 D-05 已下线），反推驱动，每域一卡 |
| [`域卡-任务.md`](./域卡-任务.md) | 未来 `helix-task` 模块**生产者**事件卡（指派/状态/截止/评论@我/检查点） |
| [`域卡-会议.md`](./域卡-会议.md) | 未来 `helix-meeting` 模块事件卡（40 PUB + **5 REP 闭环**，REP 最佳范例） |
| [`域卡-文档.md`](./域卡-文档.md) | 未来 `helix-doc` 模块事件卡（分享/评论/权限，现网无实时推送=helix 价值补位） |

> **两类卡区分**：`下游域卡` = IM 事件的**消费者**域（谁拿 IM 事件干活）；`域卡-{任务,会议,文档}` = 各业务模块的**生产者**事件契约（暂存此处，模块立项后迁各自 crate docs）。

## 阅读顺序

1. 先读 **场景全集** —— 知道"现实世界要支持哪些事件 + PUB/REP 怎么分"（广度）。
2. 再读 **下游域卡** —— 知道"每个消费者域要什么上下文才能干活"（落地）。
3. 业务模块各卡 —— 各域生产者事件契约。
4. 红线：core 不认识业务、relevance 各下游域自己算（见域卡 §0/§3.2）。
