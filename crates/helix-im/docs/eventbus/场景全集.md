## §0 三层粒度分离（先分语义，再分域）

> 这是本文的**第一切分轴**——每个场景先归一种语义，再落到业务域。

| 语义粒度 | 判据 | helix 落点 | 占比 |
|---|---|---|---|
| 🔵 **PUB 单向广播** | 发了就走，无人要回音 | `Effect::Emit` → `EventSink::emit` | ~110（主体） |
| 🟢 **REP 双向问答** | 发起方必须拿到**一一对应**的回答才能推进状态机 | `Effect::Request`/`Reply` + corr | ~20 |
| ⚪ **纯本地 / 派生 / CRDT** | 不过网络（内存 EventBus / 本地 UI / Yjs 自洽） | **不进 EventBus** | 若干 |

**REP 再细分两方向**（见 §4）：方向① core→host→core（等对端/用户拍板）· 方向② host→core→host（UI 主动查 core 内存态）。

## §1 现网机制现状 → helix 统一目标

现网跑着 **5–6 套并行"总线"**，helix 要收口成一套：

| 机制 | 域 | 语义 | helix 归一 |
|---|---|---|---|
| `im:__bus__` 单总线 + 信封 | IM | PUB | `Effect::Emit` |
| `dataPilot-dataChange` WS（80ms 批） | 任务 | PUB | `Effect::Emit` |
| `EventBusService.use('Meeting')` action + HTTP accept/refuse | 会议 | PUB + REP | `Emit` + `Request/Reply` |
| Yjs `y-websocket` + awareness | 文档协同 | 本地 CRDT | ❌ 不进 |
| Tauri `invoke()` / `send()` | 全局 | REP方向② / PUB | `Request/Reply` / `Emit` |
| 内存 `CoreEventManager` / RxJS | 任务/IM | 本地 | ❌ 不进 |

> 碎片化代价 = 每域各写一遍重连/去重/红点/@我；helix 统一 = 一套信封 + 一套 catch-up。

**规模分布**：

| 域 | PUB | REP | 本地/HTTP | 突出缺口 |
|---|---|---|---|---|
| IM | ~22 | 1 | — | typing/presence 未实现 |
| 任务/进度 | ~10 | 0（HTTP confirm） | ~15 | OKR 仅 UI |
| 会议 | 40 | 5 | — | 改期/日历提醒在他处 |
| 文档 | ~6 | 0 | ~19（HTTP poll） | 评论/分享/权限**无实时推送** |
| 通用层 | ~20 | ~13（invoke）+confirm | — | 强制下线/限流未实现 |

### §2.5 通用层（`messageNotice.service.ts`、`network-interceptor.ts`、`update.service.ts`）
- **通知中心**（三层收口）：系统弹窗（Rust 窗口 110000，`changeSize` 动态高度）· 待办红点（CoreEventManager+SQLite）· IM 加急（`expediteMap{recipients,sender}`）。

## §3 ⚪ 纯本地 / 不进 EventBus（划清边界，避免重复造轮子）

| 场景 | 现网机制 | 为什么不进 helix EventBus |
|---|---|---|
| 文档内容编辑同步 | Yjs `update`（CRDT） | CRDT 自解冲突，域内自洽 |
| 协作者光标 / 进出 | Yjs `awareness` | awareness 协议自管 |
| 任务组件间通信 | 内存 `TaskEventBus`（RxJS） | 不过网络，组件本地 |
| 文件上传进度 / 同步状态 | 本地进度事件 / IndexedDB | 本地 UI 态 |

## §4 🟢 REP 双向场景全集（两方向细分）

> REP = "发出后必须拿到一一对应的回答才能推进"。靠 corr 配对，非阻塞 call-return。判据/机制见 [REP 文档](../../../../docs/过会方案/helix-eventbus-设计.md)。

### §4.1 方向① core→host→core（发起方等对端/用户拍板）
| 场景 | 发起→等待 | 请求 | 响应 | 超时兜底 |
|---|---|---|---|---|
| 会议邀请确认 | 主持人→被邀请者 | `invitedUsersNeedConfirm` | HTTP `acceptInvitedUsersConfirm`/`refuse` | ✅ |
| 入会申请批准 | 参与者→主持人 | `applyJoin` | HTTP `acceptApply`/`refuseApplies` | ✅ |
| 开麦申请批准 | 参与者→主持人 | `applyOpenMicrophone` | HTTP `accept`/`refuseOpenMicrophone` | ✅ |
| 开麦邀请反馈 | 主持人→参与者 | `inviteOpenMicrophone` | HTTP `feedbackOpenMicrophoneInvite{accept}` | ✅ |
| 本地录制批准 | 参与者→主持人 | `applyLocalRecord` | HTTP `accept`/`refuseLocalRecord` | ✅ |
| 入群邀请待决策(IM) | core→用户 | `Effect::Request` | `Tick::PortReply` | ✅ ScheduleTimer |
| UI 二次确认(删除/覆盖) | core→UI | `NzModalService.confirm` | Promise resolve/reject | 用户驱动 |

> 机制：申请→server 广播待批 action→对端 HTTP 响应→广播结果 action。**会议 `callTimeOut` 实证超时兜底是刚需**。

### §4.2 方向② host→core→host（UI 主动查 core 内存态）
Tauri `invoke()` 同步返回，~13 个：`context:getAuth`/`get_device_id`/`system_app_version`/`im:getConnectionId`/`window:getParams`/`getScreenInfo`/`store:getItem/setItem/updateItem` 等。
> **同步进度**：core 主动"播报"走 PUB Emit；UI"主动问当前进度"才是方向② REP——别混（判据见 REP 文档 §0/§5）。

## §5.5 下游消费域视角（谁拿事件干活 · 跨业务域汇聚）

> §2 是"按事件产出域"切；本节是"按**下游消费域**"切——同一消费域汇聚来自 IM/任务/会议/文档的事件。细节（消费字段/缺字段降级/catch-up/反推校验）见 [`下游域卡.md`](./下游域卡.md)。

### D-01 系统通知域（弹窗 / 横幅 / 声音）
| 场景 | 订阅事件 | 触发 |
|---|---|---|
| 新消息桌面通知 | `im:post:received` | 非我发的消息到达（`actor != me`） |
| 加急消息通知 | `im:channel:increment`（urgentPostList） | 有人发加急给我 |
| 任务指派/截止/催办通知 | `task:assigned`/`deadline-near`/`member-rejected` | 任务系统通知 |
| 文档分享/评论通知 | `doc:shared`/`doc:commented` | 文档动作冲我来 |
| 会议开始/呼叫提醒 | `meeting-remind`/`callJoin-remind` | 会议到点 / 被呼叫 |

### D-02 @我 / 与我相关域（聚合流 + 红点）
| 场景 | 订阅事件 | relevance 谓词（域持 me 自算） |
|---|---|---|
| @我消息 | `im:channel:increment` | `mentionList.contains(me)` |
| 加急@我 | `im:channel:increment` | `me ∈ urgentPostList` |
| 回复我 | `im:post:received` | `reply_to.author == me` |
| 待办(@我/加急/回复我) | `im:todo:updated` | items 命中 me |
| 任务指派我/@我 | `task:assigned`/`task:commented` | `me ∈ members/leaderIds`、`me ∈ mentions` |
| 文档分享我/评论我 | `doc:shared`/`doc:commented` | `me ∈ collaborators`、`toUserId == me` |
| 会议邀请我/呼叫我 | `invitedUsersNeedConfirm`/`meetingCall` | `me ∈ members/users` |

### D-03 未读徽章域（per-channel + 全局计数）
| 场景 | 订阅事件 | 算法 |
|---|---|---|
| 频道未读+ | `im:channel:increment` | 增量条目累加 |
| 批次结束结算 | `im:channel:update` | 该 channel 本批收完 |
| 任务/文档未读 | `task:status-changed`/`doc:*` | 各模块列表未读 |

> 派生态：重连后由 cursor / `im:channels:loaded` 重算，不靠 replay 累加（防重复计数）。

### D-04 生命周期 / 连接状态域（连接·就绪·断线）
| 场景 | 订阅事件 |
|---|---|
| WS 连接建立 | `im:connection:established` |
| 冷启动同步完成 | `im:channels:loaded` |
| 缺口过大需重拉 | `im:sync:too_long` |
| 频道创建/关闭 | `im:channel:created`/`:closed` |
| 增量同步开始/空/失败 | `im:post:increment[-started/-empty/-failed]` |

> 当前快照语义，不 replay；重连以最新一条为准。

### D-05 运维域　🚫 已下线
不做（强制下线/限流现网未实现；token 过期/版本更新走 interceptor/UpdateService）。重启需先立 ADR。详见 §3.5 / [下游域卡 D-05](./下游域卡.md)。

## §6 数据格式：统一信封（三补字段已定 · 2026-06-16）

现网各域信封不一（`im:__bus__` / `{mode,pk,body}` / `{action,body,messageId}` / 系统通知 `{id,type,operation,content,members}`）。helix 统一一个信封：

```
EventEnvelope { v, type, actor, scope/target, ts, event_seq, causation_id, payload }
```
| 字段 | 状态 | 谁填 | 解锁 |
|---|---|---|---|
| `type`/`scope`/`payload` | 现网已有 | helix-im | 订阅过滤 + relevance 原始字段 |
| **`actor`** | ✅ 补·已定 | helix-im | 通知"非我才弹"（`actor != me`） |
| **`event_seq`** | ✅ 补·已定 | host 注入(确定性) | catch-up replay 锚点（对齐 HX-C008） |
| **`causation_id`** | ✅ 补·已定 | helix-im 透传触发帧 | 审计 / "一次操作扇出"溯源 |

- **relevance 各下游域自己算**：payload 必透传 `mentionList/urgentPostList/assignee/invitor/collaborators/recipients`，core 不下结论。
- 批次边界 = 一个 step 整批过界（HX-C007）。
- 字段规格权威源 = [能力契约 §3.1.1](../../../../docs/过会方案/helix-eventbus-设计.md)。
