# InteractionFrame v2 - 首批纵切总览与硬切准入

> 状态：Review Draft / Implementation Contract。本文定义目标态，不把任何 `planned` Gate 误记为已实现或已验证。
>
> 范围：GS01-GS04、G01 的先行实现合同，以及 G02-G16c 的终局下行呈现边界。
>
> 上位总合同：[UC01-16-界面投影视图模型与交互帧合同.md](../UC01-16-界面投影视图模型与交互帧合同.md)。本目录把总合同拆成可逐 Gate 实施和审查的分册；不修改该总合同当前的用户编辑内容。

## 1. 已拍板的边界

1. `InteractionFrame v2` 是 IM 业务 UI 的唯一真源。PC 和 Mobile 不再根据 `im:post:*`、`im:channel:*`、`increment_*`、`im:channels:loaded` 等 raw emit 重建业务 UI。
2. 全 IM 的 legacy raw emit 是待物理删除的 producer。删除后，尚未有 v2 producer 的 Gate 明确为 **planned / 无下行呈现**，不得伪报可用。
3. V2 有九个 Surface：既有八个数据 Surface，加 `message.composer@Channel(channelId)` 这一频道级交互 Surface。
4. `helix-im` 拥有 Surface scope、权限、epoch、revision、actionRef、领域裁决和 SurfaceComposer；`helix-core` 不认识任何 IM/UI 类型。
5. PC/Mobile 使用同一份生成的 v2 decoder、Frame Cache 语义和 renderer key。布局、动画、控件实现属于平台；消息类型、未读、排序、权限、temporaryId 对账不属于平台。
6. V2 wire 禁止 `SurfaceDataVm`、`Record<String, unknown>`、raw WS/HTTP JSON 作为业务旁路。新增类型通过版本化 tagged union、codec registry 和 renderer registry 显式接入；未知 kind/version fail-closed。
7. 同步状态需要 UI 展示，但不是业务 Surface。它放入 `InteractionFrame.runtime`；旧 `im:ready`、`im:health`、`im:sync:gap` 下线。
8. 一帧先原子替换 Cache，再执行一次性 `UiDirective`。`FrameApplied` 和 `DirectiveApplied` 分别确认；二者都不阻塞已持久化的业务流程。

## 3. V2 的最小协议外壳

```rust
struct InteractionFrameV2 {
    schema_version: 2,
    transaction_id: TransactionId,
    runtime: Option<RuntimeStatusVm>,
    mutations: Vec<SurfaceMutationV2>,
    directives: Vec<UiDirective>,
}

struct SurfaceMutationV2 {
    surface: SurfaceId,
    scope: SurfaceScope,
    surface_epoch: SurfaceEpoch,
    revision: Revision,
    base_revision: Option<Revision>,
    causation_id: Option<RequestId>,
    mutation: TypedSurfaceMutationV2,
}
```

一帧必须至少改变一项：`runtime`、一个 surface mutation 或一个 directive；不允许空包当心跳。`runtime` 和 mutation 同帧时进入同一原子 Cache 提交。directive 不能单独成为业务真相。

```rust
struct RuntimeStatusVm {
    connection: ConnectionState,       // connecting | online | offline
    initial_sync: InitialSyncState,    // idle | syncing | ready | failed
    recovery: RecoveryState,           // idle | syncing | recovered | failed
    session_epoch: SessionEpoch,
}
```

它只决定全局“同步中”提示，不含 Channel、Message、未读、Row 或 ActionBinding。

## 4. 九个 Surface 与唯一 owner

| Surface | Scope | Helix 领域来源 | 平台读到的内容 |
|---|---|---|---|
| `message.left-dialog-list` | `User(userId, teamId)` | Channel + ViewerState + preview Message + TopicLink | 会话顺序、preview、个人角标、频道终态。 |
| `message.unread-summary` | `User(userId, teamId)` | ViewerState aggregate | 全局未读、@我、加急计数。 |
| `message.timeline` | `Timeline(channelId, windowToken)` | Message + Channel + ViewerState + TopicLink | 当前有界消息窗口和行级动作。 |
| `message.thread-detail` | `Thread(channelId, rootMessageId)` | root/reply Message | 根消息和有序回复窗口。 |
| `message.channel-summary` | `Channel(channelId)` | Channel + ViewerState | 头部、设置、生命周期、频道治理动作。 |
| `message.member-roster` | `MemberRoster(channelId, cursor)` | ChannelMember + Presence | 成员窗口、角色、行级成员动作。 |
| `message.topic-list` | `TopicList(parentChannelId, cursor)` | TopicLink + Channel | 话题窗口。 |
| `message.participant-receipts` | `ParticipantReceipts(channelId, messageId, kind)` | receipt state + member snapshot | 回执明细窗口。 |
| `message.composer` | `Channel(channelId)` | Channel + ViewerState + policy | 当前频道能发什么、为何不能发、稳定 capability catalog。 |

跨 Surface 的展示重复是刻意的 view denormalization：任意已 attach slot 都能独立渲染，不要求客户端 join `MessageStore` 或 `ChannelStore`。禁止的重复是同一个 VM 内把不相关特性堆成无类型属性包。

## 5. VM、Row、内容类型的扩展规则

### 5.1 Surface shell 只包含该视图的稳定形状

- collection Surface：`items + page + state + surface-specific context`；
- aggregate Surface：只包含已经裁决的统计值；
- detail Surface：完整的可渲染 body 和该 detail 的 capabilities；
- interaction Surface：能力目录，不承载草稿、文件对象、光标或消息行。

`ActionBinding` 仍可作为有界 `Vec` 出现在确实拥有动作的 Row/VM 内。不要为了包装一个 vector 再造一层空对象；也不要把 `sendText/sendMedia/...` 写成 Composer 根字段。

### 5.2 消息类型扩展点

```rust
struct MessageComposerVm {
    availability: ComposerAvailabilityVm,
    capabilities: Vec<ComposerCapabilityVm>,
}

struct ComposerCapabilityVm {
    capability: ComposerCapabilityId, // message.create | message.schedule
    binding: ActionBinding,
    input_contract: InputContractRef, // im.message-content.v2
}

struct CreateMessageInput {
    content: VersionedMessageContentInput,
    reply: Option<ReplyReference>,
}
```

`VersionedMessageContentInput` 与 `MessageContentVm` 都是封闭、版本化 tagged union。新类型只在自己的 codec、validator、outbound builder、Helix projector、PC renderer 和 Mobile renderer 注册；不会给 `MessageComposerVm`、DialogRow 或 Frame Cache 外壳加一串新字段。

## 6. SurfaceComposer 的职责

`SurfaceComposer` 是 `helix-im` 内部编排器，不是 `message.composer` Surface。

```text
CommittedFactSet + AttachIndex + ViewerIdentity + RuntimeStatus
  -> ImpactPolicy（事实 -> 受影响 slot）
  -> typed projectors（事实 -> 完整 VM/Row）
  -> stable ordering / revision allocation / action grant refresh
  -> 一个 InteractionFrame v2
```

它只在对应事实已经 `PersistOk` 后工作。未 attach 的 slot 不发 mutation；事实仍已持久化，下一次 attach 必得最新 snapshot。全部 slot 按 `(SurfaceId, canonical_scope)` 稳定排序，避免 HashMap 迭代造成跨端字节漂移。

## 7. raw emit 下线政策

| 阶段 | 允许事项 | 不允许事项 |
|---|---|---|
| 文档与 review 前 | 读取旧 producer 作为事实来源；不以它作为新 V2 设计。 | 为 V2 新增 raw emit 或客户端 fallback。 |
| 文档 review 通过后 | 物理删除全 IM legacy business raw emit producer，按 `09` 清单执行。 | 把 planned Gate 说成 V2 已实现或用 raw 回填。 |
| Gate 实现期 | 每个 Gate 只产出 Frame v2 / ActionReceipt v2 / 必要 host effect。 | 重建 `im:post:*`、`im:channel:*`、`increment_*` producer。 |

此政策是已接受的主动硬切：文档审查后，G02-G16c 在尚未实现其 v2 producer 时会无下行呈现。`09` 必须保留此事实，不能用“覆盖文档”冒充 runtime green。
