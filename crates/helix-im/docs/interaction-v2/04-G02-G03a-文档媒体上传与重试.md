# G02-G03a - 文档、媒体、上传过程态与重试

> 状态：终局 V2 合同。G03 的真实文件选择、文件句柄与上传通道在本轮 deferred；本文件不把它们伪装成已设计/已实现。

## 1. 共用原则

G02、G03 与 G01 共用 `message.composer` 的稳定 `message.create` capability 和 `im.message-content.v2` 输入合同。区别只能在 `content.kind` 的 codec、effect plan、过程态和最终 `MessageContentVm`；不能为每一种内容给 Composer 根 VM 增字段。

```text
message.create
  + content.kind=document -> G02
  + content.kind=media    -> G03
  + same actionRef / channel scope / epoch validation
```

## 2. G02 - 文档消息

| 层 | 完整合同 |
|---|---|
| ActionBinding | `message.create`，输入 content kind=`document`；只允许 Helix policy 已提供的 document reference。 |
| Command Tick | 校验 binding、document reference、访问权、reply；创建 temporary Message。 |
| Effects | `PersistAtomic(temporary document Message + PendingSend)` -> PersistOk 后 `Http(CreatePost)` + timeout。 |
| 过程 Row | `MessageRowVm.content=Document{documentId,title,summary,access}`，`delivery=Sending`。 |
| Composer | timeline + dialog；已打开 thread 时条件更新。发送者不改自己的 unread。 |
| Echo | canonical document facts PersistOk 后将同一逻辑行 settle 到 `Sent`。 |
| UI | PC/Mobile renderer 以 document semantic renderer key 画卡片；不解 raw `props.document`。 |

## 3. G03 - 媒体/文件消息

### 3.1 本轮明确的边界

文件选择、操作系统句柄、权限令牌、上传分片、断点续传属于 host/driver 能力，**本轮 deferred**。V2 不允许把浏览器 `File`、Tauri path、FFI pointer 或 raw upload props 传进 VM/Frame。

### 3.2 保留给后续实现的 typed 合同

```text
HostObservation::SelectedAttachment(opaque host reference)
  -> Helix validates policy
  -> temporary Message { content=MediaPending, delivery=Uploading(progress) }
  -> PersistOk -> timeline/dialog Frame
  -> Effect::PrepareUpload / PutUpload / CreatePost
  -> progress PortReply -> throttled Persist + Frame
  -> WS canonical echo -> Sent Frame
```

| 数据 | V2 目标类型 |
|---|---|
| 输入 | `MediaInputRef`，版本化、host opaque、不可直接渲染。 |
| 过程内容 | `MediaPendingVm { mediaKind, displayName }`。 |
| 过程 delivery | `Uploading { progressPercent }`。 |
| 最终内容 | `Media { resource, thumbnail?, fileName, size, availability }`，所有字段为 typed union。 |
| 影响 Surface | timeline、dialog，条件 thread；上传进度不会让 composer actionRef 重签。 |

每次进度更新只更新所属 message 行的有界 timeline/thread VM；节流由 Helix/driver 合同决定，端侧不得自行猜进度。

## 4. G03a - 重试失败消息

`retrySend` 不在 composer capability catalog 中，而在失败 `MessageRowVm.actions` 中：它必须绑定具体 `temporaryId`、失败原因和 retry policy。

```text
MessageRowVm { id=T, delivery=Failed{retryable=true}, actions=[retrySend(T)] }
  -> ActionInvocationEnvelope(surface=message.timeline, scope=window, actionRef=retrySend)
  -> Tick::Command
  -> PersistAtomic(same T, delivery=Sending, retry attempt)
  -> PersistOk -> timeline/dialog Frame
  -> existing upload/create plan
  -> echo -> same T settle Sent
```

禁止 retry 创建第二个消息行、第二个 temporaryId 或前端复制原文重新调用 `message.create`。若 retry policy 不允许，binding 不下发或 `enabled=false` 并带 typed disabled reason。

## 5. Frame 与 UI

| 事实提交 | Frame mutation | PC/Mobile 呈现 |
|---|---|---|
| document PersistOk | timeline/dialog replaceView，row=`Document + Sending` | 文档卡 + 发送中。 |
| media prepare PersistOk | timeline/dialog row=`MediaPending + Uploading(0)` | 媒体占位与进度。 |
| upload progress PersistOk | 所属窗口 row progress 更新 | 进度变化，不重建业务排序。 |
| retry PersistOk | 同一 row `Failed -> Sending/Uploading` | 失败按钮收起，恢复过程态。 |
| canonical echo PersistOk | 同一 row `Sent + final content` | 最终内容卡。 |

所有 Frame 仍走 `03` 的整帧校验、原子 apply、ack/resync。物理文件/上传实现 deferred 不影响本合同中 G03 的 planned 状态标注。
