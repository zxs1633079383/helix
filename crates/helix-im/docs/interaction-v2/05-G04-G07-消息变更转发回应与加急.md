# G04-G07 - 撤回、转发、回应与加急

> 状态：终局 V2 合同。所有动作都由所属 Row 的 ActionBinding 或明确 HostObservation 进入 Helix；端侧不据 raw WS 自行改行。

## 1. 动作 owner 总览

| Gate | ActionBinding owner | 为什么 |
|---|---|---|
| G04/G04a 撤回/离线撤回重放 | timeline/thread 的目标 `MessageRowVm` | 权限、身份和待撤回消息都绑定具体行。 |
| G05 转发 | timeline/thread 的一个或多个已选 `MessageRowVm` | 输入是 selection overlay 的提交结果；Helix 验证全部来源/目标。 |
| G06 reaction | timeline/thread 的目标 `MessageRowVm` | 作用于一条确定消息，selected state 依 viewer 投影。 |
| G07 加急/确认 | timeline/thread 的目标 `MessageRowVm`；确认动作也可在 receipts row 上出现 | 目标、权限、确认人都由领域事实决定。 |

## 2. G04 - 撤回消息

```text
ActionInvocation(revokeMessage@message T)
  -> Tick::Command
  -> validate author/role/lifecycle + T identity
  -> Effect::Http(Revoke)
  -> Tick::Inbound(WS post_update/posts_update) 或 authoritative sync
  -> PersistAtomic(MessageRecalled, ChannelPreviewChanged, cursor)
  -> PersistOk
  -> SurfaceComposer
  -> Frame
```

HTTP 2xx 不是撤回完成；权威 WS/sync 才能产生 `Recalled`。

| 提交事实 | 受影响 Surface | V2 Row / VM |
|---|---|---|
| Message content 被撤回 | attached timeline、thread | 同一 message identity 的 `content=Recalled`，不删除后插新行。 |
| 被撤回消息是最新 preview | dialog list | `PreviewVm=Recalled` 与正确排序。 |
| reply/topic 关系受影响 | thread/timeline 条件更新 | relationship availability 变为 recalled/unavailable，不泄露旧正文。 |

`revokeMessage` binding 在 Frame 产生 Recalled 行时撤销；旧 actionRef 的 late invoke fail-closed。

### G04a - 离线撤回重放

离线 sync 带来的撤回使用完全相同的 `MessageRecalled` 事实、PersistOk 和 Frame。不同点只有输入是 `SyncTrigger`，没有用户 ActionBinding。禁止为了离线重放再发 `im:post:deleted` 给客户端。

## 3. G05 - 转发

```text
ActionInvocation(relayMessages, selectedMessageIds, targetChannelIds)
  -> Tick::Command
  -> validate 每个来源可见、每个目标可发送、内容/附件转发 policy
  -> 为每个目标创建独立 PendingSend / temporary Message
  -> PersistAtomic
  -> PersistOk
  -> target channel 的 create effects
  -> 每个 target 的 echo/sync 各自 settle
```

转发是多目标、部分成功可独立的业务操作。不得由客户端拼多目标 HTTP body 或把一个目标的 `Sent` 当所有目标成功。

| 数据 | V2 合同 |
|---|---|
| Row 内容 | `MessageContentVm::Forwarded` 为非递归、有上限、版本化 item union；不可见/嵌套内容显式 `unavailable`。 |
| SurfaceComposer | 每个目标频道独立 impact graph：timeline/dialog/thread（条件）。没有全局“转发完成”业务 Store。 |
| UI | 发起端 overlay 可显示每个 request 状态；最终消息 UI 只依各 target matching Frame。 |

## 4. G06 - reaction

```text
ActionInvocation(toggleReaction@Message M, emoji)
  -> Tick::Command
  -> validate M 可见、emoji policy、viewer identity
  -> Effect::Http(QuickReply)
  -> Tick::Inbound(post_update) / sync
  -> PersistAtomic(MessageReactionState)
  -> PersistOk
  -> Frame
```

`MessageIndicatorsVm.reactions` 是有序、已聚合的 reaction groups，每组包含 count 和 `selectedByViewer`。客户端不能自行加减 count 或根据本地 click 认定最终 selected。

| Surface | Frame 行为 |
|---|---|
| timeline | 目标 `MessageRowVm.indicators.reactions` replace。 |
| thread detail | 若消息在已 attach thread，同一 typed row replace。 |
| dialog/unread | N/A，除非服务端权威事实另有 preview/未读变化。 |

## 5. G07 - 加急与确认

G07 包含“发起加急”和“目标用户确认”的双视角。

```text
UrgentMessage action
  -> Tick::Command -> Http(Urgent) -> WS/sync -> PersistAtomic
  -> PersistOk -> InteractionFrame v2

ConfirmUrgent action
  -> Tick::Command -> Http(Confirm) -> WS/sync -> PersistAtomic
  -> PersistOk -> InteractionFrame v2
```

| 领域事实 | Surface | V2 数据 |
|---|---|---|
| Message urgency summary | timeline/thread | `MessageIndicatorsVm.urgency`，带目标、确认汇总和当前 viewer action。 |
| 当前 viewer 加急待办/未读 | dialog + unread summary | 个人 badge 与 aggregate 必须同帧。 |
| 明细已经打开 | participant receipts | `kind=urgent_confirmation` 的 typed summary/completed/pending rows。 |

不被目标的 viewer 不获得确认 binding，也不能由 receipt count 猜名单。所有成员明细只在 receipts surface attach 后下发。

## 6. 通用失败和 Frame 规则

| 情况 | 规则 |
|---|---|
| ActionRejected | 仅 ActionReceipt/overlay 变化；不伪造成功或失败业务 Row。 |
| HTTP 失败但无权威状态 | 保留原 Frame；若合同要求 retry，由 Helix 下发行级 retry binding。 |
| WS 重复/乱序 | 按权威 entity revision/event identity 幂等，Frame revision 单调。 |
| mutation 基线错误 | PC/Mobile 整帧不提交，slot resync；绝不回退到 raw event。 |

每个 Gate 的 fixture、PC/Mobile apply 和真实验证列见 `09`。
