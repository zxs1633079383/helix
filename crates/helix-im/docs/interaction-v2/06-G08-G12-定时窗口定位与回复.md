# G08-G12 - 定时、窗口、定位与回复

> 状态：终局 V2 合同。窗口、分页、定位、reply tree 的裁决均在 Helix；端侧只报告 viewport/edge/intent，不做业务分页或递归组树。

## 1. G08/G09 - 定时发送与取消

| Gate | owner / 输入 | Tick 与 Effect | PersistOk 后 Frame |
|---|---|---|---|
| G08 创建定时消息 | `message.composer` 的 `message.schedule` capability；输入为 versioned content + scheduledAt。 | validate policy/time -> `PersistAtomic(ScheduledMessage, ChannelScheduleState)` -> `Http(CreateSchedule)` -> authoritative WS/sync。 | dialog + channel summary 的 `hasScheduledMessage`/计划摘要；定时正文不向接收者提前泄露。 |
| G09 取消定时 | 对应 scheduled row/频道摘要 action。 | `Tick::Command` -> `Http(CancelSchedule)` -> WS/sync -> PersistAtomic。 | 同一 schedule VM 消失/状态变更；dialog + summary 同帧回到正确计划状态。 |

到点真正发送时不另造链路，进入 G01/G02/G03 的 create/effect/echo 流程。平台不能用本地 timer 直接把 scheduled row 改成 Sent。

## 2. G10 - 首屏窗口

```text
HostObservation::EnterChannel(C, WindowHint)
  -> summary + composer bundle Frame
  -> Tick::Command(AttachTimeline)
  -> Effect::StorageScan(local first)
  -> optional Effect::Http(GetLatestPost / context)
  -> PersistAtomic(Message window coverage/cursor facts)
  -> PersistOk
  -> timelineSnapshot@Timeline(C, token)
```

`TimelineWindowVm` 是有界完整窗口：anchor、约 60 条有序 `MessageRowVm`、page/hasOlder/hasNewer、firstUnread/target 和 state。它不是全量 MessageStore。

## 3. G10a - 上拉更早历史

```text
HostObservation::TimelineEdgeReached {
  channelId, direction=older, windowToken, visibleAnchorMessageId
}
  -> Tick::Command
  -> validate current timeline epoch/token
  -> local scan or Http(PostContext)
  -> PersistAtomic(new coverage/messages)
  -> PersistOk
  -> timelinePatch(replaceView(next bounded window))
```

客户端只上报边缘和可见锚点；不得直接请求历史 HTTP、拼页、去重或重排。新窗口替换后，旧 timeline actionRefs 因 revision/epoch 按合同失效并由新完整 VM 重新签发；这不影响 channel-scoped composer actionRef。

## 4. G11 - 定位原消息

```text
Action/HostObservation::LocateMessage(targetMessageId)
  -> Tick::Command
  -> local scan or Http(context around target)
  -> PersistAtomic(window facts)
  -> PersistOk
  -> timelineSnapshot/patch(anchor=target)
  -> UiDirective::RevealMessage(target)
```

Frame 先让 target Row 存在，directive 后才滚动/高亮。平台决定动画和像素位置，不决定“哪 60 条属于窗口”。

## 5. G12 - 回复与分支

| 层 | 合同 |
|---|---|
| attach | `HostObservation::OpenThread(channelId, rootMessageId)` -> `AttachThread` Tick。 |
| effect | local scan；不足时 `Http(GetReplies/GetReplyBranch)`。 |
| commit | Message/reply relation/window coverage PersistAtomic。 |
| Frame | `threadDetailSnapshot/patch`，含 root、完整有序 replies、page、detail context。 |
| row | 复用 `MessageRowVmV2`；reply/topic/availability 是 typed relationships，不用 raw reply fields。 |
| UI | PC 可抽屉、Mobile 可页面；都只遍历有序 rows，不递归建树、不按 reqId 猜模式。 |

新回复到达时，若对应 thread 已 attach，thread 与 root timeline 行的 reply summary 在同一 Frame 更新；若未 attach，仅持久化，下一次 OpenThread 给 snapshot。

## 6. Surface impact 规则

| 事实 | 可能受影响 Surface |
|---|---|
| scheduled state changed | dialog、channel summary；必要时 timeline。 |
| timeline coverage/window changed | 仅对应 timeline slot。 |
| target locate | 对应 timeline slot + reveal directive。 |
| reply relation/message changed | attached thread、root 所在 timeline、dialog preview（若最新活动改变）。 |
| channel permission/lifecycle changed | summary + composer；窗口变化本身不影响 composer。 |

所有 Gate 使用完整 replaceView 的有限 VM patch；客户端不会拿单条历史 raw event 去做 splice。
