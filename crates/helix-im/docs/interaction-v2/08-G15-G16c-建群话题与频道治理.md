# G15-G16c - 建群、话题与频道治理

> 状态：终局 V2 合同。频道是领域实体，Dialog、Summary、Topic、Roster 和 Composer 是它在不同 scope 中的独立投影；不能由某个平台组件互相修改。

## 1. G15a - 建群

创建频道不是新增第十个常驻 Surface。它是 `message.left-dialog-list@User` 的稳定 capability：`channel.create`。名称、成员草稿、头像选择器等输入过程是 platform overlay；最终提交的规范化请求才进入 Core。

```text
ActionBinding(channel.create)
  -> Tick::Command(CreateChannel { draft request })
  -> validate creator policy / member set / request idempotency
  -> Effect::Http(CreateChannel)
  -> authoritative channel_created WS/sync fact
  -> PersistAtomic(Channel, ChannelMember, ViewerChannelState)
  -> PersistOk
  -> Frame(dialog snapshot/patch + unread summary as needed)
```

创建者的下一步 `EnterChannel` 走 GS04：先收到同一频道的 `channel-summary + message.composer` bundle，才允许发送；timeline 窗口另行 attach。被邀请成员收到其自身用户 scope 的 dialog/unread Frame，不把创建者的 Frame 复用给其他用户。

## 2. G15 - 创建话题

话题是 Channel 与 root Message 的关系，不是客户端把两条消息临时拼起来。创建动作可以由父频道 summary 或允许的话题 root row 签发 `topic.create` binding；所见的标题/成员编辑仍为端侧输入 overlay。

```text
ActionBinding(topic.create)
  -> Tick::Command(CreateTopic { parentChannelId, rootMessageId, title })
  -> validate root ownership / membership / topic policy
  -> Effect::Http(CreateTopic)
  -> WS/sync Channel + TopicLink + root Message facts
  -> PersistAtomic(Channel, TopicLink, Message relation, Viewer state)
  -> PersistOk
  -> one Frame for affected attached surfaces
```

| 事实变化 | 受影响的已 attach Surface |
|---|---|
| 新话题频道/TopicLink | 父频道 `message.topic-list`、`message.left-dialog-list`、父 `message.channel-summary`。 |
| root Message 获得 topic relation | root 所在 `message.timeline`、已打开的 `message.thread-detail`。 |
| 当前用户加入新话题 | 新频道 `message.channel-summary + message.composer` bundle；timeline 按需 attach。 |
| 成员集/角色变化 | 相应频道 `message.member-roster`，必要时 summary/composer。 |

一条 root message 不会因为话题创建而复制到多份 client store；不同 Surface 自带自己渲染所需的 row/context，来自同一已提交事实集。

## 3. G16 - 关闭频道

`message.channel-summary@Channel` 在权限和 lifecycle 允许时签发 `channel.close`：

```text
ActionBinding(channel.close)
  -> Tick::Command(CloseChannel)
  -> validate authority + current channel epoch
  -> Effect::Http(CloseChannel)
  -> WS/sync Channel.lifecycle=closed
  -> PersistAtomic(Channel lifecycle, affected viewer state)
  -> PersistOk
  -> Frame(summary + dialog + composer + attached timeline/thread/roster/topic)
```

关闭后的 `message.composer` 不再给 create/schedule capability；它给出显式 `availability=disabled(reason=channel_closed)`，而不是让客户端保留旧 `actionRef` 后在点击时才静默失败。已打开的 timeline/thread 仍可按权限展示历史，但不再把关闭频道的旧发送 binding 当有效。

## 4. G16b - 退出频道

退出动作也由 channel summary 的 `channel.leave` binding 进入。authoritative member 事实提交后，当前用户的 Frame 必须一起处理其所有已 attach 的该频道 Surface：

1. 从 `message.left-dialog-list` 移除或转为不可访问的频道行，按产品策略决定；
2. 更新 `message.unread-summary` 聚合；
3. `message.channel-summary`、`message.member-roster`、`message.topic-list` 给出最终不可访问/卸载状态；
4. `message.composer` 移除 capability，失效其 epoch；
5. `message.timeline`、`message.thread-detail` 在当前 Frame 中变为 detached/unavailable，并以 directive 让平台关闭对应页面或返回上层。

这使“退出后还拿着旧编辑器发送”成为不可表示状态，而不是依赖 UI 端四处 if 判断。

## 5. G16c - 频道资料和成员治理更新

频道资料、权限、成员角色、头像、topic 资料等都遵循同一个不是 raw emit 的链路：

```text
ActionBinding(channel.update | member.update | topic.update)
  -> Tick::Command(...)
  -> validate actor capability + entity revision
  -> Effect::Http(...)
  -> authoritative WS/sync fact
  -> PersistAtomic(Channel / ChannelMember / TopicLink / Viewer policy)
  -> PersistOk
  -> SurfaceComposer impact policy
  -> InteractionFrame v2
```

| 改动类型 | 必要或可能的 Surface mutation |
|---|---|
| 标题、头像、描述、lifecycle | dialog row、channel summary、topic list row。 |
| 当前用户的 role/policy | channel summary、member roster、composer capabilities；必要时 timeline/thread 行级动作刷新。 |
| 他人的 role/member list | member roster；若影响 preview/展示名，再影响 dialog/timeline/thread 的完整 row。 |
| topic metadata / relation | topic list、关联 root 的 timeline/thread、必要时 dialog preview。 |

更新动作不修改 `MessageComposerVm` 的结构。权限变化仅改变其稳定 capability catalog 中某个 capability 是否存在/可用，以及对应 ActionBinding/epoch。

## 6. 原子性、失败和 PC/Mobile

- 一个已提交的 Channel lifecycle 或当前用户 membership 改变不能拆成“先删 dialog、过一秒再禁 composer”。所有已 attach 的受影响 Surface 由一次 `PersistOk -> InteractionFrame` 原子替换。
- 若远端拒绝、冲突或缺少权限，Core 不提交推测性的 Channel/Member 状态；平台保留上一个 Frame，并把请求 scoped 的失败提示作为 UI directive/overlay outcome。
- PC 可以在侧栏弹出建群对话框、Mobile 可以推入建群页；两端最终都提交相同 input contract，消费同一 Frame 语义。
- 因 sync 恢复得到频道事实时，GS03/GS04 只重组实际 attach 的 Surface；未打开频道不需要偷偷渲染，但下次进入必须得到完整的 `summary + composer` bundle。

本章的治理行为不进入 `helix-core`：Core 只调度 Command/Effect 和 port；Channel、Member、Topic 语义、影响面和 projector 都归 `helix-im`。
