# G04-G07 撤回、转发、回应与加急完整时序和数据

> 对应上级分册 `05-G04-G07-消息变更转发回应与加急.md`。本页固定 Go wire、权威回声、
> Helix 持久化屏障和完整 Frame 变化。除 `viewReceipt` 外，ActionBinding 到 command 的 live
> SurfaceRuntime dispatch 当前仍是 `GAP`。

## 1. Gate 与 Go 接口总表

| Gate | Helix canonical command | Go endpoint | Go `SUCCESS` data | 权威异步事实 |
|---|---|---|---|---|
| G04 撤回 | `im_revoke` | `POST /api/cses/posts/revoke` | 无；message=`revoke post success` | `posts_update`，并可能有 `update_channel` preview。 |
| G04a 离线撤回 | 无用户 HTTP | `/channel/sync/notify` 或现有 sync path | sync data | type=3 revoke event / canonical post。 |
| G05 转发 | `im_create_posts` | `POST /api/cses/posts/createPosts` | `CreatePostsResult` | 每个 accepted target 的 `post`/`posts_update`。 |
| G06 reaction | `im_quick_reply` | `POST /api/cses/posts/quickReply` | 无；message=`post sender success` | `post_update`。 |
| G07 加急 | `im_urgent_post` | `POST /api/cses/posts/urgentPost` | 无；message=`set urgent post success` | `post_update` + 每 viewer 的 `update_channel`。 |
| G07 确认 | `im_urgent_confirm` | `POST /api/cses/posts/urgentConfirm` | 无；message=`confirm urgent post success` | `post_update`。 |
| G07 取消 | `im_urgent_cancel` | `POST /api/cses/posts/urgentCancel` | 无；message=`cancel urgent post success` | `post_update`/viewer increment。 |

所有 endpoint 都返回公共 `CommonRes`；HTTP 200 或 `SUCCESS` 均不直接生成终态 Frame。

## 2. G04 撤回

### 2.1 上行、Go 请求与响应

目标 action owner 是 timeline/thread 中目标 `MessageVm.actions[]`：

```jsonc
{
  "kind": "revokeMessage",
  "actionRef": "opaque",
  "inputShape": "im.message-revoke.v1",
  "surfaceEpoch": 3,
  "enabled": true
}
```

renderer invoke 不再提交 `postId`；Helix 从 binding 固定的 message identity 生成当前 outbound：

```json
{ "postId": "M" }
```

Go 成功回包：

```json
{ "status": "SUCCESS", "message": "revoke post success" }
```

### 2.2 完整时序

| 次序 | 输入/Effect | 领域处理 | 输出 |
|---|---|---|---|
| G04-0 | invoke `revokeMessage` | 校验作者/角色、生命周期、message 可见性、action lease。 | accepted receipt；`Http(posts/revoke)`。 |
| G04-1 | Go `SUCCESS` | 只记录 request accepted；原消息仍保持当前 Frame。 | 无业务 mutation。 |
| G04-2 | `posts_update` / sync type=3 | 归一 `MessageRecalled{messageId,channelId,actor,eventTime,eventId}`；若是 preview，再计算 canonical preview。 | `PersistAtomic(message + channel preview + cursor/eventSeq)`。 |
| G04-3 | `PersistOk` | 作废该行旧动作，compose 已 attach slots。 | matching-causation Frame。 |

G04a 只跳过 G04-0/G04-1；离线 type=3 仍必须进入 G04-2/G04-3，不走 `im:post:deleted` renderer reducer。

### 2.3 Persist 写集与 Frame 数据

```text
Message(M):
  content = Recalled { text }
  delivery = Recalled
  canonical update/event revision
  revoke actor/time metadata（领域事实，按 VM 可见性投影）

Channel(C):
  preview = Recalled(...)              // 仅 M 是当前 preview 时
  lastActivity/order = canonical value // 不用客户端当前时间
Cursor/EventLedger:
  eventId/eventSeq applied once
```

Frame 至少替换：

- `timeline@C/W.items[M]`：完整 `MessageVm`，`content.kind="recalled"`、`delivery.kind="recalled"`，
  `actions` 不再含 revoke；
- `thread@C/root`：仅当 M 在已 attach thread；
- `dialog@viewer`：仅当服务端权威 preview 受影响，`preview.kind="recalled"`；
- 不改变 unread，除非同一个 Go authoritative fact 明确带来 viewer unread 变化。

接收者只消费自己的 WS/sync、自己的 PersistOk 和自己的 Frame；发送者的 accepted receipt 不跨 session。

## 3. G05 多目标转发

### 3.1 canonical 输入与 Go wire

目标 V2 输入只提交来源 ids 与目标 channel ids：

```json
{
  "postIds": ["M1", "M2"],
  "targetChannelIds": ["C2", "C3"]
}
```

当前 Go 同时兼容旧 `posts[] + channelIds[]` 和新的 `postIds[] + targetChannelIds[]`。V2 应优先由
Helix/Go 用 ids 加载 canonical source，避免 renderer 携带整条 Post。Go wire：

```json
{
  "postIds": ["M1", "M2"],
  "targetChannelIds": ["C2", "C3"]
}
```

Go `data` 是逐目标接受结果，而不是最终 Sent：

```json
{
  "status": "SUCCESS",
  "message": "post sender success",
  "data": {
    "status": "success | partial | failed",
    "acceptedCount": 1,
    "failedCount": 1,
    "targets": [
      { "channelId": "C2", "status": "accepted" },
      { "channelId": "C3", "status": "failed", "error": "..." }
    ]
  }
}
```

外层失败时为 `status="failed"`、message=`all post targets failed`。内层 target `accepted` 仅表示
同步落库或队列接收，终态仍看逐目标 WS。

### 3.2 完整时序与局部成功

```text
relayMessages binding + selection overlay
  -> validate every source visibility + every target membership/capability
  -> Http(createPosts with ids)
  -> CommonRes/CreatePostsResult
  -> for each failed target: request-scoped outcome, no Sent Frame
  -> for each accepted target: wait canonical post WS/sync
  -> PersistAtomic(target message + identity + channel preview + cursor)
  -> PersistOk
  -> target-specific InteractionFrame
```

每个 target 是独立 causation branch。`C2` 的 echo 不能关闭 `C3` 的 pending，任何一个 target 的
`Sent` 也不能把外层操作显示成全部完成。

### 3.3 Frame 数据

目标消息的完整 `MessageVm`：

```jsonc
{
  "id": "server-forward-id",
  "channelId": "C2",
  "author": { "userId": "actor" },
  "createdAt": 1780000000000,
  "content": {
    "kind": "forwarded",
    "summary": "2 messages",
    "items": ["bounded render-ready item data"]
  },
  "delivery": { "kind": "sent" },
  "actions": [],
  "replySummary": null,
  "readReceipt": null,
  "pinned": false,
  "bookmarked": false
}
```

每 target Frame 更新该 target 已 attach timeline、dialog preview、条件 thread。未 attach target
不强行创建 UI slot；事实先持久化，下次 attach 返回 snapshot。`Forwarded.items` 有界、非递归，
不可见 source 必须投影为 unavailable 摘要，不能泄露原文。

## 4. G06 emoji reaction

### 4.1 Go 对齐

当前 Helix outbound 严格接收 `post_id/emoji/req_id?`，Go actor 优先取 session：

```json
{ "postId": "M", "emoji": "thumbs_up" }
```

成功：

```json
{ "status": "SUCCESS", "message": "post sender success" }
```

权威 `post_update.data` 是更新后的 canonical Post，而不是 `delta=+1`。

### 4.2 时序与 Frame

```text
toggleReaction binding
  -> validate post visibility + emoji policy + viewer
  -> Http(posts/quickReply)
  -> SUCCESS (no UI change)
  -> post_update/sync canonical reaction state
  -> PersistAtomic(MessageReactionState + post revision + cursor)
  -> PersistOk
  -> timeline/thread replaceView Frame
```

`MessageVm` 当前没有独立 `reactions` 字段；若沿用现有 wire，只能把有序聚合放入有界
`SurfaceDataVm`（例如 `replySummary` 的明确子合同），这是 `GAP`。更稳妥的终局是为
`MessageVm` 增加版本化 typed reaction 字段。无论采用哪种方式，Frame 数据必须是权威 groups：

```json
[
  { "emoji": "thumbs_up", "count": 3, "selectedByViewer": true }
]
```

PC/Mobile 不得本地 `count += 1` 或反转 selected；重复 `post_update` 不推进 Frame revision。

## 5. G07 加急、确认与取消

### 5.1 Go 请求/响应

发起加急：

```json
{ "postId": "M", "targetIds": ["U2", "U3"], "message": "optional" }
```

确认/取消当前 Helix wire 都只传 postId；Go handler 也兼容 `channelId`，application 以 post
权威解析 channel：

```json
{ "postId": "M" }
```

响应分别为：

```jsonc
{ "status": "SUCCESS", "message": "set urgent post success" }
{ "status": "SUCCESS", "message": "confirm urgent post success" }
{ "status": "SUCCESS", "message": "cancel urgent post success" }
```

### 5.2 双视角完整时序

| 阶段 | 发起者 | 目标用户 |
|---|---|---|
| command | 校验可加急与 targets，发 `urgentPost`。 | 只有收到权威 urgent fact 后才获得 confirm binding。 |
| Go | 更新 post urgency，并发布 `post_update`；为各 viewer 发布 `update_channel` increment。 | 相同事件按 viewer audience 过滤。 |
| Helix persist | 保存 urgency targets/confirmed/pending + viewer channel aggregate。 | 保存自己的 pending badge 与当前可执行动作。 |
| Frame | timeline/thread urgency summary；必要时 dialog/unread。 | timeline/thread + dialog/unread；receipt detail 已 attach 时同步。 |
| confirm | 不本地推断对方已确认。 | `urgentConfirm` -> WS -> PersistOk -> matching Frame。 |

取消同样等待权威 post/update_channel；不得收到 HTTP SUCCESS 就删除所有 viewer 的 pending。

### 5.3 Frame 数据与原子影响面

`MessageVm.urgency` 当前为 `SurfaceDataVm`，目标子合同至少包含：

```json
{
  "state": "active | canceled | completed",
  "targetCount": 2,
  "confirmedCount": 1,
  "pendingCount": 1,
  "selectedByViewer": true,
  "canConfirm": true
}
```

同一次 viewer `PersistOk` 的 Frame：

- timeline/thread：完整 message row 的 `urgency` 与 actions；
- dialog：该频道完整 row 的 `urgentCount`；
- unread summary：完整聚合 `urgentTotal`；
- participant receipts（已 attach，kind=`urgentConfirmation`）：完整 completed/pending rows。

不在 target audience 的用户不能得到 target ids、confirm binding 或明细。receipt detail 的成员列表
不能塞入 timeline row。Frame apply 失败时整笔不提交并请求对应 slot snapshot。

## 6. 失败与幂等

| 情况 | 正确结果 |
|---|---|
| actionRef stale/actor mismatch | rejected receipt；无 HTTP、无业务 Frame。 |
| Go `status=failed` | request-scoped failure；保留上一版业务 VM。 |
| HTTP 超时但 WS 已到 | 以权威 WS + PersistOk 为准；request ledger 等 matching terminal Frame。 |
| duplicate/late WS | event identity/entity revision 去重，不重复转发、不重复 reaction、不重复加急计数。 |
| multi-target partial | 每 target 独立完成；外层不伪造 all-success。 |
| baseRevision gap | PC/Mobile 整帧拒绝并 resync，不消费 raw event 修补。 |
