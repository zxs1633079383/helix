# G15-G16c 建群、话题与频道治理完整时序和数据

> 对应上级分册 `08-G15-G16c-建群话题与频道治理.md`。Go 的 channel/post handler 只做协议映射，
> DB、channel_event/eventSeq、WS、Helix Persist 和 Frame 必须分别成立；HTTP data 不能跨过这些边界。

## 1. Gate 与 Go 接口总表

| Gate | Go endpoint | `SUCCESS.data` | 权威 WS/sync |
|---|---|---|---|
| G15a 建群 | `/channel/create` | canonical Channel | `channel_created`/`channel_member_update`/viewer `update_channel`，direct 有差异。 |
| G15 创建话题 | `/posts/makeTopic` | `{rootMessageId,channelId,revision}` | `post_update(source=make_topic)` + channel/member facts。 |
| G16 关闭 | `/channel/close` | 无 | `channel_close`。 |
| G16b 退出 | `/channel/member/leave` | 无 | `channel_member_update` + system post；群主可带 newCreator。 |
| G16c 成员增减 | `/channel/member/change` | 无 | per-viewer `channel_member_update` + system post/topic update。 |
| G16c 资料/权限 | `/channel/change/*`、`/channels/enableApproval` | 部分接口返回 settings projection | `update_channel`/notice/approval/role/nickname events。 |

## 2. G15a 建群

### 2.1 canonical 请求与 Go 派生

普通客户端唯一 canonical body：

```json
{
  "type": "OPEN | PRIVATE | DIRECT | TOPIC",
  "userIds": ["U2", "U3"],
  "displayName": "Project Room",
  "forceCreate": false
}
```

客户端不能提交 owner/team/roles/default picture。Go 从 session 派生 creator、team、成员角色和最多
9 个 userIds 的 USER picture；DIRECT 最终成员数必须为 2。`createSpecifyOwner` 是管理入口，不是
G15a 普通客户端能力。

Go 成功：

```jsonc
{
  "status": "SUCCESS",
  "data": {
    "id": "NEW-C",
    "type": "<canonical channel type>",
    "displayName": "Project Room",
    "teamId": "T",
    "pictureType": "USER",
    "picture": { "userIds": ["creator", "U2", "U3"] },
    "createAt": 1780000000000,
    "updateAt": 1780000000000
  }
}
```

`data` 实际序列化完整 Channel，字段多于示例。Helix 只能挑选领域所需字段，不把 ent row 作为 VM。

### 2.2 完整时序

```text
dialog@User channel.create binding
  -> validate type/member set/name/idempotency
  -> Http(channel/create canonical body)
  -> CommonRes SUCCESS + Channel data          // id hint, not UI completion
  -> Go co-tx Channel + members + member-order snapshot + channel_event
  -> WS channel_created/channel_member_update/update_channel or sync
  -> Helix reconcile returned id with authoritative event
  -> PersistAtomic(Channel + ChannelMember + ViewerChannelState + cursor/eventSeq)
  -> PersistOk
  -> creator dialog/unread Frame
```

创建者随后 `EnterChannel(NEW-C)`，由已持久化事实产生同一 transaction 的 summary + composer bundle；
timeline 另行 attach。被邀请用户只接收自己的 WS/sync、PersistOk 和 user-scope Frame。

### 2.3 Frame 数据

创建者 dialog 新 row 必须是完整 `DialogRowVm`：

```jsonc
{
  "channelId": "NEW-C",
  "channelKind": "group",
  "title": { "text": "Project Room" },
  "avatar": { "resource": null, "fallbackText": "PR" },
  "preview": { "kind": "empty" },
  "lastActivityAt": 1780000000000,
  "unreadCount": 0,
  "mentionCount": 0,
  "urgentCount": 0,
  "topicCount": 0,
  "hasScheduledMessage": false,
  "isTop": false,
  "notificationMode": "all",
  "lifecycle": { "state": "active" },
  "actions": []
}
```

进入频道 bundle：

- `ChannelSummaryVm`：canonical title/avatar/lifecycle/memberCount/topicCount/notificationMode/settingsVersion/actions；
- `ComposerVm`：`state=ready`、draftPolicy、允许的 create/schedule actions、capabilityEpoch；
- 只有 membership/policy 已 PersistOk 才能签发发送能力。

## 3. G15 创建话题

### 3.1 Go wire 与同步回包

当前 canonical body 不允许 renderer 提交 parent channel、team、type、display name 或 role：

```json
{ "rootId": "ROOT-M", "userIds": ["U2", "U3"] }
```

可选 `picture` 只允许显式非空 custom picture；默认图由服务端派生。成功 data 是稳定 projection：

```json
{
  "status": "SUCCESS",
  "data": {
    "rootMessageId": "ROOT-M",
    "channelId": "TOPIC-C",
    "revision": 1780000000000
  }
}
```

Go 返回 nil result 时是 `status=failed,message="makeTopic is already in progress"`。同步 data 只用于
request correlation；最终 UI 等 `post_update(source=make_topic)`、channel/member 事实和 PersistOk。

### 3.2 完整时序与原子事实

```text
topic.create binding at root/summary
  -> validate root visibility + policy + selected members
  -> Http(posts/makeTopic)
  -> SUCCESS data(root,topicChannel,revision)
  -> authoritative post_update + channel/member events/sync
  -> PersistAtomic(
       topic Channel,
       TopicLink(parent,root,topicChannel),
       root Message relation,
       members + viewer states,
       cursors/eventSeq)
  -> PersistOk
  -> one Frame for all affected attached slots
```

### 3.3 完整 Frame 影响面

| Surface | 完整变化 |
|---|---|
| topic-list@parent | 新完整 `TopicRowVm`：topicChannelId/root/title/preview/activity/messageCount/avatar/lifecycle/actions。 |
| timeline/thread@root | 完整 MessageVm 的 `topicLink` 与 actions。 |
| channel-summary@parent | topicCount/settingsVersion/action 变化。 |
| dialog@viewer | topic row 是否出现按产品可见性；不得从 HTTP data 直接插入。 |
| summary+composer@topic | 仅已经 attach/进入的新 topic scope；membership PersistOk 后签 capability。 |
| roster@topic | 已 attach 时完整成员页。 |

`TopicListVm.topicCount >= visible items`，topic ids 唯一，page.windowToken 必须等于 scope cursor。

## 4. G16 关闭频道

请求与成功响应：

```jsonc
{ "channelId": "C" }
{ "status": "SUCCESS" }
```

完整链：`channel.close binding -> Http -> SUCCESS -> WS channel_close{channelId,deleteAt} / sync ->
PersistAtomic(lifecycle=closed + viewer/channel indexes) -> PersistOk -> atomic Frame`。

同一 Frame 的已 attach slots：

- summary.lifecycle=`closed`，刷新 settingsVersion/actions；
- composer.state 不再 ready 或 actions 全 disabled/移除，capabilityEpoch 前进；
- dialog row 进入 closed section/按产品策略保留；
- timeline/thread 保留有权限的历史，但撤销 create/revoke/governance 等不再合法动作；
- roster/topic 根据 closed policy 仍可读或变 forbidden。

旧 composer actionRef 必须在 commit 时撤销；HTTP SUCCESS 到 channel_close 之间不能提前禁用后又因失败回滚。

## 5. G16b 当前用户退出频道

### 5.1 Go wire

普通成员：

```json
{ "channelId": "C" }
```

群主退出并转让：

```json
{
  "channelId": "C",
  "newCreator": { "id": "U2", "teamId": "T", "role": "CREATOR" }
}
```

Go 强制 `userId=session.UserId`，body 中 userId 不能让用户退出别人。成功：

```json
{ "status": "SUCCESS", "message": "channelMemberLeave success" }
```

### 5.2 完整时序与 Frame

```text
channel.leave binding
  -> validate current membership + owner transfer rule
  -> Http(channel/member/leave)
  -> SUCCESS (keep access)
  -> channel_member_update + system post / sync
  -> PersistAtomic(self membership=left + optional new owner + viewer indexes + cursor)
  -> PersistOk
  -> one terminal multi-surface Frame
```

当前用户 Frame 必须同时：从 dialog 移除/转 unavailable；重算 unread aggregate；summary/roster/topic
变 forbidden/unavailable；composer capabilityEpoch 前进且无 enabled actions；timeline/thread 变 unavailable；
必要时发无 payload的 navigation directive。平台只能在 Frame apply 后关闭页面。

其他成员收到自己的 roster/summary/system-message Frame；不能复用退出者的 forbidden Frame。

## 6. G16c 频道资料、成员和权限治理

### 6.1 当前 Go wire 目录

| Helix command | endpoint | canonical body | Go response/WS |
|---|---|---|---|
| `im_channel_change_info` | `/channel/change/info` | `{channelId, displayName?,picture?,pictureType?,header?,purpose?,orient?,module?,source?,expectedVersion?}` | data=`{channelId,purpose,header,settingVersion,...}`；`update_channel`。 |
| `im_channel_change_display_name` | `/channel/change/displayName` | `{id,displayName}` | data=settings projection；`update_channel`/system post。 |
| `im_channel_change_picture` | `/channel/change/picture` | `{id,pictureType,picture}` | 无 data；`update_channel`。 |
| `im_channel_change_notice` | `/channel/change/notice` | `{id,notice}` | data=settings projection；`update_channel_notice`。 |
| `im_channel_change_purpose` | `/channel/change/purpose` | `{id,purpose}` | 无 data；`update_channel`/system post。 |
| `im_channel_change_orient` | `/channel/change/orient` | `{id,orient}` | 无 data；`update_channel`/system post。 |
| `im_channel_change_permission` | `/channel/change/permission` | `{channelId,mentionPermission,noticePermission,topPermission}` | 无 data；`update_channel`/system post。 |
| `im_channel_member_change` | `/channel/member/change` | `{channelId,joinUsers?,leaveUsers?}` | message success；per-viewer `channel_member_update`。 |
| `im_channel_member_role` | `/channel/member/change/role` | `{channelId,userIds,role}` | 无 data；`channel_member_role_updated`。 |
| `im_update_member_nickname` | `/channel/member/change/nickname` | `{channelId,nickname}` | 无 data；`update_channel_member_nickName`。 |
| `im_channel_member_notify` | `/channel/member/change/notify` | `{channelId,notify∈NORMAL\|STRONG\|IGNORE}` | 无 data；viewer-only `update_channel`，event data 的 id 是 channel id。 |
| `im_channel_enable_approval` | `/channels/enableApproval` | `{channelId,approvalStatus}` | message success；`change_channel_approval`。 |

`change/info.expectedVersion` 触发 CAS。冲突仍是 HTTP 200，但信封为：

```json
{
  "status": "failed",
  "message": "<version conflict>",
  "data": {
    "code": "CHANNEL_SETTINGS_VERSION_CONFLICT",
    "expectedVersion": 7,
    "currentVersion": 8
  }
}
```

冲突不能覆盖本地 Frame；Helix 应请求/等待当前 authoritative settings，再给更新后的 summary snapshot/patch。

### 6.2 统一时序

```text
row/summary/roster ActionBinding
  -> bind entity id + actor + observed settings/entity revision
  -> normalize typed governance input
  -> Http(exact endpoint/body above)
  -> CommonRes SUCCESS or version conflict
  -> authoritative typed WS/sync
  -> PersistAtomic(Channel/Member/TopicLink/ViewerPolicy + eventSeq/cursor)
  -> PersistOk
  -> Surface impact policy
  -> InteractionFrame v2
```

Go `change/info` 返回的 settings projection 可以帮助关联/校验，但 mutation 的多人最终可见态仍要由
广播/sync 事实收敛。viewer-only top/notify 只影响本人 Frame。

### 6.3 改动到 Frame 的精确映射

| 已提交事实 | Frame 变化 |
|---|---|
| title/picture | dialog row、channel summary、父 topic row；包含该 channel 展示引用的已 attach row 按策略替换。 |
| purpose/header/notice | channel summary 的 purpose/noticeSummary/settingsVersion。 |
| lifecycle | summary + composer + dialog +所有当前可访问性受影响 slots。 |
| self role/policy | summary actions、composer actions/capabilityEpoch、roster self row；必要时 timeline/thread row actions。 |
| other member join/leave/role/nickname | roster 完整页与 memberCount；展示名影响已显示 message row 时替换那些完整 rows。 |
| notification mode/top | 本人 dialog row/section + summary notificationMode；不广播到其他 viewer VM。 |
| topic metadata | topic row、topic summary、root message topicLink；必要时 dialog preview。 |

`MemberRosterVm` 分页时只更新当前已 attach cursor 的完整页；memberCount 是全量权威数。角色变更不能
在 UI 对单行就地改枚举而不同步 summary/composer actions。

## 7. Go 特殊差异与禁止推断

- DIRECT create 当前可能不发普通 `channel_created`，而走成员/增量路径；Helix 必须按 viewer 的
  authoritative channel/member fact 归一，不能把某个 event 名写死为唯一完成信号。
- add/remove `manger` 路由拼写是当前 wire 事实；但 G16c 应优先统一到 member role 领域意图，
  不把 endpoint 拼写暴露给 renderer。
- `channel/change/props` 当前没有一致 WS 对账，不能当作 Frame 终态写链；必须补 authoritative
  event/sync 或显式作为非 V2 能力。
- `SUCCESS.data.channelId` 不是 membership/visibility 完成证据；没有对应 viewer PersistOk 就不能插 dialog。
- channel event、member snapshot 与 eventSeq 的一致性必须由 Go/Helix 真实链证明，本文不以 handler 注释替代。

## 8. 失败、原子性与复杂度

| 情况 | 正确结果 |
|---|---|
| permission denied/version conflict | request outcome + authoritative refresh；不提交推测性资料。 |
| HTTP success, WS absent | 保留上一业务 Frame，诊断 pending/timeout。 |
| member event gap | GS03/GS04 recovery；不局部修改 roster。 |
| leave/close frame partial apply | 整帧拒绝；不能出现 dialog 已删但 composer 仍 enabled。 |
| duplicate create/topic | 以 idempotency/root relation/entity revision 去重，只保留一条 channel/topic。 |

成员集合用 `Map<userId,Member>`、topic 用 `Map<topicChannelId,TopicLink>`、dialog 用 channel index；
单事件更新 `O(log n)`/`O(1)`，有界 Frame compose `O(affected visible rows)`。禁止每次 role 更新扫描
所有 channel、所有 message 和所有 surface 的笛卡尔积。
