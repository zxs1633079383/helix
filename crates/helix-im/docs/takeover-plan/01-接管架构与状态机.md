## 01 — 接管架构与状态机

### 1. helix 替换 `src-tauri/features/im` 的架构

helix 以 **三层 + 单 driver-native 壳** 整目录替换现网 `src-tauri/src/features/im`：

```
Angular message-v3 service 层（退化为纯 dispatch + render）
  src/pages/message-v3/service/*   ← 路径真源（非 src/app/pages，rv-tauri A3 修正）
   │ ① 语义 invoke 命令（im_send_message / im_send_urgent_post / im_quick_reply / im_switch_active_channel
   │    / ensure_channel_loaded / im_load_older_messages / im_sync_channels / im_query_messages_by_channel ...）
   │ ② listen 单总线 "im:__bus__"
   ▼
helix-driver-native（Tauri 壳）   ← 替换现网 commands.rs/router.rs/event_bus.rs/im_ws_client.rs/app-http.service 横切
   ├ #[tauri::command] 薄壳 → Tick::Command / Tick::Inbound
   ├ NativeEventSink → app.emit("im:__bus__", env)                      【M2 接缝①】
   ├ NativeTransport(SharedWsClient) → WS 收发                          【M2 接缝②】
   ├ reqwest HttpManager("im" 实例) → Effect::Http/HttpFire             【M2 接缝③ + P1.5 横切层落点】
   │     运行时注入：connectionId 头 / 鉴权头(session|Bearer mp_) / traceparent 出站透传
   │     失败码回报：401 → emit im:http:unauthorized；断网 → emit im:net:offline
   └ rusqlite via driver-host → Effect::Persist                        【M2 接缝④投影命令 store_get_messages】
   ▼
helix-im（core 纯状态机：handle(Tick)→Vec<Effect>）   ← 全部业务编排在此
   ├ acl/from_tick → 入站语义
   ├ channel gate（cursor 单调，HX-C008/C009）
   ├ outbound registry（linkme distributed_slice，C4 重构后）
   ├ commands::handle_outbound（语义命令 → camelCase Go body 拼装）
   └ acl/to_effect → Effect 生产（时间经 Clock、id 经 IdSource，C3）
   ▼
helix-core ports（Transport / Storage / Clock / IdSource / EventSink）
```

**依赖铁律**（HX-C001）：`helix-core` 永不 import tokio/sqlx/reqwest/web-sys/tauri；`cargo tree -p helix-core | grep -iE 'tokio|sqlx|reqwest|web-sys|tauri'` 必须空。鉴权 token 注入（含 `Bearer mp_`）留 driver，`grep 'mp_' crates/helix-im/src` 必须空（C6）。

### 2. 前端退化原则（纯渲染证伪标准，C1/C2）

前端**不再**：发 HTTP、算 unread/lastPost/readBits/cursor、维护第二套 sync 状态机、拼 wire body。前端**只做**：① 语义 invoke（参数 = UI 表单字段，**不含任何 wire-only key** 如 `viewers`/`teamId`/`userSnapshot`）② listen `im:__bus__` → `CoreEventManager.dispatch` → 渲染。

**证伪判据**（写进 gate）：
- C1：grep 前端 invoke 参数集不得出现 wire 字段名。否决凭空发明的泛型 `im_outbound{name,args}`（name/args 形态本身即业务知识）——每个用户意图给**独立语义命令**。
- C2：**冻结投影 payload schema** 为真源 `crates/helix-im/docs/projection-schema.md`（DialogItem 全字段 + messages 投影行全字段），测试断言 emit 的 DialogItem 字段集 == cses-client `DialogItem` interface 字段集；字段不齐 = 前端会补算 = 纯渲染破功。

### 3. IPC 表面兼容决策（拆两表，rv-tauri A2 收口）

**表 A — 渲染层零改**（信封 + 投影，byte-exact 保留）：

| IPC 面 | 决策 | 理由 |
|---|---|---|
| 单总线 `im:__bus__` 信封 `{channel,payload,tracing?}` | **原样保留**（已是最优 N→1，三审一致认可）| 省 ~190ms 启动；信封带 OTel；`to_bus_envelope` 已产此形 |
| `im:post:received` / `im:channel:update` / `im:sync:too_long` 等事件 | 保留 channel 名 | CoreEventManager dispatch 不变 |
| 投影命令 `im_query_messages_by_channel`（复用现网 `store_get_messages` 语义 + 分页 beforeId/afterId/beforeTimestamp/afterTimestamp）| 替 `imDataSource:*` 拦截垫片 | A4：现网已是 SQLite 直查垫片，非新造 |

**表 B — service 层重写**（出站/写收归 Rust，前端 service 改 invoke，**非零改**）：

| IPC 面 | 决策 | 理由 |
|---|---|---|
| ~60 HTTP 出站 | **全下沉 Rust 语义命令** + driver 横切层（鉴权/401/断网/trace）| A1：现网出站在浏览器 Angular interceptor，是**重建**非搬运 |
| `store:* updateItem channel {unread...}` 主动写 | **收归 Rust** 经字段级 `BatchUpdate WHERE PK` 推完整 DialogItem | 业务下沉铁律 + B5 禁 RMW |
| `im_get_state` / `im_delete_all_dialogs` | **补入兼容表**（现网 boot.rs 已注册，rv-tauri B1 漏项）| 漏则前端报 command not found |
| `IMWS:reconnect`（连接控制）| 保留命令名，driver 触发 reconnect | rv-tauri B5 连接生命周期归属 |

**store: 写权归属矩阵**（rv-tauri B2）：所有 message/channel 写收归 Rust（乐观落库 + WS 对账均由 helix-im 出 `Effect::Persist`）；前端**删除全部 `store:setItem/updateItem` 写点**避免与 Rust 双写同 PK 冲突；前端仅保留 `store:`/投影命令的**读**（经 `im_query_messages_by_channel`）。

### 4. 数据流全景（发消息为例，含 Clock/IdSource 注入）

```
前端 invoke("im_send_message",{action:"post", data(UI字段), seq})
  → driver command → Tick::Command{name, args}
  → ImModule::handle → handle_send_message:
       tmp_id = IdSource::next_id()             ← C3 禁 helix-im 自生成
       createAt = Clock::now_ms()               ← C3 禁 ambient now
       乐观落库 Effect::Persist(corr, PK=temporaryId) + PendingSend 登记(connectionId 维度, M1)
       outbound build（viewers 空补['all'] / 回复 root / userSnapshot 注入 / 文本截断2000 / 空消息 trim 拦截）
       Effect::Http(corr, POST /api/cses/posts/create, body=camelCase 全字段, header 鉴权意图)
       Effect::ScheduleTimer(15s send-timeout)
  → driver 批量解释 Vec<Effect>（HX-C007）：Persist→rusqlite ; Http→reqwest(注鉴权头+traceparent)→200/401
  → 服务端 Pulsar 异步 → WS 帧 action="post"（顶层 event_seq）
  → driver Inbound(bytes) → Tick::Inbound → parser → ws::dispatch "post"
       reconcile_post_echo(tmp_id→server_id, CancelTimer)  ← 锚 action=="post" 非 posted(B3)
       gate.on_ws_event(k==cursor+1 flush_contiguous，commit_target=max(nextSeq,末条)  ← B6)
       Effect::Persist(覆写 server_id) + Effect::Emit(to_bus_envelope "im:post:received")
  → driver NativeEventSink → app.emit("im:__bus__",{channel:"im:post:received",payload})
  → 前端 ImEventBusDispatcher → CoreEventManager.dispatch(POST) → 渲染
```

文件上传（M2）：multipart 大二进制**不进 core**，前端→driver 直传拿 fileId → invoke `im_send_message{file_ids}`（纯渲染合理例外）。

### 5. 接管全流程状态机（四正交子机 + 新增 SyncScheduler）

```mermaid
stateDiagram-v2
  %% ===== 连接子机 =====
  state Conn {
    [*] --> Disconnected
    Disconnected --> Connecting: driver WsManager dial
    Connecting --> Connected: WS open (Tick::Connected)
    Connected --> Helloed: 收 hello 帧(盖 connectionId→回注 driver HttpManager header, M3)
    Helloed --> Disconnected: Tick::Disconnected / 心跳半死
    Connecting --> Disconnected: 退避重连
    Helloed --> Helloed: ping(8s self-arm) / pong gap 补偿
  }

  %% ===== SyncScheduler 全局并发窗口子机（B4 新增，接管本质差异）=====
  state SyncScheduler {
    [*] --> Idle
    Idle --> Draining: hello 后批量 / 多 channel needSync 入队 pending_sync VecDeque
    Draining --> Draining: 在途 < K → 取队首 dispatch Effect::Http(sync/notify)
    Draining --> Throttled: 在途 == K(全局上限) → 后续 channel 排队不齐发
    Throttled --> Draining: 一个 sync 回报 → 释放 1 个窗口
    Draining --> Idle: 队空
  }

  %% ===== 同步子机(per-channel gate，受 SyncScheduler 限流)=====
  state SyncChannel {
    [*] --> Seeded: register_channel(cursor=0/scan 回报)
    Seeded --> Contiguous: WS 帧 k==cursor+1 → flush_contiguous
    Seeded --> Buffered: WS 帧 k>cursor+1 (空洞,缓冲)
    Buffered --> Syncing: needSync → 入 SyncScheduler 队(非直发)
    Contiguous --> Syncing: increment needSync / pong gap → 入队
    Syncing --> Applying: sync 响应 kind=events/snapshot
    Applying --> Contiguous: peek→落库→commit_target=max(nextSeq,末条)(HX-C008/B6)
    Syncing --> TooLong: kind=too_long
    TooLong --> Seeded: 清内存(cursor=resetTo-1) emit im:sync:too_long + Rust 拉首屏(不清表)
    Syncing --> Contiguous: kind=no_change
  }

  %% ===== 发送子机(per-message，含重连去重 M1)=====
  state SendMsg {
    [*] --> Optimistic: handle_send_message(IdSource tmp_id + Clock createAt 乐观落库)
    Optimistic --> Inflight: Effect::Http(posts/create)+ScheduleTimer(15s)
    Inflight --> Acked: WS echo action=="post"(server_id) reconcile+CancelTimer
    Inflight --> Failed: 15s Timer 超时 → sendStatus=unSend
    Inflight --> Acked: 重连后 increment 补回该 post → temporaryId 去重(M1，不双份)
    Failed --> Inflight: 重发
    Acked --> [*]
  }

  %% ===== 接管推进子机(Phase gate) =====
  state Takeover {
    [*] --> P0: 现状 sync-v2 ~90%
    P0 --> P1: gate绿
    P1 --> P1_5: gate绿(SendPosts编排100%测试)
    P1_5 --> P2: gate绿(出站横切层 401/断网端到端断言)
    P2 --> P3split: gate绿(outbound registry化+posts写)
    state P3split <<fork>>
    P3split --> P3a: posts读族(独立文件)
    P3split --> P3b: channel写+P0-2系统消息
    state P3join <<join>>
    P3a --> P3join
    P3b --> P3join
    P3join --> P4: 双绿+空交集自动merge
    P4 --> P5split: gate绿(19事件+SyncScheduler)
    state P5split <<fork>>
    P5split --> P5a: user-misc
    P5split --> P5b: bot-agent
    state P5join <<join>>
    P5a --> P5join
    P5b --> P5join
    P5join --> P6: Tauri四接缝
    P6 --> P7: 本轮只设计
    P7 --> [*]
  }
```

**转移铁律**：每个 Phase 节点转移 = 该 Phase 验收 gate 全绿（接口/事件 100% 测试通过 + 覆盖率达标）；gate 红则不转移。四个业务子机（Conn/SyncScheduler+SyncChannel/SendMsg）正交但有跨机交互已建模：M1 重连去重、M3 connectionId 回注、B4 全局 sync 限流。
