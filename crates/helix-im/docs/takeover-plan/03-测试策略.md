## 03 — 测试策略（硬约束：每接口/每事件有测试类，覆盖率 100%）

### 1. 度量方式

- 工具：**cargo-llvm-cov**（精度高于 tarpaulin，支持分支覆盖；`cargo llvm-cov -p helix-im --summary-only` / `--html`）。
- 命令（每 Phase gate 内）：`cargo llvm-cov --no-default-features -p helix-im --fail-under-lines 100 --fail-under-functions 100`，未达即 gate 红 → 不转移 Phase。
- **100% 判据范围**：对**本 Phase 新增文件**（如 P1 `outbound/send_build.rs`）跑 100% lines+functions；**不要求全仓 100%**（存量走 baseline 只增不减，见 `coverage-baseline.md`），避免被未触及存量拖累。
- 范围：每个 outbound 命令体 + 每个 WS handler + parser 每条 fallback 分支 + gate 每个状态转移 + SyncScheduler 限流路径。

### 3. 每 Phase gate 的测试判据（状态转移条件）

每个 Phase 节点的转移 = **本 Phase 全部接口/事件测试类 100% 通过 + 本 Phase 新增文件覆盖率 100%（lines+functions）+ `cargo check` 四 crate 绿 + 零运行时 grep 空**。任一红 → gate 红 → **不转移到下一状态**。

- gate 命令模板：`cargo test -p helix-im <phase_test> && cargo llvm-cov --no-default-features -p helix-im --fail-under-lines 100 --fail-under-functions 100 && cargo check -p helix-core -p helix-im -p helix-driver-native -p helix-driver-ffi && cargo tree -p helix-core | grep -iqE 'tokio|sqlx|reqwest|web-sys|tauri' && echo FAIL || echo OK`
- **wire 契约 casing 测试必须用从 mattermost 抓的真 Go fixture 比对**（C5），不得用 helix 自造 fixture 自产自证；凡注释带「待证/陷阱/PascalCase」的命令，gate 必含真 Go 帧比对，否则不得排进实现 Phase。
- **确定性测试**：golden_replay 类必须可回放（同输入同输出）；P1/P3b 落地后 `f5_golden_replay.rs` 须仍绿（验证 Clock/IdSource 注入未破回放）。
