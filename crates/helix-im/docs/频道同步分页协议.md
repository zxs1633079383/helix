# MessageV3 频道同步分页协议

## 事件

| 事件 | data | 触发条件 |
|---|---|---|
| `im:channel-sync-ready` | `channelSyncSessionId`, `generation`, `defaultPageSize: 20` | hello increment 全批原子持久化成功 |
| `im:read:result`（page body） | `channelSyncSessionId`, `generation`, `items`（最多 20）、`hasMore`、`nextCursor` | 当前 session 的本地 page Scan 成功 |
| `im:read:result`（complete body） | `completed: true`, `channelSyncSessionId`, `generation` | 当前 session complete；首次 complete 同步发一次 typed `im:channel-sync-complete` |

ready 不含 channels/items 数组。page 的 channel 行由本地 durable `channel` 表按
RuntimeAuth company 过滤，并经 render-ready shape 输出；page 失败、错误 cursor、旧
generation 或账号切换均不发 page。

## 命令

```json
{
  "channel_sync_session_id": "opaque",
  "next_cursor": null,
  "page_size": 20
}
```

`im_query_channel_sync_page` 只接受以上三种业务字段，`req_id` 仅允许 Host transport
注入用于 `im:read:result` 关联；`page_size` 缺省时仍固定为 20，其他值拒绝。Helix 本地
ScanSpec 没有 offset 原语，因此首页读取 21 行（20 行页面 + 1 行 lookahead），后续按
cursor 读取 `offset + 21` 的有界前缀后由 Helix 裁页；`next_cursor` 是绑定
session/generation 的 opaque token，不能由 caller 伪造 offset。

游标和 `hasMore` 依据原始扫描行的位置计算：先按 offset 取最多 20 行，再过滤
`delete_at/deleteAt > 0` 或 `is_remove/isRemove` 为真的频道。删除态在成员投影校验前
过滤，不扫描这些频道的成员；其遗留零版本或畸形成员字段不能导致整个页面失败。
其他成员权威校验仍保持严格。过滤后 `items` 可以为空或不足 20 条；只要原始扫描
还有 lookahead 行，就必须返回 `hasMore: true` 和下一 cursor。消费者不能以条数
判断结束，只在 `hasMore: false` 的页面应用完成后发送 complete。

```json
{"channel_sync_session_id":"opaque"}
```

`im_complete_channel_sync` 只接受 session ID（以及 transport 注入的 `req_id`）。完成后仅撤销
该 session 的在途 page correlation，不会影响其他业务请求；重复完成是幂等成功 body。

## 证据边界

当前 Rust focused tests 证明协议解析、cursor 隔离、Persist barrier、事件有界和 complete
幂等。`helix-driver-host/tests/increment_unread_anchor.rs` 通过真实内存 SQLite 和公开命令
验证连续两页删除记录后仍能读取有效尾页；这不代表 Go/WS、Native 或 UI DOM 验收。


## 话题全集与生命周期观察版本

Go 的根群增量、完整话题 end 和生命周期父群更新共享
`topicInventory: {version: string, channelIds: string[]}`。版本是锁内分配的数据库观察序号，
不能复用消息 timestamp。完整 end 的数量与逐条ID必须等于全集，否则不提交、不发ready。

`topic_inventory` 模块对每父群维持一个在途写和一个最新候选。读取durable version后，
将父群版本/ID集合/数量、子话题可见性、完整同步标记放入同一CAS事务。
失败最多重试2次；新版本排队时旧PersistOk不发旧数量或ready。重启仍以SQLite版本拦截旧观察。
根群批量同步用version_column单调upsert，避免每父群额外串行读写。

读取和typed event携带 `topicChannelIds/topicInventoryVersion`；版本保持十进制字符串，
宿主按版本合并整组字段。新版全集决定展示，旧无版本退出标记不能覆盖它。
旧SQLite通过追加migration升级，默认版本0，首次新清单即可恢复。
