# 0908 发送终态独立投递与验证

## 改动和边界

自发 WS 回声命中 pending send 后，发送对账持久化成功即独立发出 `im:post:sent`；频道缺号继续阻止 cursor 和普通 `im:post:received` 推进。终态携带已持久化发送意图、temporaryId 和权威 serverId，不宣称事件缺口已经补齐。复用已有终态 Persist continuation，不新增扫描、锁或定时器；每次确认按固定字段构造投影，成本与消息体大小相关。

客户端另行修复缓存中相同消息 ID 的状态变化被跳过，显式开启发送诊断后普通 trace 以 info 写入宿主，便于后续逐跳关联。

## 已执行证据

- 可控缺号用例先失败：取消 timer 后缺少独立发送终态。修复后通过。
- `cargo test -p helix-im --test send_test --lib`：405 个库测试、21 个发送测试通过。包含 256 个频道的逆序确认、重复回包/超时幂等、PersistErr 不误报 sent。
- PRE Native 实际 GoServer：MV3-G01A 和 MV3-G02C 两项通过，包含真实发送、受控首请求失败后重试；runId `messagev3-1788859627098-28699`，总耗时 77769 ms（含编译）。证据位于本机 `/tmp/send-terminal-native-pre`。
- 客户端定向回归：缓存状态更新 10、trace 4、reference stabilizer 29、IPC 投影 14 项通过；Angular dev build 通过。
- 旧测试 `send_echo_reconcile_cancels_timer` 实际只验证重复 timeout，现更名 `duplicate_timeout_does_not_repeat_failed_persist`；旧测试通过不能充当 WS 回声到 UI 的证据。

- 发布前 `cargo test -p helix-im`：1437 项通过，0 失败。

## 尚未闭合的边界

用户本轮真实 WebView 连续发送反馈“未复现”，不等于历史故障根因已证实。16:49 的服务端提交/socket_written 和后续本地 sent 记录不能证明当时 Angular 投影已更新。当前没有原始失败消息的完整逐跳 trace。

PersistErr 用例只证明不误报持久化成功，未证明存储故障后的 UI 终态恢复。客户端旧投影覆盖新状态的全部时序尚未完成 revision fence 证明。256 路确定性回放不代表生产容量压测。不得把本次发布称为所有故障场景 100% 根治。
