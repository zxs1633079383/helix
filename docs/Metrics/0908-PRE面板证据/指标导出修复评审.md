# 指标导出修复评审

2026-09-08，主责为 helix-driver-host 的 OTLP exporter。业务 MetricId、名称、kind、unit、MetricLabels 白名单不变。

## 实测问题与批准

1. 多个 SDK provider 没有独立 `service.instance.id`，Delta 流可能互相覆盖；进程级身份 proposal 被 reviewer 拒绝，因为 FFI 同进程可创建多个 provider。
2. 独立 reviewer 批准 provider 级随机非零 128 bit Resource 身份。只在懒建 provider 时产生一次，不随用户、频道或 batch 变化。
3. provider 身份隔离后的 PRE 实测仍有一个 writer 导出错误 2 次、storage_rows reset 3 次。SDK Delta collect/reset 先于 export，`retry_flush` 不重放原 payload。
4. 独立 reviewer 明确 `REVIEW: APPROVED`：在独立身份基础上使用 Cumulative snapshot，下次成功采集保留累计观察；保持 worker 非阻塞、有界队列和不重复记录 batch。

5. 再次独立 review 批准 `retains_failed_batch`：Cumulative 已记录后即推进 self cursor，避免下一失败批次重复累计自观测错误/丢弃；成功状态仍需 export 成功。重试只用已存在 pipeline，避免懒建失败后空 flush 冒充成功。

## 合同与边界

- owner：`crates/helix-driver-host/src/metrics/otlp.rs`；core/IM、HTTP/WS、数据库和业务成功条件不变。
- Resource 身份是实际 writer 身份，不是业务标签；序列随活跃 provider 及 exporter 过期窗口增长，需要约束运行实例和重启频率。
- producer 热路径仍为 `try_record`，O(1) bounded enqueue；随机数和 SDK 资源构造仅在 exporter worker 懒建时发生。
- 关闭/熔断策略不变；Cumulative 不保证未进入 SDK 的队列丢弃可恢复，也不承诺进程崩溃前所有数据可靠送达。
- 测试：OTLP unit 5 项、metrics_runtime 7 项、business_metrics 7 项通过；host-cli 构建通过。首次新增测试使用 Resource::get 的参数类型写错，修正为 &Key 后通过。
- 真验收：两个同服务 Native runtime、私有群消息、仅中断本轮 loopback OTLP 转发，恢复后双 MCP 检查累计值、reset、export error 与队列 drop；结果见本目录验收说明。
