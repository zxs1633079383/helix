## 导出失败与保护性丢弃

先前 Delta+唯一实例仍观察导出错误及 counter reset，因此改为累计快照。[约 20 秒 OTLP 转发中断](累计快照转发中断窗口.json)后，两个 writer 的 storage_rows 从 5379→5397、5074→5079，reset 均为 0；这段属于 cursor 修复之前，只用于解释累计值行为，不用其自观测计数做精确故障统计。

最终代码另做短中断：`05:58:41.204828Z` 停止本轮转发，`05:58:48.052241Z` 恢复。恢复采样仍保留每个 writer 的累计值，三个已观察实例的 reset 均为 0；恢复快照包含第三条 exporter 序列。本轮执行过 peer 重启，但该 JSON 未单独绑定每条序列到进程，不将三条序列直接解释为三个活跃客户端。

[最终恢复数据](最终运行恢复.json) 如实记录 export errors 与 queue/circuit drops；不得将故障窗口称为完整、无损观测。累计值仅能恢复已进入 SDK 的观察，不能恢复熔断/队列保护性丢弃。业务不中断及两端落库不等于指标零丢失，也不等于 Angular 渲染完成。
