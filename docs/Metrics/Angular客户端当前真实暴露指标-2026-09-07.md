## 1. 当前结论与证据

限定 PRE Prometheus `service_name="cses-client-pre"`，实际观察到 **71 个 Helix 指标族**：40 个 Histogram、16 个 Counter、15 个 Gauge；展开为 151 个序列名、1,521 条带标签序列。71 个族均有 metadata。Histogram 的 bucket/sum/count 合并计为一族。

另外有 4 个 Span 派生指标族。它们不能与业务消息数量相加，也不代表送达率。

- 查询端点：`http://192.168.6.66:30090`；Collector target `opentelemetry-collector` 为 up=1，抓取 `:8889`。
- ticks 原始样本核对时约 30 秒新鲜；持续抓取累计值不等于刚刚发生了对应业务。
- 本机 `127.0.0.1:9464/9090` 未监听；不能把本机 Collector 当作本次证据来源。
- 本轮没有启动客户端或发送消息，没有真实双用户业务闭环证据；证据等级为 PROM_QUERY。
- 客户端源码基线 `8d465d287fde43f8a1bfb7b3d5ffc735404d288c` 的 Cargo 依赖为 crates.io Helix `0.1.9`，不是旁边 Helix 工作树。
- 运行资源没有 service.version，不能证明线上进程对应此源码 revision。

## 4. Trace 派生族

| 名称 | 来源 |
|---|---|
| `otel_traces_span_metrics_calls_total` | Collector spanmetricsconnector |
| `otel_traces_span_metrics_duration_milliseconds` | Collector spanmetricsconnector |
| `calls_total` | Jaeger spanmetricsconnector |
| `duration_milliseconds` | Jaeger spanmetricsconnector |

这4个族的当前样本缺deployment_environment。新看板保留严格环境隔离，因此这些面板为空；不能通过移除环境过滤把未知环境数据混入PRE。后续应给spanmetrics维度补环境身份，重新验收。

## 5. Dashboard 与使用边界

正式路径：[Dashboard JSON](../../perf/grafana/client-channel-observability.json)；生成与导入说明见[本目录 README](README.md)。本页不将未来诊断面板作为当前已采集数据。

当前 Prometheus 无 user_id/channel_id。用户、群、登录或设备选择器非空时，技术面板有意返回无数据，禁止显示全局值冒充该 scope。按人/群的查询由结构化诊断数据提供。身份标签存在与否可用以下查询复核：

```promql
count by (service_name, deployment_environment) (otel_helix_ticks_total{service_name="cses-client-pre"})
```
