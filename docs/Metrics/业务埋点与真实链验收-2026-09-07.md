## 实际新增完成点

| 用户行为 | 当前记录 | 完成点和限制 |
|---|---|---|
| 登录后开始获取群与消息 | login_started / login_sync_started | 宿主认证上下文与新运行会话；命令行宿主不是 Java 登录验收 |
| 返回与保存群列表 | channel_inventory_page_returned / channel_inventory_persisted | Go 实际返回页、Helix matching Persist 返回；没有同快照应有群全集时 expected_known=false |
| 页面应用群列表 | channel_inventory_applied / login_sync_terminal | Angular 消费者返回 true 后记页，完整会话确认后记终态；空终页 count=0 也记；真实桌面待验 |
| 收到在线群事件 | delivery_stage / ws_received | 已解析、具有群与领域序号的 WS 入站；可能包含重复和非正文群事件，不等于唯一消息数 |
| 保存消息 | delivery_stage / persist_terminal | 实际匹配成功或失败的持久化回灌，不以收到 WS 或发出 Persist 为成功 |
| 离线或重连补齐 | sync_page_received / sync_persist_terminal / channel_checkpoint | 返回页与真实提交分开；数据库已保存水位独立记录 |
| 消息序号跳号 | gap_opened / gap_updated / gap_observed / gap_terminal | 保留期望、收到和服务器声明区间；同群有界 episode，原序号字符串化 |
| 各群最新保存进度 | channel_checkpoint | 当前窗口内最后一次已提交观察；不承诺窗口外群的完整当前态 |
| 观测链自身失败 | diagnostic records / queue / export errors | 接受、导出、丢弃、非法记录与网络失败；不作为消息业务计数 |

序号域明确区分 stream_seq、legacy_event_seq、channel_cursor；不使用根连接 seq 推业务游标。游标追上只记录 cursor_caught_up/requires_persistence_reconciliation，不据此断言所有正文无缺失。JSON 正文保存用户、群、会话和精确序号，时序与日志索引不新增这些标签。

业务记录借用固定标量；后台处理序列化和 HTTP。诊断队列默认 1024、批次 64，超长身份整条拒绝，网络有限重试保留原 event_id、时间和正文。gap 观测表最多 1024 群，查找 O(log G)，仅新 episode 分配；不增加业务数据库查询或改变补偿状态机。

## 实际运行证据

1. Go 专属群首次消息：HTTP 成功、真实数据库、接收端 WS 和同步响应中事件标识一致，stream_seq=4。
2. 新编译的两个 Helix 宿主连接同一实际 Go 服务。在线发送 seq=5：两端 SQLite 中消息标识相同，游标均为 5；Loki 中存在 ws_received 和实际 persist_terminal success。
3. 接收端退出后，发送端发送 seq=6。重启接收端并复用原 SQLite，补齐同一消息，两端消息标识/序号集合一致，游标均为 6。退出前接收端 3 行、最高 5；发送后发送端 4 行、最高 6。
4. Loki 查询到 Go 与 Helix 实际诊断；Go 完整 33 条 JSONL 已采集。详见 [机器证据](真实收发与离线补齐验证-2026-09-07.json)。日志重试或重采可能重复，不以行数当唯一交付数。
5. 新自观测通过 OTLP → Collector → Prometheus 出现 6 条序列。但测试环境 diagnostic-local 不在既有 Metrics 环境白名单中，被归为 unknown；不能宣称按 diagnostic-local 的 Metrics 环境查询通过。正式 pre 是既有合法值。首次实验队列 Gauge 单位 1 被翻译为 ratio 后缀，源代码已改为空单位计条数，最终名称为 otel_helix_diagnostic_queue_depth；该名称校正有本地测试，未冒称首轮旧二进制样本。
6. 测试服务正常停止，Go 精确清理本轮群、成员、帖子、事件和幂等行；没有清理共享数据。Go 独立证据见 [真实业务验收](/System/Volumes/Data/workspace/golang/cses-im-server/docs/reports/0907-Go诊断证据/真实业务验收.md)（跨仓部署时使用对应仓内路径）。

## 采集配置

客户端：现有 AsyncMetricSink 继续送 OTel；专用诊断 Layer 在单后台线程直推 Loki 2.9 HTTP API。通过 HELIX_DIAGNOSTICS_ENABLED、HELIX_DIAGNOSTICS_LOKI_URL、HELIX_DIAGNOSTICS_ENVIRONMENT、HELIX_DIAGNOSTICS_SERVICE、HELIX_DIAGNOSTICS_REVISION 显式配置，默认关闭。环境应与 Metrics 配置一致，使用 local/test/dev/pre/prod。

Go：既有 stdout 根 JSON；已给 monitoring/loki-pre-promtail 增加仅匹配 cses 命名空间、cses-im-server 容器、专用诊断内容的管道。仅提取 service_name、deployment_environment、platform 三个固定维度，保留原日志和 observed_at；不更改其他日志处理。实际 Promtail 语法检查通过，DaemonSet 6/6 更新并就绪。片段见 [采集规则](../../perf/grafana/go-diagnostic-promtail-stage.json)。Secret 完整原文只保存在本机临时备份，未写仓库。当前修改为运行集群配置，后续 Helm/GitOps 更新须把该片段同步入配置真源。

本机既有 JSONL 可用 [有界采集脚本](../../scripts/metrics/collect-diagnostic-jsonl.py) 送入 Loki；该脚本不生成数据、不绕过身份验证、不把上传成功当业务成功。

- 三端：core/IM/native/FFI/Web 与 CLI check、core tests、Web wasm build 通过；热路径审计未发现新增违规。
- Angular：IPC 参数 6 测试通过；上报与相关分页/空终页 6 聚焦测试通过；前端类型检查通过。本轮完整群列表测试遇到既有测试夹具缺少 ctx.userInfo 崩溃；未修改用户正在编辑的 MessageDialog 文件。单独 owner 测试还存在 ambient namespace 配置缺失，不扩大修复。
- 客户端仍依赖私仓 Helix =0.1.9，当前本地仓是 0.1.8 开发线。新增 API 用显式 business-diagnostics 候选 feature 接线；常规构建不引用未发布 API，候选模式通过 HELIX_ROOT 使用本地源码。发布后应更新锁定版本并启用候选 feature，不能把本地 path 编译当私仓已发布。
- PRE 新 Go/Helix/桌面二进制尚未部署；本轮环境 diagnostic-local 不是 PRE。真实 Angular 页面应用、同快照“应有群全集”、完整事件关联和严格端到端成功率仍待验或待补。
- Go 缺少可信 login_attempt_id/device_session_id/stream_epoch；始终 evidence_complete=false。看板严格率保留“待完善”，不把阶段记录相除作为完整消息送达率。

本轮已打通“真实业务 → 本机持久化 → 日志采集 → 查询与看板”的 Native 验证链；不能把它扩大为“所有生产用户与所有桌面场景已经闭环”。
