# 业务埋点实施评审

REVIEW: APPROVED（独立 implementation_approval 复核；运行证据待验）

## 目标与边界

补齐现有客户端真实业务事实到Grafana。Go由协作任务独立实施。Helix业务状态机仍唯一持有cursor/commit；不增加业务reducer，不改业务协议。新增诊断属于旁路：业务模块只记录白名单tracing标量，host专用Layer把固定容量字段复制到有界队列，后台序列化、批量Loki push。当前Loki2.9使用官方HTTP push API；无需升级生产集群。只在运行环境显式开启诊断时工作。长期保留登录/同步/提交检查点摘要，逐消息明细可设置时间和数量预算。

## 接缝

- ImModule：已有auth_user_id/company_id，宿主注入login_attempt_id/device_session_id；入站frame解析后记录ws_received；按现有channel cursor记录期望/实际seq，根WS seq单列不参与业务水位。
- 既有ChannelPersist/terminal/IncrementBootstrapCommit/SyncPull完成点：记录matching成功、失败和已提交checkpoint；不把HTTP200、未提交cursor或日志记录成功当业务成功。
- 既有sync响应记录请求from、权威next/horizon、返回数量、has_more和失败；pong解析旁路保留fromSeq/maxSeq，不改变补偿路由。
- Angular：复用canonical upsert后的client_applied；群列表消费者返回true之后报告applied页，final complete后报告客户端应用结束。身份从Rust认证运行时取，不信任renderer任意身份字段。权威应有群全集未知时expected_known=false。
- 每次运行/session开始与终止记录；失败/中断无正常终态时显示unknown，不能伪造success。

## 字段与成本

JSON白名单：schema_version/event/event_id/producer_service/source_revision/observed_at、tenant_id/user_id/channel_id/login_attempt_id/device_session_id、stage/path/result/reason、seq_domain/stream_epoch/event_seq/local_contiguous_seq/observed_high_seq/expected_seq/received_seq/declared_from_seq/declared_to_seq、corr、count/returned/persisted/applied_channels、evidence_complete/dropped_records。所有ID与seq字符串。缺失epoch/同快照权威不可输出严格送达率。

业务记录O(1)，批次O(batch)，不克隆正文/序列化wire/新增DB扫描；固定字段最大长度与数量，超限拒绝并计数，不截断成伪身份。队列1024、batch64，后台最多3次有界重试，失败计丢弃，不阻塞主业务；关闭有限排空；超时显式标TimedOut，不能把join超时当worker已退出。使用固定stream标签service_name=helix-im-diagnostics、deployment_environment、platform；身份仅body。

## 低基数指标合同

通过既有AsyncMetricSink记录，不建立重复业务计数owner。

|MetricId|canonical|kind/unit|owner与语义|标签|
|---|---|---|---|---|
|DiagnosticRecordsTotal|helix_diagnostic_records_total|Counter/1|后台记录accepted/exported/dropped/invalid，计诊断条数非消息量|stage={accepted,exported,dropped,invalid}|
|DiagnosticQueueDepth|helix_diagnostic_queue_depth|Gauge/1|后台采样有界队列长度|无|
|DiagnosticExportErrorsTotal|helix_diagnostic_export_errors_total|Counter/1|后台HTTP传输失败尝试|无|

既有message client terminal、sync/recovery metrics保留原owner。新业务趋势暂由已采集JSON按阶段计观测记录，标题明确“记录次数”，不假装唯一消息量/严格率。后续只有同cohort唯一终态完整时才启用成功率。

## 验证与停止条件

1. focused：固定字段/超限/精确大seq/queue满/导出失败与shutdown；真实ImModule Inbound→matching PersistOk/Err，失败cursor不推进。
2. export：本地HTTP接收端验证Loki body/标签及重试保持同一event_id、同一timestamp与body，at-least-once允许重复，不宣称Loki按event_id去重；仅证明导出格式。
3. 真实业务：已有Native真Go登录/send/reconnect入口运行候选源码，SQLite/Persist/EventSink同轮记录；Angular真实宿主独立验证，不以Native冒充UI。
4. Prometheus metadata/query检查新自观测指标，Loki按本轮真实身份/session查询非空新样本；Grafana回读scope与中文行为标题。
5. 失败需区分构建/认证/运行版本/export/采集；不得注入synthetic业务指标填看板。

回滚关闭诊断runtime恢复Noop；保留用户脏文件，未部署全局Collector，未改变业务成功失败语义。涉及文件：helix-im诊断helper与现有生命周期完成点、driver-host诊断Layer/worker和metrics注册、host-cli logger/runtime、客户端Helix runtime/telemetry适配、独立看板生成器与文档。不改core Effect协议、业务存储schema、Go他方租约、用户现有UI文件。

参考：[Loki HTTP push](https://grafana.com/docs/loki/latest/reference/loki-http-api/)、[tracing Layer](https://docs.rs/tracing-subscriber/latest/tracing_subscriber/layer/trait.Layer.html)。
