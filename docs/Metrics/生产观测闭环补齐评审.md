# 生产观测闭环补齐评审

REVIEW: APPROVED（独立 production_contract_recheck；仅批准实现合同）

## 关闭与完整性补充合同

统计是进程内诊断状态，不是业务持久化账本；“持久化成功”仅指外部 matching PersistOk。统计范围明确为单个运行会话内已接受的观察窗口。进程崩溃时未输出关闭摘要的窗口不可进入成功率；下一登录新login键，不能接管旧窗口并伪称恢复。看板必须同时显示启动与正常停止/未知结束状态，不声明跨崩溃完整率。

窗口固定30秒，每个窗口按用户/设备/登录/群分组；每个事件从首次有效ws_received起有30秒结果期限，窗口最后一个事件也过期限后才关闭，最大60秒。期限内Persist失败后成功可覆盖为成功；期限后的回执仅输出late_terminal诊断，不修改已关闭SLO结果、不重开义务、不新计分母。timeout表示期限内未确认，绝不解释为永久丢失。关闭时所有pending变unknown，完整性为false。

七个义务键字段必须非空，seq须为精确正整数、seq_domain为固定白名单；缺失/非法/超长整条拒绝进入统计，输出有界统计缺失摘要。business_event_id为辅助联查键，缺失不替代七元键；超长整条拒绝，禁止截断或哨兵值拼接。trace缺失只影响trace覆盖，不伪造parent。

事件表最多4096；活动项不淘汰。关闭项可按窗口清理，但保留每个身份/群/序号域已关闭最高序号，最多1024组。新入站若seq不大于该水位且业务cursor尚不能证明已提交，则记unknown，不重新创建可计数义务；业务cursor明确覆盖的重复排除。水位组满则新组unknown。容量、非法字段、队列丢弃均产生覆盖缺口，并使本运行会话后续摘要complete=false，恢复完整统计需新的运行会话。不得只对幸存成熟子集显示百分比。

每个关闭摘要含observed、matured、committed、failed、timeout、unknown和complete。所有unknown/丢弃摘要也输出关闭事件，持续模式每30秒有进度/关闭机会。看板成功率只有所选范围全部窗口complete=true且没有覆盖缺口时才显示；任一unknown/缺字段/丢弃必须隐藏百分比并显示原因。永久丢失结论仍须权威事件与SQLite对账，不能由本SLO推断。

本轮继续已有有界诊断旁路，不新增用户或群的 Prometheus 标签，不改变业务授权和状态机。

- Go：显式启用后 TTL=0 为持续采集；正 TTL 保留定向模式。队列上限不变，负 TTL 拒绝。长标识整条拒绝，禁止截断身份。既有三族自观测指标与 result 白名单保持有限。
- Helix：字段容量由白名单编译期长度确定；增加 business_event_id 与 traceparent，均为原始已有标量借用。Persist 回执明确序号域，避免入站 stream_seq 与终态 channel_cursor 错配。
- Host 后台新增本地接收后持久化统计：按 tenant/user/device/login/channel/seq_domain/event_seq 识别同一次交付义务，最多4096条。已在提交水位内的重复帧排除；未提交重复帧去重。matching Persist 成功/失败才成为终态；30秒无回执记 timeout，关闭时未完成记 unknown。终态缓存仅有限保留，容量不足明确报告 unknown，不伪成功。
- delivery_cohort_closed 的 evidence_scope 固定 client_persistence；不代表服务端受众送达率或页面渲染率。matured=committed+failed+timeout；unknown 不混入成功率。队列丢失后 complete=false；相同摘要保留原ID/时间重试，查询按 cohort_id 去重。
- 序列化、统计映射、计时、HTTP 仅在host后台，业务热路径只复制固定容量字段。统计更新O(log N)，N≤4096；没有新增业务DB查询。
- Trace复用既有HTTP/WS传播；业务诊断带真实carrier，后台附可查询trace_id，缺carrier时不伪造trace。客户端正式配置应装配同一出口与身份上下文，关闭/导出失败保留自观测。
- 看板为登录面板排除群条件，所有字段中文显示；用户业务明细与全局运行指标明确分区，身份缺失显示采集覆盖情况。无producer查询不得作为完成态面板。

验证：字段尾部大序号导出；持续/限时/关闭/队列满；重复/成功/失败/超时/关闭/容量/缺身份的统计测试；Trace parent跨HTTP/WS回归；客户端默认构建、配置覆盖测试；实际Go/Helix自动业务回放及Collector/Prometheus/Loki查询。真实用户页面操作最后单独验收。

不新增MetricId：复用DiagnosticRecordsTotal、DiagnosticQueueDepth、DiagnosticExportErrorsTotal及Go现有自观测。回滚关闭宿主诊断出口；核心Effect与持久化语义不变。

## 本轮实现复核与实际证据

- 本机保存窗口的去重键包含租户、用户、设备、本次登录、群聊、序号域和序号；查询以完整身份键加窗口编号分组，窗口编号本身不声明全局唯一。
- 超时后的回执仅输出迟到结果；拒绝、排队丢弃输出实例级覆盖缺口。无法恢复身份的缺口不补造用户，面板保守隐藏同环境的保存比例。
- 复核发现单频道结束帧会提前消耗全局批次编号，已修复为仅全局结束消费，并扩展原有过期批次回归。此处是实际状态修复，不能归类为纯显示变更。
- 当前 Loki 对新增独立全局保护分支返回错误。已把实例级缺口纳入已有缺口查询，仍保留身份筛选和缺样本保护；真实查询 22/22 通过。
- 真实 Go 与两个 Native 进程已核对实际批次、接收与持久化窗口；离线后重登读回新消息序号 6。证据见 [本机联调证据](生产接线本机联调证据-2026-09-07.json)。
- Grafana 第 6 版已发布并读回。三端 Rust check、Web wasm build、Host 导出 7 项测试与原过期批次回归通过。客户端正式依赖、默认构建接线与最终用户交互继续单独验收，未宣称 PRE 完成。
