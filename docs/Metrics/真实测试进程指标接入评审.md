## 合同

唯一接入位置为 Native 测试 `shared/mod.rs` 的三个真实 engine 装配点；辅助 HTTP 与 raw observer 保持原语义。
复用 `BoundedMetricRuntime` / `AsyncMetricSink`，不修改 core、IM、生产 registry 或 exporter。
同一 engine 的 Storage、HTTP、Transport、EventSink 与 EngineConfig 显式使用同一个 sink。

复用既有 `helix_ticks_total`、tick queue、effect、engine iteration、HTTP duration/status、
storage transaction/rows、WS connect/disconnect/frames、event emitted 与 exporter 自观测 family。
类型、单位及各事件标签继续以 `crates/helix-driver-host/src/metrics/registry.rs` 为准。
这些值表达各实际端口操作；HTTP 2xx、WS 写出和 engine tick 均不是业务成功终态。
新增接入不生成合成业务样本、不添加逐业务动态标签。

固定 resource：service `helix-messagev3-test`，environment `pre/local`，platform `native`，
scenario `canary`（复用已允许值，不代表发送 synthetic canary），shape `none`，profile `baseline`。
保留 runtime 既有 service instance 身份，避免多个 engine 的累计计数冲突。
不将 run、用户、群、post、correlation 或凭据加入指标标签。

队列 8192、batch 512、间隔 1 秒；业务侧仍是 bounded 非阻塞 try_record。
队列满沿用丢指标和 exporter 自观测，不等待网络。
`MESSAGEV3_METRICS_ENDPOINT` 未设、为空或线程初始化失败时明确记录 disabled 并降级，不改变业务结果。
导出异步失败保留既有 retry/backoff/circuit 和 snapshot，不当作业务失败。

runtime 由 engine task 持有，engine 结束后 spawn_blocking shutdown，调用者等待最多 3 秒。
记录关闭前 snapshot 和 shutdown outcome；TimedOut 不能证明 worker 已退出。
装配前失败使用 Drop 发停止信号；已创建 engine 的失败进入现有 cleanup。
失败发送路径同步改为统一 SendCleanup，早退也释放 engine/transport/SQLite。
