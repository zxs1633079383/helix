# 跨仓版本固定与验收

> 本文范围排除 G03/G03a，不得将上传链路混入本次 Frame V2 清退。

## 固定面

Helix revision、cses-client Cargo manifest/lock pin、Strict Matrix source revision/raw hash/semantic hash、Helix fixture manifest、client fixture manifest 和 E2E evidence pin 必须来自同一 immutable candidate。当前 client 四包已固定到 Helix V1 删除提交 `32e3a065...`，client 删除提交为 `a4770d6d6`；删除后 E2E 使用新的 candidate 与 evidence epoch。

## 唯一迁移顺序

1. 客户端 V2 reader 正向与负向测试通过。
2. Helix 25 Gate 全量 V2 writer 完成，逐 Gate replay/Persist barrier 通过。
3. Strict Matrix、fixture 与生成合同升级并重新生成。
4. revision、Cargo pin、合同 pin、fixture hash 一致。
5. **切断 Helix V1 producer 的生产可达路径**；命中 V1 writer 即 candidate fail。
6. **切断 cses-client V1 consumer/normalize 的生产可达路径**；收到 V1 即 fail-closed。
7. 构建一次 V2-only Native candidate。
8. 双用户连续执行全部 25 Gate，required fail=0、required skip=0。
9. 同一运行必须证明 `v2Frames>0`、`v1Frames=0`、`rawBusinessFallbacks=0`。
10. 每个 Gate 的截图、双端日志、远端 PG、本地 SQLite、Frame/Surface apply、DOM/UI 证据齐全。
11. 物理删除 V1 producer/type/codec/normalize/fixture/兼容测试与已确认的 Row V1 合同。
12. 删除后重新构建同一范围。
13. 删除后再次连续执行全部 25 Gate。
14. 二次运行仍为 25/25，且后续 Task、静态合同、索引、文档和证据状态全部闭合，任务才完成。

不得按 UC 单独重复编译 Native；一次 candidate 只进行一次完整构建和连续聚合执行。首次 E2E 之前不允许保留 V1 fallback，首次 E2E 之后也不得用旧绿色替代删除后的二次运行。
