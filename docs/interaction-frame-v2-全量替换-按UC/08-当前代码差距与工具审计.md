# 当前代码差距与工具审计

> 审计时间：2026-07-23 03:18 PDT。结论来自当前 Helix、cses-client 与 Go 工作树；未运行 Native E2E，不产生新的 Green。

## 结论

本目录的业务目标和 25 Gate 范围仍有效，但原版本快照、切换顺序和部分能力判断已经过期。当前代码**没有达到 V2-only 候选态**，也不能继承 017 的业务绿色作为 V2 清退证据。

## E2E 工具现状

已有能力：

- `npm run message:desktop:scenario:all`：一次 Native candidate 连续执行 Gate。
- `scripts/message-real-chain/reduce-evidence.mjs`：固定 27 Gate 基线，排除 G03/G03a 后正好 25 Gate；要求双用户 HTTP/WS、Go request/WS/远端 readback、Helix projection/本地 readback、DOM、driver result、代码引用与 no-mock。
- driver result 已要求 444/678 双用户截图及 diagnostics。
- `message:real-chain:doctor`、`message:projection-ownership`、`message:surface-runtime:source-pin` 可分别检查边界、raw reducer ownership 与 pin。

仍缺能力：

1. reducer/collector 没有正式采集 `v1Frames`、`v2Frames`、`rawBusinessFallbacks`，无法证明纯 V2。
2. `helixProjection` 证据尚未强制包含 `schemaVersion=2`、transactionId、causationId、surfaceEpoch 与 `FrameApplied`。
3. 聚合运行仍按 27 Gate 固定集合，缺少本 Feature 的显式 25 Gate profile；不能靠人工忽略 G03/G03a。
4. 没有独立 SCSS/CSS gate。需要至少包含 Sass 编译、目标组件样式载入、关键布局无溢出/遮挡和双尺寸截图断言。
5. 当前工具能要求远端/本地 readback，但还需为每个 Gate 固定表、主键、actor/observer 可见性和运行前后差异，避免“查到旧行”。
6. 删除后回归没有独立 candidate/evidence epoch，容易误用删除前产物。
