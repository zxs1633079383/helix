# G01 字段级设计基线与规格输入

> 目标：把 G01“发送文本”从一个按钮动作展开为可被 Spec、Plan、Tasks、Step、Review、Checklist 共同引用的全领域事实图。本文只声明源码能够证明的 CURRENT；跨 Surface 原子提交以 TARGET 标记，不能拿目标图冒充实现证据。

## 1. 结论先行

G01 不是“调用一次 HTTP”。它至少跨越十一个事实边界：

1. Angular Composer 采集用户意图。
2. Tauri `AcceptedCommand` 只证明命令入队。
3. Helix 分配 `temporaryId`、组装请求并建立 `PendingSend`。
4. 本地 SQLite 先持久化 `sending`，读回后才能投影。
5. 当前 Helix 生产 `message.timeline` 的 InteractionFrame V2。
6. Go `posts/create` 受理并在远端 PG 事务内写消息、频道计数、成员计数、事件与 outbox。
7. HTTP `SUCCESS` 驱动发送终态兜底；`serverId` 可能立即存在，也可能稍后由 WS/recovery 补齐。
8. WS `post` 用 `temporaryId` 和 `eventSeq` 完成身份与顺序对账。
9. 本地终态再次持久化、读回、投影为 `sent` 或 `failed`。
10. Angular SurfaceRuntime 按 slot 校验、stage/swap，再回送无内容的 `FrameApplied`。
11. DialogLeft、Unread、Composer 是发送可能影响的频道域视图，但 CURRENT G01 strict matrix 只声明 Timeline；它们必须由后续 impact policy 以“事实真的变化”为条件进入同一 V2 transaction。

用户口中的 `ChannelFrame` 在当前协议中不是第二种 Frame 类型。准确含义是：同一个 `InteractionFrameV2` 可以携带 `message.left-dialog-list`、`message.unread-summary`、`message.composer` 等频道派生 Surface mutation。

## 2. CURRENT 与 TARGET

| 维度 | CURRENT 源码事实 | TARGET 规格要求 |
|---|---|---|
| Frame 版本 | 仅 `schemaVersion=2` | 保持 V2-only |
| 上行动作 | `ShellService` 直接调用 `im_send_message` | 若采用 `ActionBinding(message.create)`，必须由 Composer Frame 投影 binding 并以版本化 action envelope 上行 |
| G01 producer | strict matrix 声明两阶段 `message.timeline` projection | 按实际变化影响 Timeline、DialogLeft、Unread、Composer |
| 乐观态 | SQLite `message.send_status=sending`，读回后 Timeline `delivery=sending` | 不变；禁止 Angular 自造 |
| 成功态 | HTTP `SUCCESS` 可先标 `sent`；WS/recovery 可补 `serverId/eventSeq` | 身份收敛和排序事实可追踪 |
| 失败态 | PortError 立即写 `unsend`；坏响应等待 timer；迟到 echo 可覆写为 sent | 明确失败原因、retryable 与迟到权威覆盖 |
| PendingSend | Helix 内存 `HashMap` 聚合，不是 SQLite 表 | Spec 必须决定是否接受重启丢失在途聚合 |
| DialogLeft | G01 当前未声明 mutation | preview、lastActivity、排序等事实变化时提交 |
| Unread | G01 当前未声明 mutation | 只按 actor 权威计数变化提交；不得从 row 聚合猜总数 |
| Composer | G01 当前未声明 mutation | capability、draftPolicy 或 action 状态变化时提交 |
| 客户端 | strict decode、原子 slot apply、DOM 渲染、FrameApplied | 不从 HTTP/Promise/raw `im:post:*` 重建业务状态 |

## 3. 字段真源矩阵

### 3.1 Angular 到 Tauri

| 对象 | 字段 | 必填 | Owner/来源 | 去向与约束 | 验证 |
|---|---|---:|---|---|---|
| `im_send_message` payload | `channel_id` | 是 | 当前 active channel | Helix command；不能为空 | invoke 参数日志、command test |
|  | `type` | 是 | G01 固定 `TEXT` | `CreatePostBody.type` | strict matrix |
|  | `text` | 是 | Composer 文本 | Helix 限长后成为 `message` | DOM marker + Go body |
|  | `props` | 否 | typed input | 先清理上传凭据再落本地/远端 | SQLite/PG JSON |
|  | `replied` | 否 | 回复上下文 | 仅含 `id/reply_id/reply_root_id/reply_first_level_id` | command contract |
|  | `req_id` | 否 | runtime correlation | 只进入 `Cses-Track-Id`，不得进业务 body | HTTP header/log |
| `AcceptedCommand` | `reqId` | 是 | Tauri/Helix adapter | 关联 receipt，不是业务终态 | invoke result |
|  | `command` | 是 | public command | 应为 `im_send_message` | invoke result |
|  | `helixCommand` | 是 | adapter mapping | 当前同为 `im_send_message` | invoke result |
|  | `accepted` | 是 | queue admission | `true` 只表示接管 | negative test |

### 3.3 本地 SQLite

当前唯一 durable 发送表是 `message`。`pending_send` 是 Helix 内存聚合，不得在 Spec 中写成 SQLite 表。

| 字段 | G01 首写 | 终态/echo 更新 | 投影用途 |
|---|---|---|---|
| `temporary_id` | Helix 分配，PK | 不变 | 本地身份与对账键 |
| `id` | body `id`，通常空 | server ID 到达后覆盖 | `MessageVm.id` 最终身份 |
| `channel_id/user_id` | trusted context | 不变 | Timeline scope/author |
| `type/message/simple_message` | HTTP body | 内容更新链另管 | content/preview |
| `props/viewers/user_snapshot/mentions` | 序列化 body | WS 可补齐 | typed VM 输入 |
| `replied_message/reply_messages/reply_count` | 默认或 body | reply 链更新 | reply summary/thread |
| `reply_id/reply_root_id/reply_first_level_id` | reply 三锚 | 不变 | `MessageVm` reply 字段 |
| `expedite_map/topic/quick_reply/read_bits` | 默认或 body | 对应 UC 更新 | urgency/topic/action/receipt |
| `event_seq` | 乐观态通常 `0` | WS/recovery 权威序号 | Timeline 顺序、DOM evidence |
| `send_status` | `sending` | `sent` 或 `unsend` | `DeliveryVm` |
| `revoke` | `0` | G04 更新 | recalled content/delivery |
| `create_at/update_at` | injected/server time | 权威事实可覆盖 | 展示时间与排序 |

### 3.5 WS、Frame、Surface 与 DOM

| 对象 | 字段 | 语义/验收 |
|---|---|---|
| WS `post` | `event,data.post,data.eventSeq,data.event_seq,event_seq,broadcast.channel_id` | 事件名必须是 `post`；序号三处一致；`temporaryId` 能关联发送 |
| `InteractionFrameV2` | `schemaVersion,transactionId,causationId?,runtime,mutations,directives` | `schemaVersion=2`；整帧非空、无重复 slot |
| `runtime` | `connection,initialSync,recovery` | 与 Surface 同一原子发布，不由 UI 猜 |
| `SurfaceMutationV2` | `surface,scope,revision,baseRevision?,causationId?,mutation,surfaceEpoch` | snapshot 无 base；patch 必须 `revision > baseRevision` |
| `TimelineWindowVm` | `channelId,anchor,items,firstUnreadMessageId?,targetMessageId?,page,state` | G01 CURRENT 唯一声明 Surface |
| `MessageVm` | `id,channelId,eventSeq,author,createdAt,content,delivery,actions,quickActions,replyId?,replyRootId?,replyFirstLevelId?,replySummary,replyThread?,reactions,readReceipt,templateConfirmation?,urgency?,pinned,bookmarked,topicLink?` | DOM 只能机械渲染这些事实 |
| `DeliveryVm` | `uploading/sending/sent/failed/recalled` | G01 核心为 `sending -> sent|failed`；迟到权威 echo 可 `failed -> sent` |
| `DialogRowVm` | `channelId,channelKind,rootMessageId?,title,avatar,companyTag?,preview,lastActivityAt,unreadCount,mentionCount,urgentCount,topicCount,memberCount,memberLeaves,hasScheduledMessage,isTop,notificationMode,lifecycle,settingsVersion,purpose?,header?,actions` | TARGET：发送导致 preview/activity/order 等事实变化时提交 |
| `UnreadSummaryVm` | `unreadTotal,mentionTotal,urgentTotal,unreadChannelCount` | TARGET：actor 权威摘要；不从 Dialog row 求和 |
| `ComposerVm` | `channelId,state,draftPolicy,actions,capabilityEpoch` | TARGET：只有 capability/draft/action 变化才提交 |
| `FrameApplied` | `transactionId,appliedSlots,result` | 完整 commit 和 directive attempt 后回送；不得携带 mutations/content |
| DOM | `data-message-id,data-channel-id,data-event-seq,data-delivery` | 发送行身份、频道、序号、状态 |
| Dialog DOM | channel row selector + preview/activity/unread attributes | 只有收到对应 Surface mutation 才能变化 |

## 4. 三条核心不变量

1. **受理不等于终态**：`AcceptedCommand.accepted=true`、HTTP `SUCCESS`、WS 到达、SQLite 写入、FrameApplied、DOM 可见是六个不同证据面。
2. **先持久化再投影**：`sending/sent/failed` 必须由本地 durable row 读回后进入 Frame；Angular 不根据 Promise 或 raw event 推导。
3. **只提交真实变化的 Surface**：G01 的领域影响集可以是四个 Surface，但单帧不能为凑矩阵重复未变化 Surface；CURRENT 仍是 Timeline-only，TARGET 需要代码和测试证明 impact policy。

## 5. 失败、竞态与恢复分支

| 分支 | 权威动作 | 本地终态 | 必须验证 |
|---|---|---|---|
| P1 SQLite 失败 | 不释放 HTTP | 无可渲染 sending | Go 无请求、无伪 Frame |
| HTTP `SUCCESS` + server ID | reconcile | `id=serverId,status=sent` | timer cancelled、pending 清理 |
| HTTP `SUCCESS` 无 server ID | sent fallback | `status=sent,id` 可暂空 | pending 保留直到 WS/recovery 补 ID |
| HTTP PortError | immediate failure | `status=unsend` | `delivery=failed`、timer cancelled |
| malformed/non-SUCCESS | 等 timeout | 最终 `unsend` | 不误判 sent |
| echo 先于 timer | reconcile | sent | timer 不再 fire |
| timer 先于迟到 echo | 先 failed 后 sent | sent | 同一 `temporaryId`、不重复行 |
| 重复 HTTP/WS | idempotent | 一行、一 server ID | PG idempotency + SQLite conflict key |
| Surface revision gap | fail closed/resync | 不部分提交 | 无半帧 DOM |
| directive 失败 | Surface 已提交 | `FrameApplied.result=directive-failed` | ack 与业务内容分离 |

## 6. 后续 Spec Kit 强制输入

### Spec 必须回答

- G01 的 actor、observer、前置 active channel 与权限是什么？
- G01 保留 public command，还是切到 Composer 投影的 `ActionBinding(message.create)`；两者不得在 CURRENT/TARGET 中混写？
- `sending/sent/failed` 各自的权威事实、持久化屏障和 causation key 是什么？
- 哪些事实变化才触发 Timeline、DialogLeft、Unread、Composer？
- HTTP `SUCCESS` 无 server ID 的暂态是否满足产品语义？
- `PendingSend` 仅内存、进程重启后的恢复责任属于谁？
- 双用户视角中，发送者与观察者分别应收到哪些 Surface？

### Plan 必须拆出

- Helix domain/state、application orchestration、SQLite adapter、Go/PG/WS authority、Tauri transport、Angular SurfaceRuntime、组件 DOM、证据 reducer 八个 owner。
- CURRENT Timeline-only 到 TARGET impact policy 的最小实现路径。
- fixture 必须由 Helix contract test 导出或真实链捕获，并带 commit/hash/provenance。
- focused contract -> 双端 integration -> Native 双实例 -> PG/SQLite/Frame/DOM 全链的验证顺序。

### Tasks/Step 必须具备

每项 Task 至少写清 `input -> code owner -> output -> evidence -> done signal`。Step 不得只写“实现发送消息”，而应拆为：

1. command/receipt；
2. temporary identity/PendingSend；
3. optimistic SQLite barrier；
4. sending Frame；
5. Go PG transaction；
6. HTTP terminal；
7. WS/recovery identity reconcile；
8. terminal Frame；
9. cross-surface impact；
10. Angular atomic apply/FrameApplied；
11. DOM/visual；
12. dual-store and dual-user evidence。

### Review 必查

- 是否把 `accepted` 或 HTTP result 直接变成 UI sent。
- 是否让 UI 生成 `temporaryId`、`eventSeq`、unread 或 Dialog preview。
- 是否在 PersistOk 前发业务 Frame。
- 是否把 `pending_send` 误写成 SQLite 表。
- 是否用 raw `im:post:*` 重建 Surface VM。
- 是否宣称四 Surface 已落地，但 strict matrix/producer 仍只有 Timeline。
- 是否遗漏迟到 echo、重复消息、revision gap、FrameApplied transport failure。
- 是否出现 timeline × surface 的无索引 `O(n*m)` 扫描。

### Checklist 验收证据

- [ ] command payload 与 `AcceptedCommand` 日志可关联。
- [ ] P1 前 Go 请求数为 0，P1 后才出现 `posts/create`。
- [ ] 本地 SQLite 同一 `temporary_id` 只有一行，状态按场景收敛。
- [ ] 远端 PG `post/channel/channel_member/channel_event/outbox/idempotency` 可用 post/channel/eventSeq 关联。
- [ ] WS `post` 的 `temporaryId/postId/eventSeq/channelId/trackId` 可关联。
- [ ] Frame `schemaVersion=2`、causation、revision、surfaceEpoch 和 mutation 完整。
- [ ] CURRENT 测试只期待 Timeline；TARGET 多 Surface 测试必须由真实 producer 输出。
- [ ] Angular `FrameApplied` 在原子提交后回送且不含业务内容。
- [ ] DOM 的 message ID、channel ID、eventSeq、delivery 与 Frame 一致。
- [ ] 发送者与观察者双实例截图、Native/Helix/Go 日志、SQLite/PG 查询属于同一 fresh scenario。
- [ ] SCSS/CSS visual test 无溢出、遮挡、状态跳动或 Dialog row 错序。
- [ ] V1/raw fallback 计数为 0，删除后的同一套 G01 再跑通过。
