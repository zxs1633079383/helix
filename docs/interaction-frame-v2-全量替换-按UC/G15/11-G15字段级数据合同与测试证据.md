## 1. Canonical inbound

| Gate | command | required | optional | unknown |
|---|---|---|---|---|
| `G-15` | `im_make_topic` | `root_id`、`user_ids`、`req_id` | 无 | 拒绝 |
| `G-15a` | `im_create_channel` | `type`、`user_ids`、`display_name`、`force_create` | 无 | 拒绝 |

canonical payload 使用 snake_case，且仅允许表中字段。camelCase 只可存在于公共 facade
intent；PC 与 Mobile 必须委托 Helix 共享 normalization，不能各写一套字段转换。

## 2. HTTP、WS 与远端权威

| Gate | HTTP request | HTTP response | WS/sync inbound |
|---|---|---|---|
| `G-15` | `POST /api/cses/posts/makeTopic` body `{rootId,userIds}`；`req_id` 只用于 Helix/客户端关联，不能进入 HTTP body；未提供自定义图片时服务端从归一化成员派生 `pictureType=USER/picture.userIds`，客户端不得提交空 picture 占位 | HTTP 200 application/json；`CommonRes.status=SUCCESS`；权威响应 `data={rootMessageId,channelId,revision}`；Helix 必须先持久化服务端 `channelId` 与 `revision`，仅 Persist Ok 后发布成功投影 | `channel_created`, `post_update` |
| `G-15a` | `POST /api/cses/channel/create` body `{type,userIds,displayName,forceCreate}`；session 身份、team、成员角色与默认 `pictureType=USER/picture.userIds` 由服务端派生，客户端不得提交 team/role/owner/picture | HTTP 200 application/json；`CommonRes.status=SUCCESS`；`data` 是服务端创建后的权威 Channel object，至少包含合法 `id`，并透传 `type`、`displayName`、`teamId`、`pictureType` 与 `picture` 等服务端终态；Helix 以 `data.id` 落 channel，并以 canonical 请求的 `userIds` 补成员投影 | `channel_created` |

HTTP 200/accepted 不是 Frame 终态。写路径必须等待 matching PersistOk 或权威 readback；
observer 必须依赖自身 WS/sync/恢复链，不能读取 actor 的 intent。

## 3. InteractionFrameV2

完整 envelope 必须包含：

`schemaVersion=2, transactionId, causationId?, runtime{connection,initialSync,recovery},
mutations[], directives[]`。

每个 mutation 必须包含：

`surface, scope, revision, baseRevision?, surfaceEpoch, causationId?, mutation`。

| Gate | canonical Surface | schema |
|---|---|---|
| `G-15` | `message.channel-summary` | `InteractionFrame/v2` |
| `G-15` | `message.thread-detail` | `InteractionFrame/v2` |
| `G-15a` | `message.channel-summary` | `InteractionFrame/v2` |
| `G-15a` | `message.member-roster` | `InteractionFrame/v2` |

本 GN 的 typed 接受值：

`ChannelSummaryVm`、`MemberRosterVm`、`ThreadDetailVm(detailContext=topic)`；topic/channel/member/root/revision 必须同源

业务不变量：

actor 为隐式 session owner；userIds 只传显式邀请者；topic root/reply 关系不得由 renderer 拼接

## 4. Frame inventory

1. `create-channel-or-topic-command`
2. `http-authority`
3. `channel-member-persist`
4. `channel-or-thread-frame`
5. `observer-frame`

上述是阶段 inventory，不代表每一阶段都必然独立出 Frame。Fixture producer 必须从真实
`Tick/PortReply/Inbound -> ImModule::handle -> Effect::Emit` 捕获 actual Frame，再固定
允许的部分顺序、可选 Frame 和终态。

## 5. 负向合同

- topic root 和 reply 关系不得由 UI 拼接
- 千人选人和批处理仅可在 Helix 执行
- schemaVersion 非 2、未知字段、重复 slot、scope/surface 不匹配、patch 缺 baseRevision
  均必须 fail closed。
- PC/Mobile 不得从 raw WS、HTTP、SQLite row 或 command receipt 重建 typed VM。
