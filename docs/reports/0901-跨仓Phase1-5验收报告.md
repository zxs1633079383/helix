## 运行态修复与合并内容

初轮失败根因是旧 Docker `mattermost-imv2` 数据卷缺少 `channel_member.effect_id`，
导致所有依赖 `channel/create` 的 Gate 在前置阶段失败。使用仓库提供的
`make docker-up-clean` 重建本地 IM/Pulsar/Redis 测试卷（保留 CSES 数据卷），确认当前
schema 后再执行最终轮。Go Docker 使用 `config-docker.yaml` 的
`host.docker.internal:19200`，并以持久 Kubernetes port-forward 提供 PRE ES。

候选测试工作树的 Phase1–5 domain tests、Phase5 Chain 目录、真实链 runner、契约测试和
共享断言已合入；真实登录解析同时兼容 `accounts/defaultIndex` 对象与顶层账号数组。
`G08D` 的 leave 场景由 observer 执行动作，保留 creator 完成本轮频道清理，避免 leave 后
使用已离开成员 close 导致清理失败。
