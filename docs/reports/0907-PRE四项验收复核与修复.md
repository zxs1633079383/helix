## 修复内容

修复分为 Native 验收设施和 Helix IM 的HTTP权威发送结算；不改变产品默认 EventSink 容量和原业务断言。

- 单 Gate 与 Phase 池使用相同的既有 16384 条有界观察预算；超过预算仍显式失败。2048 条恢复突发先挤掉终态的测试在旧 1024 容量下失败，修复后通过。
- 超时记录最近 16 条事件身份元数据；重试与置顶证据加入实际失败阶段、关联 ID。运行链失败返回 Err，不再仅写非 PASS evidence 后让 Cargo 返回成功。
- 置顶错误路径关闭 session，并汇总频道清理错误。池模式的物理资源回收仍由 Phase cleanup 负责。
- G10E 重开读回使用 mode=rw，保留 IGNORE 严格断言；失败也写 evidence、执行清理；关闭并保留数据库时移除池缓存租约。
- 观察诊断额外空间为固定 16 条元数据，观察通道容量固定 16384；逐事件时间 O(1)。只影响测试观察端。

## G02C 生产根因与修复

`getLatestPost`先读到同temporaryId及合法server ID时，旧`handle_message_query_remote_reply`立刻调用viewer helper。本端作者被该helper映射成`im:post:sent`，且Emit早于对应PersistOk。随后sync已推进cursor，晚WS的event_seq=8、expected_seq=9触发dup-drop，不能补出验收要求的`im:post:received`。现场同时确认SQLite同temporaryId已是sent并对应真实WS post ID，不能归因于HTTP未发送或消息未落库。

修复在helix-im的application编排层复用canonical投影工厂，登记`AuthoritativeSendTerminalPersist`，仅匹配PersistOk后发received；PersistErr抑制成功终态，重复PortReply被correlation消费机制丢弃。仍只通过原发送聚合写message id/send_status/temporary_id；不重放旧正文、channel/member或cursor写集，不把I/O移入core。HTTP扫描仍是既有有界一页O(n)，n上限60；新增correlation持有一份共享Bytes事件，释放随回报完成，不引入历史消息集合或全表扫描。

Raw observer关闭前显式drop不再消费的tick receiver，避免Disconnected被满队列反压。SharedWsClient.close在返回前已abort并await reader、完成lifecycle、落稳Disconnected，因此仅将已进入closing状态的`Sending after closing is not allowed`归为幂等关闭；其他错误和15秒超时继续失败。
