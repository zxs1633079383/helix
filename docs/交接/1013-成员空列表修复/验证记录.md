## 原因与影响

`handle_message_v3_post_persist_reply` 在事务成功后推进已提交 cursor，再读取当前 viewer 的 `channel_member`。`channel_update_from_member_readback` 原先直接解析 `Vec<String>`，精确空串失败，使 `handle_message_v3_post_readback_reply` 在 ACK、post 接收和 channel 事件前返回。

因此消息可已落库、历史查询可见，但实时消息接收、通知入口、频道摘要/未读展示及客户端送达 ACK 缺失。该错误终止本条回调，不等于整个 WS 连接或进程停止；受影响频道的后续消息可能重复失败。sync dialog 读回复用同一 helper，也可能中断频道更新。转发场景可进入读回失败终态。

已经推进 cursor 的消息不会仅因升级此修复而自动重新派发；本轮没有补发历史通知。用户报告的 13 次错误未逐消息对账，不能推定等于八条通知缺失。

## 修复合同

- 读回仅把精确空串解释为 `[]`。有效字符串数组保持原值，非法 JSON、`null`、非字符串元素及纯空格仍拒绝；viewer 校验与持久屏障保留。
- 新建 `channel` / `channel_member` 的两个列表默认 `[]`；成员更新、频道 full/patch、dialog reset 的空列表写入规范化。原历史 additive migration 不回改。
- 追加幂等迁移只修改 `WHERE 列 = ''`。旧 SQLite 表默认值不会被 `CREATE TABLE IF NOT EXISTS` 改变，因此追加 PK 定位的 INSERT/UPDATE 触发器，兼容旧默认值/空串写入；有效与损坏非空数据均保留。
- 启动迁移会扫描既有表；消息热路径没有新增全表扫描或成员遍历。正常非空写不触发修复 UPDATE，空串写只增加一次当前 PK 更新；没有新增 JSON 列或数组 read-modify-write。
- 按单群5000人、每群5RPS、多群并行、1秒可达的目标设计；本轮不证明容量或1秒达标。
