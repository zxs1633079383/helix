# 离线置顶缓存修复与频道属性审查

## 交付范围

基线：Helix `f690b9662569dc27c720b2937db9839c09f6327c`，分支 `reactor/MessageV3-helix`。
本批修复置顶缓存；其他属性按用户要求继续核验，确认的独立缺口单列，不扩大为所有频道合同重构。
未修改版本、未push、未发布。真实Go、Tauri、双设备UI和容量验收未执行。

## 已修复的边界

- 在线post_pin、置顶NOTICE、普通sync、terminal prefix、Snapshot、TooLong和increment频道快照共用失效写集。
- 新增业务表`channel_pinned_fence(projection_key,revision)`，账号与频道共同构成主键；DDL同时进入新库schema、升级迁移和Web稀疏表元数据。
- 失效事务原子执行缓存删除和revision递增；恢复路径与消息/cursor同事务。在线post_pin还将消息patch合入同一事务。
- HTTP成功后读取持久revision，再以UpsertGuard CAS保存列表、revision+1和top_count。先删除后旧写、先新写后旧写都由CAS拒绝；任何后段错误整笔回滚。
- 每个Query/HTTP/FenceRead/Persist/Readback都有内存epoch。旧请求返回`HELIX_PINNED_STALE`，本地读返回cache miss；提交失败不再返回旧成功body。
- 每个新权威列表请求推进epoch；重连不再将epoch归零。失效或重连后的dirty频道保持cache miss，直到匹配的权威提交/读回成功。
- 不新增core/driver存储原语，不改变MessageV3信封、请求payload或服务端协议；新增一次主键读和固定数量单行写，无成员遍历。

## 生命周期合同

| 阶段 | 成功 | 失败/迟到 |
|---|---|---|
| 本地Query | 两次主键读取并校验数量后返回缓存 | 跨代/dirty/存储失败为miss |
| HTTP | SUCCESS数组进入FenceRead | HTTP失败保持原错误链；跨代拒绝，不写缓存 |
| FenceRead | 读取持久revision后生成CAS原子写 | 存储失败终结req_id；跨代拒绝 |
| Persist | CAS通过后才启动频道摘要读回 | CAS/存储错误返回失败，不回灌旧body |
| Readback | 同代成功才返回列表与摘要 | 跨代/存储失败无成功终态 |
| 超时/重复/重连 | HTTP/存储沿现有PortError回灌；corr_map单次remove | 重复无第二结果；重连推进代次，旧请求拒绝 |

所有存储参数均owned；失效中的固定主键复制用于多个StorageOp，已就近解释lint豁免，不是消息体或成员集合的深拷贝。

## 其他channel属性：核验结果

| 范围 | 结果 |
|---|---|
| 群名等共享字段 | **确认独立缺口，未在本批修复**：公开increment先产生updateAt=100旧快照写集，公开update_channel的updateAt=200新群名先落真实SQLite，再执行旧写集，群名回退为old，updated_at回退100。普通快照没有版本/CAS。 |
| 话题列表/thread_count | 源码具有服务端version、每父群有界队列、持久UpsertGuard及集合/数量同事务。没有据此宣称全链通过。 |
| 未读/mention/urgent成员投影 | 源码已有projection_revision/last_read_seq及旧协议sequence guard，sync persona复用canonical member projection；与本次置顶缺口不同。 |
| 成员/owner/admin/boss | increment支持独立表及join/leave；全量成员与在线变化交错仍未完整实测。 |
| 公告 | 新增公开Tick证明同数量低版本列表被拒绝。客户端group-announcement-section同时监听post received/updated和announcementChanged，打开/切群也queryAnnouncements直读权威；因此撤回先前仅凭Helix无专用恢复入口就怀疑必然陈旧的推断。保持页面且TooLong没有相应post事件时仍需真实UI验证。 |
| 会话置顶/通知设置 | 独立viewer成员态及actor隔离；本批未做完整双用户离线验收，不能称全部无缺口。 |

## 后续边界与性能

普通共享字段需要单独确定权威版本/稀疏快照兼容合同，再将独立红测转绿；本批不擅自把updateAt当成所有字段的可比较版本。
单群5000人、每群5RPS、多群并行、1秒可达仍是目标，非本轮实测。失效按频道/同步批次进行，额外主键操作不随成员数增加；重连标脏按已知频道数线性扫描，不逐成员展开。
