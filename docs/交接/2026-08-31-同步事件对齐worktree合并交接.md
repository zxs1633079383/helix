## 2. 统一事件内核变更

### 2.1 type=1 在线与 Routine Sync 共用应用器

- 在线 WS `post` 与 Routine Sync type=1 共用 `message_v3_post_mutation_ops`，不再各自维护一套消息、
  channel 与 viewer member 写集。
- Routine Sync 删除共享 channel 级未读 bump，未读事实固定在 `(channel_id,user_id)`
  viewer 复合键。
- 只有 matching `PersistOk` 后才读回 viewer 绝对态并交付一个 `im:channel:update`；无提前 Emit、
  无 shell 侧 delta 补算。

### 2.2 小 gap、大 gap、PongGap 与 Hydration

- 小 gap 先缓冲高序号事件，补齐前序事件后仍逐个等待对应 `PersistOk` 再推进 cursor。
- 大 gap 通过 Sync 恢复同一 viewer 绝对未读，不因批量回放重复 bump。
- Pong fan-out 按 pending persist 与 dirty channel 集合做 O(1) 登记，整批排空后每频道只读回一次。
- HydrationHistory 只恢复消息事实，不二次增加未读。
- `PersistErr`、迟到伪 `PersistOk`、重复回报和越界 scope 均 fail-closed。

### 2.3 type=2/type=3/type=6 与原子批终态

- type=2 编辑收敛为原子 patch，不在 Persist 前发布成功事件。
- type=3 撤回与 type=6 `readBits` 可在同一批中以固定顺序结算，不回退 viewer unread。
- type1→type2→type3→type6 顺序由回归锁定，重复 correlation 不重复 Emit 或重复写入。
- 1/10/100/500 条批量均只产生一次 `PersistAtomic`，写操作上界保持 `O(N)`。

### 2.4 提交屏障与旧测试基线

- 统一事件内核不把 HTTP 2xx、WS 收帧、内存 mutation 或 AcceptedCommand 写成 durable
  terminal event。
- matching `PersistOk` 后从已提交本地事实读回事件，`PersistErr` 丢弃待发布终态。
- 旧 `ImConfig` 测试构造已显式补齐 `client_platform`，旧事件名、查询投影、WS echo
  与原子持久断言已对齐当前合同。
