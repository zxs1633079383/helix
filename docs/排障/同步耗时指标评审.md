# 同步耗时与分页观测合同

REVIEW: APPROVED

独立合同评审：sync_timing_review。实现复核补充见文末；线上证据仍未完成。

## 范围与真实分母

用户“各端”仅指 Helix 与 Go。增加观测，不修复本轮以外的 sync 并发窗口问题。整轮起点为生产 hello 建立 recovery epoch，终点为恢复完成已发布、scheduler idle、所有恢复提交和清单页/最终清单持久化屏障均排空；不以HTTP200或Go返回作Helix完成。断线/身份替换/明确失败关闭观测轮次，不发成功。旧轮与重复终态只记录一次。UI刷新和渲染不计入Helix恢复耗时。

分页明细指当前 /channels/load/increment/page 的频道清单分页，每页最多64；总页数为ceil(manifest长度/64)，空清单一次空页请求亦记1页。总页数在首响应后才已知。消息sync/notify是后续补齐阶段，计入整轮耗时，其Go处理耗时另按operation=message_sync计量；不把清单页总数冒充消息分页总数。

## Helix seam

ImModule增加可选只读SyncObserver端口，传递Copy标量，无OTel/runtime依赖；driver-host适配到既有AsyncMetricSink::try_record，Native/Tauri与host-cli生产构造都注入同一个已配置出口。诊断开关关闭时指标仍可独立生产；不存在第二个业务状态机。观测时间采用Module::handle传入now_ms；记录Unix毫秒开始/结束，差值饱和减，时钟倒退不产生负值。该口径是宿主注入时钟，不宣称跨机器时钟可直接相减。

单个round观测状态和单个清单page观测状态，O(1)；不保存各页历史到无界map。页面的开始/终态、整轮的开始/终态通过专用diagnostics记录，sync_session_id=connection_id，page_index为JSON字段；同一page请求使用X-CSES-Sync-Session-Id和X-CSES-Sync-Page-Index HTTP观测头传给Go，不改业务payload/授权/响应合同。ID<=128、页号正整数；Go对不合法头忽略，指标仍生产。

## 指标合同

Helix:
- RecoveryStartedTotal / helix_recovery_started_total / Counter / 1 / 无业务标签。
- RecoveryTerminalTotal / helix_recovery_terminal_total / Counter / 1 / result=success|failed|cancelled。
- RecoveryDurationSeconds / helix_recovery_duration_seconds / Histogram / s / 同result。
- RecoveryStartedTimestampSeconds / helix_recovery_started_timestamp_seconds / Gauge / s / 无业务标签，最近开始。
- RecoveryCompletedTimestampSeconds / helix_recovery_completed_timestamp_seconds / Gauge / s / 无业务标签，仅最近真正成功完成，开始不伪造完成。
- RecoveryInventoryPages / helix_recovery_inventory_pages / Histogram / 1 / result，仅终态有已知清单页数时观测，失败未获manifest则不写0。
- IncrementPageTerminalTotal / helix_increment_page_terminal_total / Counter / 1 / result。
- IncrementPageDurationSeconds / helix_increment_page_duration_seconds / Histogram / s / result。终点为本页匹配PersistOk或失败，空ops页在验证成功后完成。

Go:
- im_sync_page_requests_total / Counter / 1 / operation=channel_inventory|message_sync,result=success|failed|cancelled。
- im_sync_page_duration_seconds / Histogram / s / 同标签。Handler/app真错误决定result，HTTP200业务失败不能计成功。采用time.Now/time.Since单机单调时钟。
- Handler入口记录sync_server_page_started，defer记录sync_server_page_terminal；明确stage=server，含开始/结束时间、耗时、关联页号、实际返回数量。不声称服务端已确认客户端落库。

固定标签<=2，不含channel/user/run/页号/req_id。所有时间分布包含15/30/60/300/600秒桶；不修改既有非本轮指标的桶。必要时纠正既有ImRecoverySessionTotal把im:sync:recovered(state=failed)计success的分类。

## 实现复核后的完成门槛

- 现有 `im:sync:recovered` 可能先于下一页续拉发布；空清单也不一定发布该事件。因此观测不把该事件当最终依据。
- 使用既有 corr_map 分类：本轮 timestamp scan、清单 HTTP/Persist、消息 sync/续拉/too-long reload、成员投影及消息持久化，按新增 Effect 增加常数计数，匹配 PortReply 减少。另须启动频道投影 ready、清单最终屏障成功、scheduler idle、清单批次与恢复提交排空。
- `corr_floor` 取新 epoch Tick 开始时的单调分配水位；旧连接回执不能关闭新轮指标屏障。额外观测状态 O(1)，处理成本 O(本Tick新增Effect数)，无遍历全量频道或相关表。
- driver-host 没有运行时 helix-im 依赖；Native/Tauri与host-cli通过只读闭包传递Copy标量给 `record_sync_timing`，未反向引入业务crate依赖。
- 不推进业务cursor、不修改并发窗口；首次失败关闭观测，后续重试不把本轮改写成功。停止取消采用最后一个注入Tick时间，成功完成采用匹配终态Tick时间。
