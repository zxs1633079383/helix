## 当前恢复诊断入口（2026-09-12 静态对账）

[`sync_observation.rs`](../../crates/helix-im/src/sync_observation.rs) 在恢复活跃时按注入时间
限频记录 `sync_recovery_pending`（快照间隔至少 1000ms）。`pending_operations` 是待完成异步
操作计数；`scheduler_inflight`、`scheduler_pending` 与 `batch_persist_inflight` 分别展示调度和
批次持久化状态。`barrier_mask` 仅为诊断快照，不参与完成判定；bit 为 1 表示屏障未闭合：

| bit | 屏障 |
|---|---|
| 0 | 启动频道投影 |
| 1 | 频道清单提交 |
| 2 | 增量分页拉取 |
| 3 | 批次持久化进行中 |
| 4 | 批次待处理 |
| 5 | 同步调度未空闲 |
| 6 | recovery session 待提交 |

Host 的 [`diagnostics/fields.rs`](../../crates/helix-driver-host/src/diagnostics/fields.rs)
保留这些字段。日志 worker 满 `batch_max` 即导出，稀疏批次从首条记录建立固定截止时间；
后续记录不延长截止时间，关闭时排空已接收记录。实现见
[`worker.rs`](../../crates/helix-driver-host/src/diagnostics/worker.rs)，回归入口为
[`diagnostics_runtime.rs`](../../crates/helix-driver-host/tests/diagnostics_runtime.rs) 的
`full_backlog_batches_without_per_batch_interval_wait` 与 `sparse_event_flushes_by_coalescing_deadline`。
本次未重跑这些 Rust 测试或真实同步，不把源码存在计为采集成功。
