# 文字接龙三仓实施合同 v1

本仓只实现 Helix 端的 Command、Effect、PortReply、PersistAtomic 和 canonical projection。GoServer
完整合同见 `cses-im-server/docs/接龙/17-文字接龙-三仓实施合同-v1.md`；本文件保留 Helix 所需的
机器字段，防止客户端或 Rust Host 自行猜协议。

## 责任边界

- Angular 只提交最小 intent，不提交 `seq/eventSeq/totalMessages/participantCount`。
- Helix 负责生成并稳定保存 `operationId`，携带 `clientMutationId` 调用 Go。
- Go 的 HTTP/WS authority fact 先进入 `PortReply`，再进入 `PersistAtomic`；只有 `PersistOk` 后
  才 `Emit im:post_chain:*`。
- `eventSeq` 是 Channel cursor；`seq` 是 Chain cursor。不要新增第二套 Channel gap gate。
- 业务逻辑不进入 `helix-core`、Angular 或 Tauri Host；Host 只执行通用 HTTP/SQLite effect。

## Command 与最小 intent

```text
post_chain_create     {channelId, chainId, mode=TEXT, title, description, deadlineAt, clientMutationId, deviceId}
post_chain_publish    {channelId, chainId, expectedRevision, deadlineAt, clientMutationId, deviceId}
post_chain_append     {channelId, chainId, text, attachments, clientMutationId, deviceId}
post_chain_get        {channelId, chainId, middleCursor, limit, deviceId}
post_chain_reconcile  {channelId, chainId, clientMutationId, operationId, deviceId}
post_chain_close      {channelId, chainId, clientMutationId, deviceId}
post_chain_retract    {channelId, chainId, entryId, clientMutationId, deviceId}
post_chain_mark_read  {channelId, chainId, lastEventSeq, deviceId}
```

`operationId` 由 Helix 生成；未知网络结果不能生成新的 operationId 或盲目重发。TEXT append
不允许 categoryIds；服务端计数为 absolute snapshot。

## Effect / PortReply 顺序

```text
Tick::Command
  -> Effect::Http(POST /api/cses/post-chain/*)
  -> Tick::PortReply(HttpAccepted|BusinessRejected|Unknown)
  -> WS authority fact 或 HTTP fact admission
  -> Effect::PersistAtomic
  -> Tick::PortReply(PersistOk)
  -> Effect::Emit(im:post_chain:*)
```

HTTP 4xx/5xx 仍可能被 Host 包装为 `PortOutcome::Ok`，必须解析 CommonRes 的业务 `status/code`。
`BusinessRejected` 只更新请求设备 mutation；`Unknown` 进入 `RECONCILING` 并调用 reconcile。
任何 Persist 失败都不能 Emit confirmed projection。

## Durable projection

PersistAtomic 至少保存：

```text
chain_summary(chainId, channelId, mode, status, totalMessages, participantCount, lastSeq, revision)
chain_entry(entryId, chainId, postId, authorId, seq, text, createdAt, status)
chain_window(chainId, headIds, tailIds, hiddenCount, middleCursor, hasMore)
chain_mutation(clientMutationId, operationId, state, entryId, errorCode)
chain_viewer(chainId, deviceId, lastEventSeq, lastReadAt)
```

实际表名沿用现有 Helix schema/migration 约定；projection reducer 按 entryId upsert，绝不把 chain
entry 降级成普通 ChatMessage。旧 revision 丢弃，重复 eventId 幂等；`eventSeq` gap 走既有
replay/get gate。

## Emit 事件

```text
im:post_chain:draft
im:post_chain:publish
im:post_chain:upsert
im:post_chain:append_rejected
im:post_chain:reconcile
im:post_chain:close
im:post_chain:retract
im:post_chain:read_cursor
```

`upsert` 最小 payload 包含 `eventId/eventSeq/chainSummary/chainEntry/operationId/clientMutationId`；追加或撤回
同时携带服务端生成的可选 `textWindow(headEntryIds, tailEntryIds, hiddenCount, middleCursor, hasMore)`，
其中 `totalMessages/participantCount/lastSeq` 是绝对值。Angular 只消费这些事件。
