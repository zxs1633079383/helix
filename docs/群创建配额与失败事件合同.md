# 群创建配额与失败事件合同

## 计数与释放

2026-09-08 用户确认：同一创建者在每个公司最多保有 200 个未关闭、未解散的群，关闭后释放名额。
Go 按最终落库的 `create_by + team_id` 隔离，计数 `O/P`：公司大群与当前多人建群表单实际发送的普通群 `P`。
私聊 `D` 和话题 `T` 排除。历史 `delete_at IS NULL` 与 `delete_at = 0` 均为未关闭；非零关闭时间排除。
该限制约束创建者的活跃群，不限制其加入他人群的数量，也不删除已有超额群。

Go `CreateChannel` 与空 ID 的 legacy `Save` 在调用者事务内，先对创建者/公司取得事务级 advisory lock，
再查询最多 200 个匹配 ID 并执行原有插入。事务提交前不释放锁；拒绝或数据库错误回滚。
关闭提交后的后续 READ COMMITTED 查询自然释放名额。与关闭并发的请求可能保守拒绝，但不会超配。
现有 `/channel/change/info` 及 team upsert 的修改分支使用 `ChangeChannelInfo`，不接受类型与公司变更字段。

## 创建生命周期

入口保持 `im_create_channel`，HTTP 保持 `/channel/create` 和现有 HTTP 200 / `status: failed` 业务失败信封。
配额由 Go 判断；Helix 和 Angular 不复制计数逻辑。

| 阶段 | 行为 |
| --- | --- |
| Tick::Command | 使用现有请求关联，发起 HTTP |
| Go 配额拒绝 | HTTP 200，`status: failed`，message 为用户可读配额文案 |
| Helix PortReply | 释放原 correlation，Emit `im:channel:create-failed`；无成功 Persist 或 created |
| 重复/迟到 PortReply | 已消费 correlation 不再 Emit |
| 创建成功 | 保持 HTTP/WS authority → PersistAtomic → matching PersistOk → created |
| 传输失败/畸形响应 | Emit 未确认或异常提示，不伪造成功 |
| PersistErr | 继续禁止成功 Emit；客户端等待上限后显示未确认，不能视为 Go 未创建 |
| Angular | 先订阅关联终态，再发 command；accepted 不结束用例；匹配失败仅调用既有轻提示组件 |
| 完成/失败/超时/取消 | 释放事件订阅与定时器；取消前尚未提交的 microtask 不再发请求 |

失败事件为 `{event:"im:channel:create-failed",data:{requestId,reason,message}}`。
`reason` 为 `business_rejected`、`transport_failed` 或 `invalid_response`；业务拒绝保留 Go 文案。
这是外部请求结果事实，不创建本地群投影。Native/FFI/Web 继续原样转交业务 bytes。
该事件属于现有 G08a 创建生命周期，不增加 Gate 分母。

## 验证边界

隔离 PostgreSQL 已验证 199/200、8 个事务争抢最后一位、用户/公司隔离、D/T 排除、历史 NULL、关闭释放恰好一个名额。
Helix G08a focused 已验证成功持久屏障、配额失败、端口失败、畸形回复与重复回灌。
Angular 定向测试验证失败关联、一次轻提示、无错误弹框、成功等待、超时和取消。
这些证据不能代替部署后真实 Go → Native → Angular 宿主联调；目前没有发布或部署本修复。

## 同步拥塞审查

Go 每个物理连接的 realtime 与 bulk 队列各 2048。增量事件归入 bulk。
Helix 已传 HTTP `connectionId`，但当前 Go 增量发布只带 UserIds，向该用户全部连接广播。
`PublishSlice` 等待 Hub 入队，不等待 socket 写出或对端消费；分块后紧循环也不构成流控。
当前增量只有最终 end，没有可续拉的 page/cursor/ACK 合同，不能直接挪用 sync/notify 的续拉机制。

后续行为修复须共同定义：验证归属后的发起连接定向、有界批次及继续发送条件、最后一批 end；
Helix 同连接重复 hello 的在途去重须保留已有启动二阶段补偿，不可直接删掉第二次增量。
本次静态审查确认上述缺口，未将它们误报为已修复，也未增加物理队列容量。
