## 一、评审结论

**能过会——靠"诚实 + 原点守住"过，不是靠"无懈可击"过。** 原点经得起敲，技术核心方向正确，未建完的部分被主动摆上桌、且有明确的最低成本验证路径。带这份纪要上桌，比带一份滴水不漏的 PPT 更有底气。

## 二、原点复核（守住）

| | 核心问题 | 复核结论 |
|---|---|---|
| P1 | 业务逻辑写多份 | **真**——2550 行从 cses-client 真数过，Flutter 移动端更高 |
| P2 | Bug 修多处、行为分叉 | **真**——亲手联调修过，Flutter 再对一次就是回调地狱 |
| P3 | 业务逻辑测不动 | **真**——依赖真实平台，时序 Bug 难复现 |

现状校准：**两端在跑（桌面 Tauri + Flutter 移动），浏览器在路上**（非"三端已在跑"）。

价值定锚：**押"IM 一个模块、一份逻辑两端（未来三端）一致 + 可回放可单测"本身即已回本**；presence 等第二、三模块是上不封顶的彩头，不是地基。即使平台叙事不兑现，投资也不白做。

## 三、本次拍板（带去过会的决策）

| # | 决策 | 内容 |
|---|---|---|
| 1 | **cursor 归属（ADR-004 关闭）** | cursor 是 IM 模块的同步游标概念，**归 `helix-im`，不进 core**；core 只保留与业务无关的通用 spec 原语 |
| 2 | **栅栏升级：禁词清单 → 公开面冻结** | "core 零业务概念"从 `grep 禁词`（denylist）升级为 `cargo public-api` **快照冻结 core 公开类型面**（allowlist）；任何新增具名业务类型即 CI 红——拦的是"新增了类型"这个结构事实，而非某个词 |
| 3 | **四能力解耦定性：行为级（A）** | Tick/Effect 提供的是**行为解耦**（模块只 emit 自己需要的 Effect），**非编译级裁剪**；方案中"feature additive / 单独构建 / 编译级互不依赖"措辞全部校准为"行为级解耦"。唯一保留的 B 口子：wasm 包体积——若 wasm size 真咬人，再为 wasm 单独拆 `Effect` 子枚举 |
| 4 | **DomainEvent 契约版本化** | 业务逻辑全进 Rust 后，core 与前端唯一对话面是 DomainEvent 事件流；该契约**必须版本化**，否则"业务回调地狱"会换成"事件 schema 对不齐地狱" |
| 5 | **三端说法诚实校准** | 措辞从"三端在跑"改为"两端在跑 + 浏览器在路上" |

## 四、头号技术风险（主动上桌）

**乱序增量同步（断线重连 backfill）尚未验证。** 架构在最干净的发消息链上已证明，但在最脏的"乱序帧缓冲 + gap 检测 + 按序补齐"链上一字未证。

**最低成本验证路径（列为 M1 第一优先级）**：
> **先写乱序 backfill 的 proptest，再写任何 driver。** 在 `helix-im` 内用 owned 状态（`pending: BTreeMap<Seq,Frame>` 缓冲、`cursor` 连续水位、bitmap 已拉区间）+ `ScheduleTimer` 驱动"攒 1s flush"，喂任意乱序的 `Tick::Inbound` + `Tick::Timer`，断言落库顺序 == 排序后顺序。
>
> 过了 → 架构在 hard path 上证完，过会底气十足；逼着 `ImModule` 膨胀成丑八怪 → 以最低成本在 M1 撞到天花板，远胜 M4 才撞。范式参考：Telegram `getDifference(pts)`。

## 五、回到原点：框架还是补丁

> 「我现在做的，是为原点构建的框架，还是在忙着打各种补丁？」

- **是框架**：原点真实（真数据 + 亲手的疤）；sans-IO / Tick-Effect 真把碎片化的业务回调收拢成一份可回放的扁平状态机——**这是地基**。
- **回调地狱的真身已诊断对**：不是回调本身，是业务状态机被剁碎散落在嵌套回调里；Helix 把它收拢进 core 一份扁平 `match`，前端塌缩成无嵌套的"事件流 → 渲染"。
- **施工修正而非补丁**：措辞超前兑现处已校准（四能力行为解耦、三端说法）；栅栏盲区已升级为结构保证。
- **诚实是最大加分**：未建完的硬骨头（乱序同步）被主动指认、未装懂——建框架的人会说"这墙我还没砌"，打补丁的人会刷层漆糊过去。
