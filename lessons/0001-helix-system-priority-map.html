Lesson 0001

先学会判断“这件事归谁管”

Helix 的第一课不是 Rust 语法，而是边界判断。只要能判断一件事属于 core、IM、host driver、native、FFI、还是外部 Tauri 宿主，后面的代码就不会散成一团。

本课目标：用 7 层优先级给当前系统排学习顺序，并能回答一个问题：我现在遇到的需求，应该先看哪个文件/哪条不变量？

一张脑内地图

core

helix-core 是纯状态机和 ports。它不做 I/O、不认识 IM、不碰 tokio/sqlx/tauri。

im

helix-im 是业务模块。它把命令、WS、sync、projection、query 转成 core 能吐出的 Effect。

host driver

helix-driver-host 兑现 Storage/HTTP/WS，提供 shared pump，让 native 与 FFI 共用一套执行语义。

端壳

driver-native 面向 PC/Tauri，driver-ffi 面向手机/C++ shim。端壳只装配，不复制业务。

学习优先级

P0

先背北极星和当前 P0

读 docs/GOAL.md 的一段话定义和硬约束，再读 docs/ROADMAP.md §二 P0。现在最该盯的是 Tauri 四接缝、golden fixtures 工具链、双端 check、feature 拆分、多模块并发写实测。

P1

学 core 的输入输出协议

只抓四个词：Tick 是输入，Module 处理状态，Effect 是输出，ports 是外部能力的抽象。core 的价值是确定性和可回放。

P2

学 host pump 如何兑现 Effect

run_engine_loop 把 core/im 吐出的 Effect 分发给 storage/http/timer/event sink。这里要重点懂五个泵不变量：回灌必达、主循环不等 I/O、同 key 写顺序、回灌优先、graceful drain。

P3

学 helix-im 的业务分层

按目录记职责，不按文件名硬背。outbound 组 HTTP，ws 吃 live 帧，sync 管 cursor/补拉，send 管 pending/echo，对 UI 的投影看 projection-schema.md。

P4

学 native 与 FFI 的不同出口

native 事件可以 broadcast；FFI 事件必须 batch，一次过 C++ vtable。FFI 还要把 raw pointer、panic、destroy join、buffer 生命周期当红线。

P5

学边界情况，不学“漂亮抽象”

每个边界坑都对应 HX-C 卡：零运行时、Send、features、热路径、FFI、批处理、确定性、测试可证伪、hop 观测。它们是防止系统偏航的护栏。

P6

最后补 Rust 语法

语法按 Helix 需求补：trait bound 读 ports，enum/match 读 Effect，Result 读外部输入，owned 数据读 async 边界，unsafe extern C 读 FFI，cfg/features 读双端编译。

第一轮练习

需求：给 Tauri 投影事件加录放对账，应该优先看哪层？

需求：修一个 HTTP 出站命令体字段，应该优先看哪层？

需求：手机端事件回调不能逐条过边界，应该优先看哪层？
