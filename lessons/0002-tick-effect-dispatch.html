Lesson 0002

Helix 的主循环：喂 Tick，吐 Effect

上一题你答对了：新增 IM 业务命令先看 helix-im。这一课把原因讲透：业务模块不直接 I/O，它只把“意图”吐成 Effect，再由 host driver 兑现。

本课目标：读任务时能判断它落在 Tick、Module、Effect、还是 dispatch。这是 Helix 最核心的一条链。

四段链路

1. Tick

外部世界进入内核的输入。UI 命令是 Tick::Command，WS 帧是 Tick::Inbound，HTTP/DB 回包是 Tick::PortReply。

2. Module

业务模块处理 Tick。这里必须同步、纯粹、不 await、不 I/O。IM 模块在这里决定“要发请求”“要落库”“要 emit”。

3. Effect

模块吐出的副作用意图。Effect::Http 不是已经发了 HTTP，只是声明“请宿主发这个 HTTP”。

4. Dispatch

helix-driver-host 的分流兑现层。这里把 Effect 真正交给 Storage、HTTP、Transport、EventSink、Timer。

为什么业务命令先看 helix-im

像 im_mark_channel_read 这种命令，它的问题不是“Rust 怎么发 HTTP”，而是业务上要发哪个后端接口、带什么 body、成功后更新什么本地状态、向 UI 投影什么事件。这些都属于 helix-im。

但 helix-im 不应该直接调用 HTTP client。它应该吐出 Effect::Http { corr, req }。driver-host 收到后发 HTTP，完成后回灌 Tick::PortReply { corr, outcome }。IM 再根据回包吐 Effect::Emit 或后续 Persist。

关键代码锚点

  • crates/helix-core/src/tick.rs：Tick 输入集合。
  • crates/helix-core/src/module_host.rs：Module::handle 的纯函数约束。
  • crates/helix-core/src/effect.rs：Effect 意图集合。
  • crates/helix-driver-host/src/engine.rs：run_engine_loop 主泵。
  • crates/helix-driver-host/src/dispatch.rs：dispatch_effects 真正兑现。

一个微型剧本

UI/FFI/Tauri
  -> Tick::Command("im_mark_channel_read")
  -> helix-im accepts + handle
  -> Effect::Http { corr, req }
  -> driver-host dispatch 发 HTTP
  -> Tick::PortReply { corr, outcome }
  -> helix-im handle 回包
  -> Effect::Emit(DomainEvent)
  -> driver-host EventSink
  -> native broadcast / ffi batch / loopforge app.emit("im:__bus__")

三个容易搞错的点

错 1

把 Effect 当成 I/O 已经发生

Effect 只是意图。真正发 HTTP、写 DB、发 WS，在 driver-host 的 dispatch 里。

错 2

依赖同一批 Effect 的顺序

effect.rs 明确说同一个 step 产出的 Vec<Effect> 之间无兑现顺序保证。需要因果就用 Correlation 串起来，等 PortReply。

错 3

为了一个业务命令去改 core

新增 IM 命令通常不改 core。只有新增一种通用能力或抽象形状，比如新的 port/effect/tick 类型，才考虑 core。

练习

需求：IM 处理完命令后要让宿主发 HTTP。模块应该直接调用 HTTP client，还是吐什么？

需求：HTTP 并发池、背压、回包变成 PortReply，主要看哪里？

需求：必须等 HTTP 成功后再 emit 投影事件，靠什么表达因果？

主资源

本课主资源是 Tick -> Effect -> Dispatch 速查，对应源码是 crates/helix-core/src/tick.rs、crates/helix-core/src/effect.rs 和 crates/helix-driver-host/src/dispatch.rs。Rust 语法上，先补 enum、trait、Result。

下一课建议：专门拆 Correlation，因为它是“异步 I/O 回到确定性 core”的关键纽扣。
