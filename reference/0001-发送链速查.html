回到第 1 课：从 Tick::Command 到 sent →

一句话：HTTP 2xx 只是 admission；WS post echo 带回服务器 id 后，Helix 才把本地行收敛为 send_status = "sent"，并在 MessageV3 原子提交与 read-back 后发布 im:post:received。

最短源码地图

  1. tick.rs：Tick::Command、PortReply、AppCommand。
  2. module/trait_impl.rs：命令名分支到 handle_send_message。
  3. send/flow.rs：P1 optimistic persist、pending、HTTP、timer。
  4. port_reply/dispatch_core.rs：P1 Ok 后进入 sending；HTTP reply 不直接宣布 sent。
  5. post_echo_settle.rs：按 temporaryId 对账、写 sent、取消 timer、清理 pending/corr。
  6. message_v3_post.rs：PersistAtomic、read-back、received emit。

三个诊断问题

  • 看到了 HTTP 2xx，为什么不能写成 sent？因为它没有服务器 post 的权威 id 和 WS delivery 事实。
  • 为什么同时保留 id 和 temporaryId？前者是服务器主键，后者是本地乐观行与 echo 的对账锚点。
  • 为什么 received 不能在 PersistAtomic 前 emit？否则 UI 看见成功，但本地 durable 事实可能还没提交。
