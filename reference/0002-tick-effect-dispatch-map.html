Reference 0002

Tick -> Effect -> Dispatch 速查

一句话：core/im 只决定“该发生什么”，driver-host 决定“怎么兑现”。

1

Tick 是输入

crates/helix-core/src/tick.rs 定义所有能喂进内核的东西：Inbound、Command、PortReply、Timer、Connected、Disconnected。

2

Module 是纯处理器

crates/helix-core/src/module_host.rs 规定 handle 必须同步、无 I/O、无 await、无 spawn。模块只把副作用写进 EffectSink。

3

Effect 是意图

crates/helix-core/src/effect.rs 定义 Send、Persist、Http、Emit、ScheduleTimer 等。它们不是已执行的 I/O，只是“请宿主做这件事”。

4

Dispatch 兑现意图

crates/helix-driver-host/src/dispatch.rs 把 Effect 分流到 Storage、HTTP、Transport、EventSink、Timer。这里才是真 I/O 兑现层。

5

PortReply 回灌

Persist 和 Http 带 Correlation，driver 完成后回一个 Tick::PortReply，再定向投递回原模块。不要依赖同一批 Effect 的顺序。

判断口诀

看到“业务决定”先找 helix-im；看到“怎么发 HTTP / 写库 / 发 WS / emit 给 UI”先找 helix-driver-host 或端 driver；看到“抽象形状变了”才碰 helix-core。
