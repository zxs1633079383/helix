Reference 0003

Correlation + PortReply 速查

Correlation 是异步 I/O 的回执小票：谁发起，谁收回包。

1

什么时候需要 Correlation

Effect::Persist、Effect::Http、Effect::Request 需要未来回包，所以带 corr。Emit、Send、PersistFire、HttpFire 不靠它。

2

core 的 corr_map

ExecutionShell 扫描本次 step 新吐出的 Effect，把 Correlation -> module_index 注册进 core 的 corr_map。以后 Tick::PortReply 回来，就能投回原模块。

3

driver 的 reply_tx

helix-driver-host worker 执行完 Storage/HTTP 后，用独立 unbounded reply_tx 发 Tick::PortReply { corr, outcome }。这条通道必须不阻塞。

4

IM 自己也有 corr_map

helix-im 还维护业务上下文：同一个 corr 对应 SyncPull、OutboundSendHttp、MessageQuery 等。core 只知道“回哪个模块”，IM 才知道“这张小票代表什么业务”。

5

未知 corr 怎么办

core 收到未知 PortReply 会忽略；IM 收到未知业务 corr 也 no-op。这是边界零信任：迟到响应、已取消请求、断线后回包都不能把状态机打崩。

口诀

Correlation 管“这是谁的回包”，CorrelationContext 管“这个回包要继续哪段业务”。
