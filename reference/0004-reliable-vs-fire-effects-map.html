Reference 0004

必达 vs 可丢 Effect 速查

判断一个 Effect 能不能 fire，不看“是不是异步”，只看“丢了会不会破坏状态机”。

1

需要回包推进业务

用 Effect::Persist 或 Effect::Http。它们带 Correlation，driver 必须回灌 Tick::PortReply。

2

只做幂等补写

才考虑 Effect::PersistFire。典型是已经确认主写成功后，推进单调 cursor / status patch 这类可重复、可重算的写。

3

HTTP 默认必达

posts/create、sync/notify、increment 这类请求必须用 Effect::Http。它们的响应体、inflight 清闸或 cursor 推进都是 load-bearing。

4

HttpFire 是显式放松

Effect::HttpFire 不带 corr，不回 PortReply，队满可丢当前请求。只有“不需要响应、丢失可自愈、无 inflight 闸”的请求能用。当前 helix-im 基本没有真实生产者。

5

driver 背压规则

Persist / Http 使用 Overflow::Block：慢下来，不丢。HttpFire 使用 Overflow::DropNewest：满了丢本条，靠后续同步自愈。

一句口诀

要回执就必达；可重算才可丢。
