EffectSink 与顺序陷阱速查

EffectSink 是本次 step 的输出缓冲，不是因果队列。

1

模块只写声明

Module::handle(&Tick, now_ms, &mut EffectSink) 里只能 out.push(Effect::...)，不能直接 I/O、await、spawn。

2

ExecutionShell 复用 scratch

step() 开头 scratch.clear()，复用同一个 Vec 容量；返回的 &[Effect] 只在下一次 step() 前有效。

3

Vec 顺序不是兑现顺序

同一批 Vec<Effect> 只是“本步吐出的声明集合”。driver 可以并发/异步兑现，不能靠下标表达“先写库再发 HTTP”。

4

因果靠 PortReply

正确链路是：吐 Persist { corr } → driver 回 Tick::PortReply → 模块处理 Ok → 再吐下一步 Http / Emit。

5

start() 有区间注册

start() 会累积多个模块的 on_start effects，所以 core 只扫描每个模块新增的 [start..] 区间，避免把前一个模块的 corr 注册到后一个模块名下。

一句口诀

EffectSink 管“这一步吐了什么”；PortReply 管“下一步何时开始”。
