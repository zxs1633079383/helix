# IM Gate 本地证据目录 v1

## 目的

截图中的 30 个 Gate 需要统一回答三件事：

1. 哪一种 `Tick` 进入 `helix-im`；
2. `helix-im` 交给 host 哪些 `Effect`；
3. 哪些 `Effect::Emit {event,data}` 是 PC/Mobile 对端真正消费的业务出站。

本轮为此建立本地目录
`specs/047-im-event-gate-inventory/.v1/`。该目录可能承载运行态请求、响应和关联标识，
因此由仓库 `.gitignore` 的 `**/.v1/` 规则整体忽略，不进入 commit。

## 目录合同

```text
.v1/
├── README.md
├── manifest.json
└── gates/
    └── G-xx/
        ├── contract.json
        ├── inbound-contract.json
        ├── effects-contract.json
        ├── outbound-contract.json
        ├── capture-status.json
        └── captures/
            ├── inbound.ndjson
            ├── effects.ndjson
            └── emit.ndjson
```

- `contract.json`：从当前 Strict Matrix 生成的声明合同，不是运行证据。
- `inbound-contract.json`：进入模块的 `Tick::Command`、`Tick::Inbound`、
  `Tick::PortReply` 和适用时的 `Tick::Timer`。
- `effects-contract.json`：模块交给 host 执行的 HTTP、Persist、Timer 等完整 Effect 意图。
- `outbound-contract.json`：业务对端消费的 `Effect::Emit`，信封固定为 `{event,data}`。
- `capture-status.json`：索引 Helix tests、WDIO 源码和历史 evidence，并记录三个原始
  捕获槽位是否存在。
- `captures/inbound.ndjson`：原始 Tick 记录。
- `captures/effects.ndjson`：同一 step 的完整 Effect 批次。
- `captures/emit.ndjson`：从 Effect 批次筛出的原始 `{event,data}` 业务出站。

生成器不会创建空的 `captures/*.ndjson`。文件不存在或为空时必须保持
`NOT_CAPTURED`；历史测试 PASS、fixture、源码文件或旧 `gate-report.json` 只能作为
source index，不能自动晋级为本轮真实捕获。

## 方向基准

所有方向统一以 **Helix module boundary** 为观察点：

| 类型 | 归属 | 例子 |
|---|---|---|
| inbound | 进入模块 | `Tick::Command(im_send_message)`、`Tick::Inbound(post)`、`Tick::PortReply(PersistOk)` |
| effects | 模块交给 host | `Effect::Http`、`Effect::PersistAtomic`、`Effect::ScheduleTimer` |
| outbound | 对端业务出站 | `Effect::Emit(DomainEventBytes({"event":"im:post:received","data":...}))` |

这里不是 “Emit 或 Channel” 二选一。Helix 领域输出是 `Effect::Emit`；Native 的
`EventSink` 使用 broadcast channel 承载，Tauri adapter 再令 `channel=event`。
FFI 没有逐事件 channel API，而是把同一步的 `DomainEventBytes` 交给
`on_domain_events_batch`。所以 `channel` 是适配器路由标签，不是另一层业务输出。

当前代码真源：

- `crates/helix-core/src/module_host.rs`：`Module::handle(Tick, &mut dyn EffectSink)`。
- `crates/helix-core/src/effect/operation.rs`：`Effect::Emit { event: DomainEventBytes }`。
- `crates/helix-driver-native/src/event_sink.rs`：Native broadcast `EventSink`。
- `crates/helix-driver-native/src/bus_guard.rs`：Tauri 消息把 `event` 映射成 `channel`。
- `crates/helix-driver-ffi/src/event_sink.rs`：FFI step 内缓冲 Emit。
- `crates/helix-driver-ffi/src/vtable.rs`：`on_domain_events_batch` 批量回调。

Actor 发出的 UI command 是 inbound；Helix 发往 Go 的 HTTP request 只是待执行 Effect；
Go HTTP response 回到模块后又是 `Tick::PortReply`；只有 `Effect::Emit` 才登记为本目录的
业务 outbound。

## 生成

```bash
node specs/047-im-event-gate-inventory/scripts/generate-v1-evidence.mjs
```

生成器覆盖各类 contract、`capture-status.json`、`manifest.json` 和本地 README，
但保留已经采集的 `captures/*.ndjson`。重复运行必须得到相同合同和源码索引；只有新增或
修改非空 capture 文件时，捕获状态才会变化。

## 当前判定

本轮只完成 30 Gate 的合同与源码证据索引。生成前没有发现统一的同一 run
`inbound/effects/emit` 原始捕获，因此不得把历史 Gate Green 报告改写为本目录的
`CAPTURE_PRESENT`。实际缺口以 `.v1/manifest.json` 为准。

当前生成结果：

| 证据面 | 结果 | 可以证明什么 |
|---|---:|---|
| Gate 目录 | 30/30 | 截图分母均有独立证据位置 |
| inbound/effects/emit 声明 | 30/30 | 合同已按模块边界拆分 |
| Helix producer/fixture 源码索引 | 30/30 | 当前仓存在对应测试源 |
| WDIO mock/single-real/dual-real 源码族 | 30/30 | PC 三类场景均有源码入口 |
| 历史 evidence 索引 | 26/30 | G-10b、G-10c、G-10d、G-11a 未找到独立历史 evidence |
| 同一 run 原始 capture | 0/90 | 尚不能证明任一 Gate 的三槽原始捕获闭合 |

这里的 `26/30` 不代表 26 个 Gate 当前 Green；它只表示找到了可继续审核的旧证据文件。
G-10 至 G-11a 的窗口、anchor、定位与分页元数据仍有 `PARTIAL/INFERRED_REQUIRED`
标记：当前存在某些 raw emit 不等于它们已经具备替代旧 UI 层合同的全部字段。
