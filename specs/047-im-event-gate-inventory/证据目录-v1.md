# IM Gate 本地证据目录 v1

## 目的

截图中的 30 个 Gate 需要统一回答三件事：

1. 什么进入 Helix；
2. Helix 向端口输出什么；
3. 哪一个响应或权威事实使业务状态完成。

本轮为此建立本地目录
`specs/047-im-event-gate-inventory/.v1/`。该目录可能承载运行态请求、响应和关联标识，
因此由仓库 `.gitignore` 的 `**/.v1/` 规则整体忽略，不进入 commit。

## 目录合同

```text
.v1/
├── README.md
├── manifest.json
└── gates/
    └── G-xx/
        ├── contract.json
        ├── inbound-contract.json
        ├── outbound-contract.json
        ├── response-contract.json
        ├── capture-status.json
        └── captures/
            ├── inbound.ndjson
            ├── outbound.ndjson
            └── response.ndjson
```

- `contract.json`：从当前 Strict Matrix 生成的声明合同，不是运行证据。
- `inbound-contract.json`：进入 Helix 的 command、WS authority 与 PortReply 声明。
- `outbound-contract.json`：离开 Helix 的 HTTP、Persist、Timer 与 Frame 声明。
- `response-contract.json`：HTTP、WS、Persist 和 terminal Frame 的闭合响应声明。
- `capture-status.json`：索引 Helix tests、WDIO 源码和历史 evidence，并记录三个原始
  捕获槽位是否存在。
- `captures/inbound.ndjson`：UI command、WS authority 或 PortReply 的原始入站记录。
- `captures/outbound.ndjson`：HTTP、Persist、Timer、Frame 等 Effect 的原始出站记录。
- `captures/response.ndjson`：闭合请求或业务终态的 HTTP、WS、Persist、Frame/DOM
  对账记录。

生成器不会创建空的 `captures/*.ndjson`。文件不存在或为空时必须保持
`NOT_CAPTURED`；历史测试 PASS、fixture、源码文件或旧 `gate-report.json` 只能作为
source index，不能自动晋级为本轮真实捕获。

## 方向基准

所有方向统一以 **Helix boundary** 为观察点：

| 类型 | 归属 | 例子 |
|---|---|---|
| ingress | 进入 Helix | `im_send_message`、WS `post`、HTTP PortReply、PersistOk |
| egress | 离开 Helix | `HttpRequest`、`Persist`、`ScheduleTimer`、`InteractionFrame` |
| response | 终态闭合 | 合法 `post.id`、WS authority、本地提交成功、FrameApplied/DOM |

Actor 发出的 UI command 是 ingress，但 Helix 发往 Go 的 HTTP request 是 egress；
Go HTTP response 回到 Helix 后再次属于 ingress。不能仅按“客户端发/服务端收”笼统命名，
否则 sender/receiver 和 Port 方向会混在一起。

## 生成

```bash
node specs/047-im-event-gate-inventory/scripts/generate-v1-evidence.mjs
```

生成器覆盖 `contract.json`、`capture-status.json`、`manifest.json` 和本地 README，
但保留已经采集的 `captures/*.ndjson`。重复运行必须得到相同合同和源码索引；只有新增或
修改非空 capture 文件时，捕获状态才会变化。

## 当前判定

本轮只完成 30 Gate 的合同与源码证据索引。生成前没有发现统一的同一 run
`inbound/outbound/response` 原始捕获，因此不得把历史 Gate Green 报告改写为本目录的
`CAPTURE_PRESENT`。实际缺口以 `.v1/manifest.json` 为准。

当前生成结果：

| 证据面 | 结果 | 可以证明什么 |
|---|---:|---|
| Gate 目录 | 30/30 | 截图分母均有独立证据位置 |
| ingress/egress/response 声明 | 30/30 | Matrix 合同已按 Helix boundary 拆分 |
| Helix producer/fixture 源码索引 | 30/30 | 当前仓存在对应测试源 |
| WDIO mock/single-real/dual-real 源码族 | 30/30 | PC 三类场景均有源码入口 |
| 历史 evidence 索引 | 26/30 | G-10b、G-10c、G-10d、G-11a 未找到独立历史 evidence |
| 同一 run 原始 capture | 0/90 | 尚不能证明任一 Gate 的三槽原始捕获闭合 |

这里的 `26/30` 不代表 26 个 Gate 当前 Green；它只表示找到了可继续审核的旧证据文件。
