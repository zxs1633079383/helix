# IM Gate 本地证据目录 v1

## 目的

截图中的 30 个 Gate 需要统一回答三件事：

1. 哪一种 `Tick` 进入 `helix-im`；
2. `helix-im` 交给 host 哪些 `Effect`；
3. 哪些 `Effect::Emit {event,data}` 是 PC/Mobile 对端真正消费的业务出站。

本轮为此建立本地目录
`specs/047-im-event-gate-inventory/.v1/`。该目录保存 Rust producer 生成的合同与 hash
索引，由仓库 `.gitignore` 的 `**/.v1/` 规则整体忽略，不进入 commit；目录不存在时不代表
代码或测试失败，只表示本轮尚未生成本地证据产物。

## 目录合同

```text
.v1/
├── manifest.json
└── gates/
    └── G-xx/
        └── generated/
            ├── inbound.json
            ├── outbound.sender.json
            ├── outbound.receiver.json
            └── provenance.json
```

- `manifest.json`：生成器写入的 Gate ID、每 Gate 文件数、逐文件 SHA-256、全树 hash 和
  `consumer_sync`，不重建业务 payload。
- `inbound.json`：Rust producer 实际喂给 `ImModule::handle` 的 Tick 及远端依据。
- `outbound.sender.json` / `outbound.receiver.json`：各自视角的 MessageV3
  `{event,data}` 与本地存储依据；允许 persona-local Gate 的 `events: []`。
- `provenance.json`：producer test、`ImModule::handle`、Helix HEAD、storage schema hash、
  三份文件 hash 与 consumer 同步边界。

当前生成器不会创建 `README.md`、`contract.json`、`capture-status.json` 或
`captures/*.ndjson`。运行态原始捕获若另行采集，必须在对应 evidence pack 中单独登记，不能
把历史源码、fixture 或旧报告自动晋级为当前 capture。

## 方向基准

所有方向统一以 **Helix module boundary** 为观察点：

| 类型 | 归属 | 例子 |
|---|---|---|
| inbound | 进入模块 | `Tick::Command(im_send_message)`、`Tick::Inbound(post)`、`Tick::PortReply(PersistOk)` |
| effects | 模块交给 host | `Effect::Http`、`Effect::PersistAtomic`、`Effect::ScheduleTimer` |
| outbound | 对端业务出站 | `Effect::Emit(DomainEventBytes({"event":"im:post:received","data":...}))` |

这里不是 “Emit 或 Channel” 二选一。Helix 领域输出是 `Effect::Emit`；Native 的
`EventSink` 使用 broadcast channel 承载，Tauri adapter 再令 `channel=event`。
FFI 没有逐事件 channel API，而是把同一步的 `DomainEventBytes` 交给
`on_domain_events_batch`。所以 `channel` 是适配器路由标签，不是另一层业务输出。

当前代码真源：

- `crates/helix-core/src/module_host.rs`：`Module::handle(Tick, &mut dyn EffectSink)`。
- `crates/helix-core/src/effect/operation.rs`：`Effect::Emit { event: DomainEventBytes }`。
- `crates/helix-driver-native/src/event_sink.rs`：Native broadcast `EventSink`。
- `crates/helix-driver-native/src/bus_guard.rs`：Tauri 消息把 `event` 映射成 `channel`。
- `crates/helix-driver-ffi/src/event_sink.rs`：FFI step 内缓冲 Emit。
- `crates/helix-driver-ffi/src/vtable.rs`：`on_domain_events_batch` 批量回调。

Actor 发出的 UI command 是 inbound；Helix 发往 Go 的 HTTP request 只是待执行 Effect；
Go HTTP response 回到模块后又是 `Tick::PortReply`；只有 `Effect::Emit` 才登记为本目录的
业务 outbound。

## 生成

```bash
node specs/047-im-event-gate-inventory/scripts/generate-v1-evidence.mjs
```

生成器串行执行 manifest 中的 30 个 Rust target，逐 Gate 写入上述四份 JSON，并在最后运行
schema contract。重复运行必须得到相同文件集合和 hash；业务字段只能由 Rust producer 写入，
JavaScript 不拼接 event/data。

## 当前判定

本工作树当前未携带被忽略的 `.v1/` 目录，因此本页不声明某次生成的 Gate 数、文件数或
capture 状态。运行生成器后，Gate 数、四文件集合、tree hash 和 schema 结果以
`.v1/manifest.json` 与 `message_v3_artifact_schema` 的实际输出为准；历史报告不能替代该
证据。
